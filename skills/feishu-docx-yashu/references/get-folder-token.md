# 获取文件夹 token

## 概述

获取飞书云空间中文件夹的 token（folder_token）。文件夹是飞书云空间中用于管理文件和其它文件夹的容器，每个文件夹都有唯一的 token 作为标识。在不同接口中，其参数命名可能不同，包括 `token`、`folder_token`、`folderToken` 等，但本质上都是同一个概念。

支持以下两种获取方式：

| 获取方式                 | 适用场景                         | 说明                                                                        |
| ------------------------ | -------------------------------- | --------------------------------------------------------------------------- |
| 方式一：从文件夹链接提取 | 用户提供了文件夹的 URL           | AI Agent 直接用正则从 URL 路径中提取 token，无需调用任何 API 或脚本         |
| 方式二：AI Agent 查找    | 用户仅提供文件夹名称，未提供链接 | 由 AI Agent 通过调用「获取文件清单」工具（`get-files`）逐层查找匹配的文件夹 |

### 文件夹链接格式

| 链接类型     | URL 格式                                                 | 说明                        |
| ------------ | -------------------------------------------------------- | --------------------------- |
| 云空间文件夹 | `https://{domain}.feishu.cn/drive/folder/{folder_token}` | token 直接从 URL 路径中提取 |

示例：

- `https://kr0lqjlbmo.feishu.cn/drive/folder/XmlTfpUwQlH7ZTdih8gcN753nyc?from=space_personal_folder` 的 token 为 `XmlTfpUwQlH7ZTdih8gcN753nyc`
- `https://kr0lqjlbmo.feishu.cn/drive/folder/Ip7vfeMnUlzLyIdj7KJcWxt1nde` 的 token 为 `Ip7vfeMnUlzLyIdj7KJcWxt1nde`

### 判定逻辑

| 用户输入           | 判定条件                  | 执行方式                                       |
| ------------------ | ------------------------- | ---------------------------------------------- |
| 提供了文件夹链接   | URL 包含 `/drive/folder/` | 方式一：AI Agent 直接用正则提取 token          |
| 仅提供文件夹名称   | 无链接，只有名称          | 方式二：AI Agent 通过 `get-files` 工具逐层查找 |
| 同时提供链接和名称 | 有链接                    | 优先使用方式一（更快速准确）                   |

## 方式一：从链接提取 token

AI Agent 在思考过程中直接使用以下正则匹配 URL 即可：

```
/\/drive\/folder\/([a-zA-Z0-9]+)/
```

### 提取示例

| 输入 URL                                                                                           | 提取出的 token                |
| -------------------------------------------------------------------------------------------------- | ----------------------------- |
| `https://kr0lqjlbmo.feishu.cn/drive/folder/XmlTfpUwQlH7ZTdih8gcN753nyc`                            | `XmlTfpUwQlH7ZTdih8gcN753nyc` |
| `https://kr0lqjlbmo.feishu.cn/drive/folder/XmlTfpUwQlH7ZTdih8gcN753nyc?from=space_personal_folder` | `XmlTfpUwQlH7ZTdih8gcN753nyc` |
| `https://kr0lqjlbmo.feishu.cn/drive/folder/Ip7vfeMnUlzLyIdj7KJcWxt1nde#heading=h1`                 | `Ip7vfeMnUlzLyIdj7KJcWxt1nde` |

### 注意事项

- 仅支持 `/drive/folder/{token}` 格式的链接，会自动忽略 URL 中的查询参数（`?` 后内容）和锚点（`#` 后内容）
- token 仅由字母和数字组成，正则中 `[a-zA-Z0-9]+` 已涵盖全部合法字符
- 若 URL 不匹配该格式，应判定为非法链接，提示用户提供正确的飞书云空间文件夹链接

## 方式二：AI Agent 查找流程

当用户仅提供文件夹名称而未提供链接时，由 AI Agent 通过调用「获取文件清单」工具（`get-files`，文档见 `references/get-files.md`）完成查找。

### 查找策略

- **起始位置**：从根目录开始查找（`get-files` 传入空 `folder_token`）
- **匹配规则**：精确匹配 `type` 为 `folder` 且 `name` 与用户提供的名称完全一致的项（区分大小写）
- **递归深度上限**：2 层（根目录 → 子文件夹 → 孙文件夹）
- **子文件夹阈值**：5 个。当前层级未命中时，若子文件夹数量 ≤ 5，自动逐一进入子文件夹查找；若 > 5，反问用户让其提供链接或指定 `parent_folder_token`
- **广度优先**：同层全部遍历完成后再进入下一层

### 操作步骤

```
步骤 1：调用 get-files 获取根目录文件清单
        参数: { tenant_access_token, folder_token: "" }

步骤 2：在返回的 files 数组中筛选 type === "folder" 且 name === 用户提供的名称的项
        - 若命中 → 返回该文件夹的 token 与信息，流程结束
        - 若未命中 → 进入步骤 3

步骤 3：从根目录 files 中筛选出所有 type === "folder" 的子文件夹列表

步骤 4：判断子文件夹数量
        - 若 ≤ 5 个 → 进入步骤 5
        - 若 > 5 个 → 反问用户：
          "根目录下存在 N 个子文件夹，逐一查找可能耗时较长。
           请提供文件夹链接（推荐），或指定从哪个子文件夹开始查找。"

步骤 5：逐一调用 get-files 进入每个子文件夹查找（当前深度 = 1）
        对每个子文件夹：
          参数: { tenant_access_token, folder_token: 子文件夹的 token }
          在返回的 files 中筛选 type === "folder" 且 name 匹配的项
          - 若命中 → 返回该文件夹的 token 与信息，流程结束
          - 若未命中 → 收集该层所有 type === "folder" 的孙文件夹

步骤 6：判断当前深度
        - 若深度 < 2 且孙文件夹数量 ≤ 5 → 进入步骤 5 查找孙文件夹（深度 = 2）
        - 若深度 = 2 → 停止递归，返回查找失败
        - 若孙文件夹数量 > 5 → 反问用户

步骤 7：若 2 层内均未找到 → 返回失败，提示用户：
        "未在根目录及两层子文件夹中找到名称为 xxx 的文件夹。
         请确认名称是否正确，或直接提供文件夹链接。"
```

### 返回结果

无论方式一还是方式二，AI Agent 最终应向用户返回如下结构化信息：

```json
{
  "code": 0,
  "msg": "获取文件夹token成功",
  "data": {
    "folder_token": "XmlTfpUwQlH7ZTdih8gcN753nyc",
    "folder_name": "",
    "method": "url",
    "parent_folder_token": "",
    "found_at_depth": 0,
    "path": "根目录/项目文档"
  }
}
```

| 字段                | 说明                                                                       |
| ------------------- | -------------------------------------------------------------------------- |
| folder_token        | 文件夹的唯一标识 token                                                     |
| folder_name         | 文件夹名称。方式一时为空字符串，方式二时为匹配到的名称                     |
| method              | 获取方式：`url`（方式一链接提取）或 `name`（方式二 AI Agent 查找）         |
| parent_folder_token | 父文件夹 token。方式一和方式二在根目录命中时为空字符串                     |
| found_at_depth      | 命中时所在的深度。方式一固定为 0；方式二：0=根目录，1=子文件夹，2=孙文件夹 |
| path                | 从根目录到目标文件夹的路径描述，便于用户确认位置                           |

### 失败返回

```json
{
  "code": -1,
  "msg": "错误信息描述",
  "data": null
}
```

## 注意事项

1. **无脚本依赖**：本能力完全由 AI Agent 完成，无需调用任何 Node.js 脚本
2. **方式一优先**：用户同时提供链接和名称时，优先使用方式一（更快更准确）
3. **链接格式**：方式一仅支持 `/drive/folder/{token}` 格式的链接
4. **递归深度**：方式二硬性上限 2 层（根 → 子 → 孙），超过则停止并提示用户
5. **子文件夹阈值**：方式二中若当前层级未命中且子文件夹数量 > 5，AI Agent 应反问用户而非自动遍历，避免大量 API 调用
6. **同名文件夹**：方式二若存在多个同名文件夹，返回第一个匹配项；可通过 `path` 字段确认位置
7. **权限要求**：方式二需要应用具有云空间及目标文件夹的读取权限
8. **权限配置**：若调用 `get-files` 时返回 `1061004`（forbidden），需在浏览器中打开文件夹链接，将飞书企业自建应用添加为协作者并赋予「可管理」权限

## 错误处理

| 错误码   | 错误信息                                        | 来源   | 解决方案                                                                                                                    |
| -------- | ----------------------------------------------- | ------ | --------------------------------------------------------------------------------------------------------------------------- |
| 99991663 | Invalid access token                            | 方式二 | 运行 `cd "$SKILL_DIR/scripts" && node get-tenant-access-token.js --parameter-file-path <参数文件绝对路径>` 刷新令牌 |
| 1061004  | forbidden                                       | 方式二 | 在浏览器中打开文件夹链接，将飞书企业自建应用添加为协作者并赋予「可管理」权限                                                |
| -1       | 链接格式不正确，无法提取 token                  | 方式一 | 确认链接包含 `/drive/folder/` 路径                                                                                          |
| -1       | 未找到名称为 xxx 的文件夹                       | 方式二 | 确认文件夹名称是否正确，或请用户提供文件夹链接                                                                              |
| -1       | 根目录下存在 N 个子文件夹，逐一查找可能耗时较长 | 方式二 | 请用户提供文件夹链接（推荐），或指定从哪个子文件夹开始查找                                                                  |
