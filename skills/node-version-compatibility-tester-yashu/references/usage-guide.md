# 使用指南与示例

> **加载时机**：用户输入格式不明确、或需要查看具体调用示例时加载本文件。

## 技能定位

本技能是一个**通用测试工具**，可以测试任意用户指定的技能在不同 Node.js 版本下的兼容性。

## 通用使用模板

**用户输入格式**：

> 对技能 `{目标技能路径}` 进行 Node.js 版本兼容性测试

## AI 执行流程

| 步骤 | AI 行为                | 具体操作                                                                                 |
| ---- | ---------------------- | ---------------------------------------------------------------------------------------- |
| 1    | 读取目标技能文档       | 读取 `{目标技能路径}/SKILL.md`                                                           |
| 2    | 提取全脚本索引清单     | 从 SKILL.md 中找到「全脚本索引清单」表格，**列出所有要测试的功能脚本**                   |
| 3    | 分析凭证需求           | 判断每个功能是否需要外部 API 凭证                                                        |
| 4    | 读取凭证（如需要凭证） | 读取 `$TARGET_SKILL_DIR/.env`；若不存在则终止任务并使用 `AskUserQuestion` 向用户索要凭证 |
| 5    | 遍历所有功能 + 版本    | 对每个功能脚本，在 3 个 Node 版本下分别执行实际运行测试                                  |
| 6    | 生成报告               | 汇总各 Node.js 版本 × 各功能的测试结果                                                   |

### ⚠️ 关键原则：必须测试所有功能

- 从「全脚本索引清单」获取功能列表
- **不能跳过任何一个功能**
- 全部测试完毕后才能生成报告

## 测试执行要点

**对于每个目标技能，AI 必须：**

1. **阅读目标技能的 SKILL.md 文档**
   - 找到「全脚本索引清单」表格，这是所有功能脚本的列表
   - 学习每个功能的调用方式（命令格式、参数格式）

2. **必须测试所有功能，不能遗漏**
   - 对清单中的每个功能脚本分别执行测试
   - 对每个功能脚本，分别在 3 个 Node 版本下执行

3. **不要假设命令格式**
   - 不同技能有不同的调用方式
   - 必须从目标技能的文档中学习正确的调用方式

4. **构造测试参数**
   - 从目标技能的 `references/*.md` 文档中获取正确的参数格式
   - 对于需要凭证的功能，询问用户

5. **执行真实测试**
   - 按照文档说明的方式运行脚本
   - 记录实际输出（成功/失败 + 错误信息）

## 示例：测试任意技能

**用户输入**：

> 对技能 `skills\wechat-publisher-yashu` 进行 Node.js 版本兼容性测试

**AI 执行**：

1. 读取 `skills\wechat-publisher-yashu\SKILL.md`
2. 从文档中找到「全脚本索引清单」表格，例如：
   | 脚本 | 功能 |
   | ---- | ---- |
   | publish.js | 发布文章 |
   | query.js | 查询状态 |
   | delete.js | 删除文章 |
3. 对每个功能（publish、query、delete），分别在 Node 18.20.8、20.20.1、24.18.0 下执行测试
4. 记录结果，生成兼容性报告

## 示例：测试需要凭证的技能

**用户输入**：

> 对技能 `skills\feishu-bitable` 进行 Node.js 版本兼容性测试

**AI 执行**：

1. 读取 `skills\feishu-bitable\SKILL.md`，学习调用方式
2. 发现需要飞书 API 凭证，读取 `$TARGET_SKILL_DIR/.env`；若 `.env` 不存在则使用 `AskUserQuestion` 询问用户
3. 根据凭证情况执行测试或等待用户提供凭证
