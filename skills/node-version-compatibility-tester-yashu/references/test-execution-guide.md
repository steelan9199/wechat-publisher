# 实际运行测试执行指南

> **加载时机**：执行【兼容性测试模式】步骤 4「执行测试」时，必须加载本文件。

## 执行测试规范（强制遵守）

**禁止使用 `node --check` 语法检查！必须进行实际功能测试！**

| 判定    | 操作方式                                       | 说明                           |
| ------- | ---------------------------------------------- | ------------------------------ |
| ✅ 正确 | 按照目标技能的文档，对每个功能执行实际运行测试 | 真实运行技能功能，验证实际效果 |
| ❌ 错误 | 使用 `node --check` 对代码进行基础检查         | 仅做语法检查，不验证实际功能   |

## 实际运行测试的四步流程

### 第一步：动态分析目标技能

```
读取 {目标技能路径}/SKILL.md
    │
    ├─ 提取「全脚本索引清单」→ 这是最重要的！列出了所有功能脚本
    │                           【必须测试每一个，不能遗漏】
    │
    ├─ 提取脚本路径 → 识别 scripts/ 目录下的所有可执行文件
    │
    └─ 分析凭证需求 → 检查是否需要 token、apiKey、secret 等外部凭证
```

### 第二步：分类处理功能

| 功能类型       | 识别特征                    | 测试方式                   |
| -------------- | --------------------------- | -------------------------- |
| **本地处理类** | URL解析、文件转换、格式处理 | 构造示例参数，直接执行测试 |
| **API调用类**  | 需要 token、apiKey、secret  | 询问用户是否提供凭证       |
| **交互类**     | 需要用户输入                | 使用模拟输入执行测试       |

### 第三步：阅读文档并执行测试

**对于每个功能，AI 必须：**

1. **仔细阅读目标技能的 SKILL.md 文档**
   - 找到该功能的调用方式（命令格式、参数格式）
   - 理解该功能需要什么输入参数
   - 确认是否需要外部凭证

2. **按照文档说明构造测试参数**
   - 参考文档中的示例
   - 对于需要凭证的功能，使用 `AskUserQuestion` 询问用户

3. **按照文档说明的方式执行脚本**
   - **不要假设命令格式**，必须从文档中学习
   - 不同技能可能有不同的调用方式：
     - `node scripts/xxx.js --parameter-file-path params.json`
     - `python scripts/xxx.py --config config.yaml`
     - `node scripts/xxx.js --input "data"`
     - 或其他文档中定义的方式

4. **记录实际输出**：成功/失败 + 错误信息

### 第四步：处理凭证需求

```
功能需要凭证？
    │
    ├─ 是 → 读取 $TARGET_SKILL_DIR/.env
    │       │
    │       ├─ .env 存在 → 从 .env 中读取凭证，构造参数并执行测试
    │       │
    │       └─ .env 不存在 → 终止任务，使用 AskUserQuestion 向用户索要凭证
    │
    └─ 否 → 直接构造测试参数并执行
```

## 测试参数构造指南

### 重要原则

测试参数**必须**从目标技能的参考文档（`references/*.md`）中获取，不能随意构造！

### 如何获取正确参数

1. **读取目标技能的 SKILL.md**，找到该功能对应的参考文档路径
2. **读取对应的 `references/*.md` 文档**
3. **严格按照文档中的参数格式构造参数文件**

| 功能类型   | 正确做法                                     | 错误做法                  |
| ---------- | -------------------------------------------- | ------------------------- |
| URL解析类  | 读取 `references/url-to-document-id.md`      | 随意构造 `{"url": "..."}` |
| 文件转换类 | 读取 `references/feishu-to-markdown.md`      | 随意构造参数              |
| 上传类     | 读取 `references/markdown-to-feishu.md`      | 随意构造参数              |
| 令牌获取类 | 读取 `references/get-tenant-access-token.md` | 随意构造参数              |

### 参数文件存放规则

- 临时参数文件**必须**存放在 `$SKILL_DIR/temp` 目录
- 不能与脚本文件混杂存放
- 每个功能测试完成后**必须**清理（调用 `clear_temp.js`）

## 凭证处理策略

当目标技能需要外部 API 凭证时，按以下流程处理：

```
功能需要凭证？
    │
    ├─ 是 → 读取 $TARGET_SKILL_DIR/.env
    │       │
    │       ├─ .env 存在 → 从 .env 中读取凭证，执行测试
    │       │
    │       └─ .env 不存在 → 终止任务，使用 AskUserQuestion 向用户索要凭证
    │
    └─ 否 → 直接执行测试
```

## 授权保护处理规则（重要）

当目标技能本身有授权保护（如 license-key.txt、免费试用限制）时：

| 识别信号             | 说明               |
| -------------------- | ------------------ |
| `免费试用次数已用完` | 试用期已用完       |
| `请购买授权码`       | 需要购买授权       |
| `license-key.txt`    | 提示写入授权码文件 |
| `授权码`             | 明确要求授权码     |
| `未授权`             | 未经授权           |
| `请先激活`           | 需要激活           |

**处理流程：**

1. **检测到授权保护信号 → 立即终止该功能测试**
2. **真实记录**：将授权保护作为测试结果的一部分
3. **标记结果**：`跳过（授权保护）`
4. **禁止绕过**：绝对不能用 curl、Invoke-RestMethod 等方式尝试绕过授权保护来测试
