# 3. 交付（按 §0.1 档位裁剪，不写用不到的节）

## 3.0 [GATE] Gate 0：先划走，再分解

先做官方 Step 1：能用规则、正则、精确查找、状态机、数据库唯一约束解决的判断，**整条划走**，写「留给代码」+ 理由，**不进判断表**。

## 3.5 组合

### 3.5.1 调度（[→SKILL]「Compose and verify」第 1 段）

- 并行：同一份 state 上可同问的（含推测性问句）；每个推测前提写进 instructions。
- 串行：哪些必须先拿答案才能取证据 / 构造新 state / 定下一组选项；写明第二请求**具体多带了什么**。
- 新鲜度：state 会在等待期间变 → 写版本号 / 时间戳守卫。
- 停止：最多几轮、何谓收敛。
- 预算：[ADD] **请求数 = Σ(每批条数)**，不是「批次 × 批内条数」。token 主要来自同一份 state 的重复携带。
- §0.5 允许联网 → 跑一次实测，贴真实耗时与返回。
