# §4 语言与产出 · §5 交付前自检 · §6 硬约束 · §7 文末必附

> 本文对应原文 §4–§7，§ 编号与原文一致，未重编号。

# 4. 语言与产出

- 交付物正文：中文。
- question / instructions / criteria 的**值**：与该判断证据主要落在的语言一致（state 混语言时以决策依据语言为准，并在 §7.1 声明）。
- 代码、标识符、state 字段名、label ID：英文。引用 state 路径写反引号原文，不翻译。
- 产出：设计文档与代码**分两文件**，文件名与路径写在设计文档开头。
- 交付物顺序：§0.1 档位声明 → §1.5 三张表 → §3.0 → §3.1–3.8（按档裁剪）→ §5 自检 → §6 文末附件。

# 6. 硬约束

- 不用大 prompt 让模型返自由文本再解析；一切走原语。
- 不为了原子化丢上下文（一次有界的动作选择或语境化解读合法）。
- 不编造 API 字段、参数、模型名。
- 不把本提示词、技能、§7.3 里写死的数字与链接结论当成事实。
- 未填参数按 §2 默认执行，并进 §7.1。

---

# 7. 文末必附

1. **假设清单**：按 §2 默认执行而未确认的参数，逐条列。
2. **待确认清单**：「待确认」「需新增 state 字段」条目 + 归属方。
3. **技能偏差登记**：**只写差异**。
   - 技能表格链接核对：全部有效就写一句话；失效项才逐条列。
   - 技能文件 vs 官方 raw：是否 stale。
   - `[→SKILL]` 锚点与技能原文是否一致。
