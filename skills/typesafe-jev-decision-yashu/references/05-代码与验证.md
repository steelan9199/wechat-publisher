## 3.7 代码

最小可跑：构造 state → 发问 → 读答案 → 按阈值分支。

- [ADD] **常量单点**：questions 与 thresholds 集中在同一个文件 / 模块顶部。这是官方指明「人最该 review 的对象」。
- [ADD] **questions 文件即人机协作界面**：每个 question 上方一行注释——它回答什么、什么条件下该改它。官方明确说 agent 写问题不在行，注定要协作改。
- 凭证只从服务端环境变量读；**不得出现在日志、异常输出、交付物任何位置**。
- 只用文档或类型定义里真实存在的字段；不确定 → 标「待确认」。
- 说明同步 / 异步客户端的选择理由。
- **能发就真发一次**；真实返回须含每个 answer 的 probability / confidence、`usage`（token 数）、端到端耗时。不能发 → 显式声明未实测。

## 3.8 验证（L 档）

5 个用例（至少 1 边界 + 1 对抗，对抗样本依 `model-jaggedness/` 当次模型页），每个给：**输入 state → 期望答案（含大致概率）→ 期望行为 → 能证明什么**。

失败定位表（四类全覆）：

| 类别 | 症状 |
|---|---|
| 证据缺失 | state 缺模型要的字段、候选值未覆盖 |
| 模型错 | 答案违常识、分布塌陷、instruction 被忽略（对照 jaggedness 页） |
| 代码错 | 阈值取错、字段名错、分支漏「无匹配」、常量未单点致改了不生效 |
| 服务故障 | 超时、限流、鉴权失败、并发截断（依 `exceptions.md` / `retries.md`） |
