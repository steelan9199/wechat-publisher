## 0.1 [GATE] 规模判定（先于一切阅读与设计）

开场一句话写明档位。档位决定 §1 预算与 §3 产出物，**不按档位裁剪的交付物视为未完成**：

| 档 | 触发条件 | 产出物 |
|---|---|---|
| **X 只需结论** | 无明确产品行为；或 Gate 0 划走后无剩余判断 | 一段结论 + 建议，**终止**，不产设计文档、不填表 |
| **S 单判断增量** | 现有流程加 1–2 个判断，单轮请求 | 判断表 + 代码 + 1 次实测 |
| **M 新流程** | 新建 3+ 判断的流程，单轮或两轮 | S + 调度 + 合成 + 阈值契约表 |
| **L 带证据 / 多轮 / 阈值敏感** | 需检索证据、多轮，或阈值影响资金 / 合规 / 人身 | M + 八步对齐表 + 5 用例 + 失败定位表 |

判不准 → 取低档，并说明「若需 L 档请说一声」。

## 0.3 [GATE] 事实基准与反漂移（四条，同一条消息内并发）

1. 读 `https://docs.typesafe.ai/llms.txt`。**它是当次唯一路径基准**——此后一切页面路径以它为准，不以技能表格、也不以本提示词的任何路径为准。
2. [ADD] 读 `agent-skill.md`。技能表格里没有这一页。它的 4 条 vibe-coding 原则与 common issues 表属于**执行指令**而非背景知识，其中原则 2（先审计划再实施）、原则 3（常量单点 + 问题需与人协作改）、原则 4（不接受断言的面值，主动验证自己的假设）、issue「confidence 阈值滥用」四条直接决定 §2/§3 形态，逐条落实。
3. [ADD] **查技能本身是否过时**：比对本地 `SKILL.md` 与官方 raw（`raw.githubusercontent.com/typesafe-ai/skills/main/skills/typesafe-ai/SKILL.md`）。官方把「agent 编造字段」的头号成因判为 stale skill。有差异 → 报告并建议更新，**不静默沿用**。
4. 核对技能表格 + 本提示词里出现的每个路径是否仍在索引中。不在 → 记入 §7.3，**不得据此写代码**。

## 0.4 [GATE] 环境事实探测（先查清，再写代码）

| 查什么 | 怎么查 |
|---|---|
| SDK 装了没 / 版本 | 锁文件（`pyproject.toml` / `requirements*.txt` / `poetry.lock` / `uv.lock` / `package.json` + lock）、`pip show`、`npm ls`；版本号写进交付物 |
| 包名与导入路径 | `sdk/python.md` / `sdk/javascript.md`，并对照该 SDK 的 `changelog.md`。**不许猜** |
| 类型定义 | Python：site-packages 下 `.pyi` / `py.typed`；Node：`node_modules/**/*.d.ts` |
| 凭证变量名 | `sdk/{python\|javascript}/api/constants.md` |
| 凭证可用性 | [ADD] 只判**是否存在**，绝不打印值 |
| 能否跑最小调用 | [ADD] 跑 `introduction/quickstart.md` 的最小调用——它决定 §3 是实测还是「未实测，概率为推测」 |
| SDK 未装 | 先报告，问是否允许装；**不得凭空写 import 路径或依赖版本号** |

## 0.5 [ADD] 实验优先

若用户已导出凭证且允许联网：**在锁定设计之前**先用便宜的小请求试 question 措辞与候选值覆盖，拿真实分布回来再定 §3 的判断表。

- 探索性试探（定设计用）与交付性实测（§3.7 贴真实返回）**是两件事，都要做**，不要合并。
- 试探不计入 §3 产出，但发现的措辞问题要写进 §7.1。
- 不允许联网 → 跳过本闸门，并在 §3 显式声明未实测。
