# PPT Master Rules · 大师级演示文稿生成规则

本文件是 `guizang-ppt-lite` 的强制生成规范。生成任何 PPT 前，先按本规则做演示设计，再写 HTML。

## 1. 核心原则

| 原则     | 要求                                     | 常见错误                             |
| -------- | ---------------------------------------- | ------------------------------------ |
| 结论先行 | 页面标题优先表达判断，而不是描述主题     | “AI 新范式”这种空标题                |
| 一页一事 | 每页只承载一个主观点                     | 一页同时讲背景、问题、方案、行动     |
| 视觉中心 | 第一视觉焦点必须清晰                     | 所有元素大小接近，观众不知道先看哪里 |
| 信息层级 | 主标题、主视觉、支撑点、注释形成递减层级 | 标题弱、正文重、卡片平均分布         |
| 叙事推进 | 每页与前后页存在因果、对比、递进或转折   | 页面像随机拼图                       |
| 认知减负 | 减少观众解释成本                         | 小字密集、概念过多、装饰抢戏         |
| 克制审美 | 用比例、留白、对齐、对比建立高级感       | 渐变、发光、阴影、随机图形           |

## 2. 生成前必须完成的演示蓝图

生成前在内部完成以下蓝图：

| 蓝图项   | 输出标准                                                        |
| -------- | --------------------------------------------------------------- |
| 核心主张 | 整套 PPT 用一句话说清楚要让听众相信什么                         |
| 目标动作 | 听众看完后要批准、对齐、购买、传播，还是启动项目                |
| 叙事弧   | Hook → Context → Tension → Insight → Framework → Proof → Action |
| 页面地图 | 每页角色不同，不能只是内容平均拆分                              |
| 节奏设计 | 大字页、结构页、对比页、行动页交替出现                          |
| 风险点   | 哪些页可能内容过密、视觉重心失衡、低对比或无结论                |

## 3. 页面角色库

每页必须先归类为以下一种角色。

| 页面角色       | 功能               | 推荐视觉中心                     | 禁忌             |
| -------------- | ------------------ | -------------------------------- | ---------------- |
| Hook 钩子      | 让听众立刻进入问题 | 强标题 / 反差句 / 单一大数字     | 上来讲目录       |
| Context 背景   | 解释为什么现在讨论 | 时间变化 / 外部压力 / 关键事实   | 背景铺太长       |
| Tension 问题   | 制造必要紧迫感     | Before/After / 三个瓶颈 / 断点图 | 只罗列痛点       |
| Insight 洞察   | 给出新解释         | 一句话判断 / 框架图              | 复述常识         |
| Framework 框架 | 把复杂问题结构化   | 2x2、三层、闭环、飞轮            | 维度不 MECE      |
| Evidence 证据  | 支撑判断           | 数据、案例、流程证据             | 编造数字、堆截图 |
| Path 路径      | 告诉怎么做         | 时间线、阶段、能力栈             | 只有口号没有步骤 |
| Action 行动    | 明确下一步         | 责任、动作、节奏、产出           | 行动藏在底部     |
| Close 收束     | 形成共识或决策     | 金句 / 决策问题 / 下一步         | 重复封面         |

## 4. 页面布局审美规则

### 4.1 视觉中心

每页必须只有一个第一视觉焦点。常见焦点：

- 一个强结论标题
- 一个大数字
- 一个对比结构
- 一个框架图
- 一个行动清单的首要动作

禁止：

- 三个以上元素争夺第一焦点。
- 主要信息被放到底部或角落。
- 视觉中心和页面结论不一致。

### 4.2 信息层级

推荐层级：

```text
Level 1: 页面结论 / 主视觉
Level 2: 关键结构 / 关键数字 / 关键对比
Level 3: 3-5 个支撑点
Level 4: 注释、来源、页脚
```

硬规则：

- 标题必须比正文强至少 2 个层级。
- 支撑卡片不能全部等重；至少有 1 个重点或明确顺序。
- 注释不能抢正文注意力。

### 4.3 留白与重心

| 项目     | 标准                                   |
| -------- | -------------------------------------- |
| 页面上方 | 不空到失衡，也不贴顶                   |
| 页面下方 | 保留导航安全区，核心内容不得沉底       |
| 左右边距 | 统一轴线，不随页漂移                   |
| 卡片间距 | 体现分组关系，不平均撒开               |
| 视觉重心 | 通常位于画面上中或中部，不默认压到底部 |

禁止靠 `align-items:end`、大 margin、绝对定位把主要内容推到底部，除非该页是明确设计的“悬念收束页”。

### 4.4 对齐与网格

- 页面必须有清晰主轴：左轴、中心轴或分栏轴。
- 同一组元素必须共享边线或中心线。
- 分割线、卡片、标题和正文必须服务结构，而不是装饰。
- 不得出现看似随机的漂浮元素。

### 4.5 横向翻页机制（硬约束）

PPT 必须为**横向翻页**，页面水平排列，左/右键切换。HTML 实现必须遵循以下规则：

**必须使用的模式：**

| 层级 | 要求                                                                                 |
| ---- | ------------------------------------------------------------------------------------ |
| HTML | `<div id="deck">` 作为所有 slide 的容器，`display: flex`，页面水平排列               |
| CSS  | `.slide` 设 `min-width: 100vw` / `flex: 0 0 100vw`，翻页用 `transform: translateX()` |
| JS   | `deck.style.transform = translateX(-N * 100vw)`，每次切换精确移动一个视口宽度        |
| 容器 | `#deck` 宽度由 JS 动态计算：`deck.style.width = slideCount * 100 + "vw"`             |
| 主体 | `body { overflow: hidden }` 完全禁用原生滚动，翻页不依赖浏览器滚动机制               |

**禁止的模式：**

| 禁止项                                                   | 原因                                                |
| -------------------------------------------------------- | --------------------------------------------------- |
| `scroll-snap-type: y mandatory`                          | 导致纵向滚动而非横向翻页                            |
| `scroll-snap-type: x mandatory`                          | 浏览器吸附无法像素级精确对齐，会露出下一页内容      |
| `scroll-snap-align: start`                               | 依赖浏览器滚动，对齐不可靠                          |
| `scroll-behavior: smooth`                                | 让滚动行为不可控                                    |
| `scrollIntoView()`                                       | 无法做到精确的 `100vw` 对齐，页面会卡在两个视口之间 |
| `IntersectionObserver` 监听滚动切换页码                  | 在有吸附偏移时误判当前页                            |
| `.ppt-safe-frame { width: 100vw; height: 100vh }` 无容器 | 页面纵向堆叠而非水平排列                            |

### 4.6 动效引擎脚本（硬约束）

模板 `assets/template.html` 中的 `<script type="module">` Motion One 动效引擎脚本**必须逐字完整复制**到生成的目标 HTML 中，禁止以下行为：

| 禁止项                   | 原因                                                              |
| ------------------------ | ----------------------------------------------------------------- |
| 手写或"简化"模块脚本     | 必然遗漏 `playSlide(0)` 初始化调用，导致首屏加载后文字消失        |
| 只复制部分逻辑           | `window.__playSlide` 注册和首屏初始化紧密耦合                     |
| 删除 `playSlide(0)` 调用 | 模板底部同步 `go(0)` 先于模块脚本执行，无此补调则首屏动效永不触发 |

> **技术原因**：页面底部的同步 `<script>` 调用 `go(0)` 时，`<script type="module">` 尚未执行完毕，`window.__playSlide` 未定义。模块脚本完成后必须补调 `playSlide(0)` 以触发生效页的入场动画。详见 `assets/template.html` 末尾的注释。

## 5. 叙事节奏规则

### 5.1 基础节奏

10 页左右推荐：

```text
1 封面钩子
2 Why Now
3 问题 / 瓶颈 1
4 问题 / 瓶颈 2
5 问题 / 瓶颈 3 或总结
6 核心洞察 / 新范式
7 能力框架
8 路径 / 阶段
9 管理行动 / 决策请求
10 收束 / 共识
```

### 5.2 节奏变化

每 3-4 页至少变化一次页面类型：

- 大标题页
- 对比页
- 结构图页
- 卡片/清单页
- 时间线页
- 行动页
- 收束页

禁止连续 3 页都是同一种卡片网格。

## 6. 商业表达规则

| 表达对象 | 优先写法                                 | 避免写法       |
| -------- | ---------------------------------------- | -------------- |
| 标题     | “AI 转型的本质是组织能力升级”            | “AI 转型”      |
| 问题     | “传统流程为确定性设计，无法承接持续试验” | “流程问题”     |
| 框架     | “决策、流程、数据、人才、治理五项能力”   | “多维能力提升” |
| 行动     | “90 天内选择 3 条任务链做闭环验证”       | “加强 AI 应用” |
| 收束     | “先改变组织能力定义，再采购工具”         | “谢谢观看”     |

## 7. 配色安全与文字完整显示规则（硬约束）

**这是不可协商的硬性规则。任何页面的配色和文字显示如果不通过本章检查，必须修正，不得交付。**

### 7.1 对比度硬规则

| 场景              | 要求                                        | 禁止                               |
| ----------------- | ------------------------------------------- | ---------------------------------- |
| 浅色背景正文      | `#0a0a0a` 或 `var(--ink)`，明度不超过 15%   | `#5f5f5b`、`#737373`、透明度叠加灰 |
| 深色背景正文      | `#fafaf8` 或 `var(--paper)`，明度不低于 85% | `rgba(255,255,255,0.6)` 及更低     |
| 蓝色/彩色背景正文 | `var(--accent-on)`，纯白                    | 灰色、低对比色                     |
| 灰色背景卡片正文  | `var(--ink)`，不依赖 `opacity`              | 在半透明背景上用灰字               |

### 7.2 半透明容器禁令

| 禁止                                              | 原因                          | 修正                                |
| ------------------------------------------------- | ----------------------------- | ----------------------------------- |
| `background: rgba(255,255,255,0.45)` 容器承载正文 | 背后网格/背景会穿透，正文发虚 | 改为 `.surface-light` / `.no-glass` |
| `backdrop-filter: blur()` + 低对比正文            | 模糊背景削弱文字边缘          | 取消模糊或用不透明背景              |
| 卡片用 `opacity` 同时影响文字                     | opacity 是全局作用            | 只对背景色做半透明，不对整个容器    |

### 7.3 正文颜色禁用清单

以下写法在正文中文场景禁止使用：

- `color: var(--muted)` 且 `--muted` 明度在 30%-65% 之间
- `color: #5f5f5b`、`#737373`、`#888`、`#999` 作为正文主色
- `color: rgba(10,10,10,0.6)` 或更低 opacit
- `color: rgba(255,255,255,0.55)` 或更低
- 用 `opacity` 降低整段正文对比度

允许的正文颜色：

- 浅底：`var(--ink)` / `#0a0a0a`
- 深底：`var(--paper)` / `#fafaf8`
- 浅底辅助文字（注释、脚注）：`var(--text-secondary)`，但不得用于主要说明文字

### 7.4 文字完整显示规则

| 检查项     | 标准                                 |
| ---------- | ------------------------------------ |
| 标题裁切   | 标题不得被容器 overflow 隐藏任何字符 |
| 正文裁切   | 卡片正文不得被截断最后一行           |
| 图注遮挡   | 底部图注不得被导航 dot 遮盖          |
| 行动项遮挡 | 行动页文字不得进入导航安全区         |
| 超长内容   | 拆页或浓缩，不得缩小字号到 14px 以下 |

### 7.6 字符编码硬规则（不可协商）

**HTML 文件中所有中文、日文、韩文（CJK）字符必须写为原文字符，严禁使用 Unicode 转义序列。**

| 禁止                          | 正确           |
| ----------------------------- | -------------- |
| `\u8fc7\u53bb 40 \u5e74`      | `过去 40 年`   |
| `\u4f01\u4e1a\u8f6f\u4ef6`    | `企业软件`     |
| 任何 `\uXXXX` 形式的 CJK 内容 | 对应的原文字符 |

此规则是硬约束。Unicode 转义序列在 HTML 的 `<meta charset="UTF-8">` 声明的文件中不会被浏览器正确渲染，会直接显示为 `\uXXXX` 原始文本，导致整个文件不可读。此错误一旦发生，整个 HTML 文件视为废品，必须重新生成。

### 7.5 配色安全检查模板

生成后每页检查：

```text
[ ] 浅底卡片上的正文是否为 var(--ink) 或等效深色？
[ ] 灰底卡片上的正文是否清晰可读（不依赖 opacity）？
[ ] 暗底页面上的说明文字是否足够亮（不低于 rgba(255,255,255,0.78)）？
[ ] 是否存在半透明容器（rgba .4-.6）承载正文？
[ ] 标题、正文、图注、行动项是否有任何裁切或遮挡？
[ ] 如果用户指出"看不清"，是否在 1 分钟内定位到具体元素并修正？
```

## 8. 场景加权规则

### 董事会汇报

权重：结论 35%，证据 25%，行动 25%，美感 15%。

- 标题必须是结论句。
- 每页都能回答“所以管理层要做什么”。
- 行动页必须清晰、居中、有优先级。

### 战略发布

权重：情绪 30%，叙事 30%，共识 25%，美感 15%。

- 允许大字和留白，但必须服务转折。
- 避免连续口号页。
- 每个抽象概念必须落到具体行为。

### 产品路演

权重：价值 35%，可信 25%，差异 25%，美感 15%。

- 功能必须翻译成客户收益。
- 证明页必须明确“为什么可信”。
- CTA 必须具体。

### 趋势洞察

权重：洞察 35%，解释 25%，启发 25%，美感 15%。

- 必须有反常识或新框架。
- 不做信息搬运。
- 结尾必须给出管理启示。

## 9. 交付前逐页审查清单

生成后逐页检查：

```text
[ ] 这页角色是否明确？
[ ] 标题是否是完整结论？
[ ] 第一视觉焦点是否清晰？
[ ] 观众 3 秒能否知道重点？
[ ] 信息层级是否递减？
[ ] 内容是否过密？
[ ] 视觉重心是否稳定？
[ ] 是否有低对比、白底白字或裁切？
[ ] 这页和前后页是否有叙事关系？
[ ] 是否存在随机装饰或无意义图形？
```

任何一项不通过，必须先修正再交付。
