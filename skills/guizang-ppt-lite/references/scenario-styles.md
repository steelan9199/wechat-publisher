# Scenario Styles · 4 个 PPT 使用场景风格

本文件定义 `guizang-ppt-lite` 唯一允许对外使用的 4 种场景风格。风格以“听众、目标动作、内容结构、页面规则”为核心，不以纯视觉标签命名。

## 1. 董事会汇报 Boardroom Brief

| 项目       | 规则                                             |
| ---------- | ------------------------------------------------ |
| 适用       | CEO 战略会、董事会、经营会、组织变革会、业务复盘 |
| 听众       | 高管、业务负责人、决策者                         |
| 目标       | 形成判断、批准方向、明确行动                     |
| 模板       | `assets/template.html`                           |
| 视觉关键词 | 瑞士网格、强标题、克制色彩、结构图、行动清单     |
| 内容关键词 | 结论先行、因果清晰、证据支撑、责任明确           |

### 推荐叙事

```text
Executive Hook → Why Now → Bottleneck → Strategic Insight → Framework → Path → Governance → Management Action
```

### 页面规则

- 标题写成结论句，例如“AI 转型的本质是组织能力升级”。
- 每页必须回答一个管理问题：为什么、差距在哪、怎么做、谁负责、何时复盘。
- 视觉中心通常是结论标题、关键数字、框架图、对比结构或行动清单。
- 行动页不能沉底；行动项必须处于页面中部或上中部视觉中心。
- 禁止口号化、情绪化、装饰化。

## 2. 战略发布 Executive Keynote

| 项目       | 规则                                             |
| ---------- | ------------------------------------------------ |
| 适用       | 战略发布、年度大会、内部动员、愿景宣讲、变革启动 |
| 听众       | 全员、管理层、合作伙伴                           |
| 目标       | 建立共识、激发行动、形成方向感                   |
| 模板       | `assets/template.html`                           |
| 视觉关键词 | 大标题、强节奏、留白、对比、阶段性金句           |
| 内容关键词 | 冲突、转折、信念、未来图景、行动号召             |

### 推荐叙事

```text
Tension → Shared Reality → Belief → Strategic Shift → Future State → Pillars → Call to Action
```

### 页面规则

- 每页只传递一个强观点，不做信息堆叠。
- 大字页只用于钩子、转折、共识、收束，不连续滥用。
- 抽象愿景必须落到具体行为变化。
- 情绪要克制，避免鸡血口号。

## 3. 产品路演 Product Pitch

| 项目       | 规则                                                  |
| ---------- | ----------------------------------------------------- |
| 适用       | 产品发布、客户提案、SaaS 方案、融资路演、解决方案介绍 |
| 听众       | 客户、投资人、销售团队、合作伙伴                      |
| 目标       | 让听众相信价值、理解差异、愿意进入下一步              |
| 模板       | `assets/template.html`                                |
| 视觉关键词 | 模块化、流程图、产品结构、少量高亮、理性科技感        |
| 内容关键词 | 痛点、收益、方案、差异、证明、转化                    |

### 推荐叙事

```text
Problem → Cost of Inaction → Solution → Workflow → Differentiation → Proof → Business Value → Next Step
```

### 页面规则

- 功能必须翻译为客户收益。
- 产品结构页要回答“它如何工作”，不是堆功能列表。
- 差异页要回答“为什么不是别人”。
- 证明页优先使用案例、流程结果、用户证据；没有证据时不编造数据。

## 4. 趋势洞察 Insight Editorial

| 项目       | 规则                                             |
| ---------- | ------------------------------------------------ |
| 适用       | 趋势报告、行业洞察、白皮书、观点分享、研究型演讲 |
| 听众       | 管理者、专家、媒体读者、行业从业者               |
| 目标       | 产生新理解、形成判断框架、启发下一步行动         |
| 模板       | `assets/template.html`                           |
| 视觉关键词 | 编辑感、标题张力、图文节奏、留白、纸感           |
| 内容关键词 | 反差、信号、模式、框架、启示                     |

### 推荐叙事

```text
Provocation → Signal → Pattern → Framework → Implication → Opportunity → Takeaway
```

### 页面规则

- 开场必须有反差或新判断。
- 不做信息搬运；每个事实必须服务一个洞察。
- 框架页要解释变化背后的机制。
- 结尾必须回答“这对听众意味着什么”。

## 5. 场景风格选择优先级

当用户同时表达多个关键词时，按以下优先级判断：

1. **听众是谁**：高管/客户/全员/专家。
2. **目标动作是什么**：决策/购买/共识/启发。
3. **使用场景在哪里**：会议室/发布会/销售路演/报告分享。
4. **内容形态是什么**：战略、产品、愿景、趋势。

示例：

| 用户需求                                      | 应选场景   |
| --------------------------------------------- | ---------- |
| “AI 时代传统企业组织能力升级，CEO 内部战略会” | 董事会汇报 |
| “年度战略发布，面向全员讲清未来三年方向”      | 战略发布   |
| “给客户介绍我们的 AI 客服产品方案”            | 产品路演   |
| “做一份 2026 年行业趋势洞察报告”              | 趋势洞察   |

## 6. 跨场景统一审美底线

无论选择哪种场景，都必须遵守：

- 一页一个主观点。
- 第一视觉焦点清晰。
- 信息层级递减。
- 叙事不是内容均分。
- 低对比、裁切、沉底、随机装饰一律不合格。
- 没有素材就不用图片版式。
- 没有真实数据就不用伪 KPI。
