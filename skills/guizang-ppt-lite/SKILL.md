# guizang-ppt-lite

生成一份**高级质感、商业表达优先、符合成熟演示文稿规则、单文件 HTML**的横向翻页网页 PPT。
生成的ppt放到当前项目的ppt文件夹下。

最高原则：**先做演示设计，再写 HTML。**
不得把内容随机塞入模板；每一页都必须先通过“页面角色、核心结论、视觉中心、信息层级、叙事节奏、可读性”的设计审查。

详细规则参考：[`references/ppt-master-rules.md`](references/ppt-master-rules.md) 与 [`references/scenario-styles.md`](references/scenario-styles.md)。

| -------------------------- | --------------------------------------- | ---------------------- | ---------------------------- | --------------------------------- |
| 董事会汇报 Boardroom Brief | CEO 会、董事会、经营会、战略复盘        | 高管、业务负责人       | 结论先行、证据支撑、行动清晰 | `assets/template-consulting.html` |
| 战略发布 Executive Keynote | 战略发布、组织动员、愿景宣讲            | 全员、管理层、合作方   | 冲突—转折—共识—行动          | `assets/template-narrative.html`  |
| 产品路演 Product Pitch     | 产品发布、SaaS 方案、融资路演、客户提案 | 客户、投资人、销售团队 | 痛点、方案、差异、证明、转化 | `assets/template-tech.html`       |

## 强制工作流

### Step 1 · 明确演示任务

先判断以下 5 项；信息不足且会影响质量时，最多问 3 个选择题。

| 判断项     | 必须明确                                     |
| ---------- | -------------------------------------------- |
| 使用场景   | 是决策会、动员会、路演，还是洞察分享         |
| 听众       | 谁在听，他们关心决策、认同、购买还是启发     |
| 目标动作   | 听完要批准、对齐、购买、传播，还是启动项目   |
| 内容成熟度 | 是只有主题、已有大纲、已有长文，还是已有素材 |
| 约束       | 页数、语气、品牌、是否需要数据/图片          |

### Step 2 · 先产出演示蓝图

生成 HTML 前，先在内部完成演示蓝图：

```text
受众判断 → 核心主张 → 叙事弧 → 页面清单 → 每页角色 → 每页核心结论 → 每页视觉中心 → 每页版式类型
```

不得跳过蓝图直接写页面。

### Step 3 · 使用成熟 PPT 规则设计每页

每页写代码前，必须逐页确认：

| 规则       | 通过标准                                                              |
| ---------- | --------------------------------------------------------------------- |
| 页面角色   | 这页是钩子、背景、问题、洞察、框架、证据、方案、路线图、行动还是收束  |
| 核心结论   | 标题或主视觉能独立表达一个完整判断                                    |
| 视觉中心   | 页面有且只有一个第一视觉焦点；观众 3 秒知道先看哪里                   |
| 信息层级   | 主标题 > 关键数字/图形 > 支撑点 > 注释，层级清晰                      |
| 叙事位置   | 这页和前后页有因果/转折/递进关系，不是随机并列                        |
| 认知负荷   | 一页最多 1 个主观点 + 3-5 个支撑点；复杂内容拆页                      |
| 留白与重心 | 内容不贴边、不贴底、不平均摊满；视觉重心稳定                          |
| 对齐与网格 | 页面元素共享清晰轴线，禁止随意漂浮                                    |
| 可读性     | 投屏可读，不用低对比文字，不用小字堆叠                                |
| 配色安全   | 正文必须高对比；禁止灰字叠加半透明浅底；禁止依赖 opacity 制造正文层级 |
| 完整显示   | 标题、正文、图注、行动项不得被裁切、遮挡或只显示一部分                |

详细检查项执行 [`references/ppt-master-rules.md`](references/ppt-master-rules.md)。

### Step 4 · 选择模板并生成

1. 根据“四种使用场景风格”选择唯一模板。
2. 读取目标模板，确认可用类名和布局结构。
3. 必须使用模板内的 PPT Master Guards：`.ppt-safe-frame`、`.ppt-balanced-frame`、`.ppt-action-frame`、`.ppt-focal`、`.surface-light`、`.surface-muted`、`.surface-ink`、`.surface-accent`、`.text-readable`、`.ppt-no-sink`。
4. 复制模板或基于模板生成目标 HTML；不得完全绕开模板重新写一套低对比 CSS。
5. 替换 `<title>`。
6. 保持单文件 HTML；除非用户提供素材，否则不要强行使用图片。
7. 主题色只从 references 预设选择，不随意自造颜色。
8. 如果新增局部 CSS，必须通过“配色安全与完整显示规则”：正文颜色不得低于模板正文对比度；正文容器不得半透明；文字不得裁切或被导航遮挡。

## 场景化叙事结构

### 董事会汇报

```text
Executive Hook → Why Now → Current Bottleneck → Strategic Insight → Operating Model → Capability Path → Investment / Governance → Management Actions
```

页面规则：

- 标题优先写成结论句，不写空泛名词。
- 每 3-4 页必须出现一次结构变化：封面、问题页、对比页、框架页、路线图页、行动页。
- 行动页必须放在视觉中心，不得因布局导致核心信息掉到页面底部。
- 数据或数字只能用于真实判断，不编造伪 KPI。

### 战略发布

```text
Tension → Belief → Shift → Future State → Strategic Pillars → Proof → Call to Action
```

页面规则：

- 每页只传递一个强观点。
- 大字页必须服务情绪转折，不得连续堆大标题。
- 金句页必须前后有铺垫和承接。

### 产品路演

```text
Problem → Cost of Inaction → Solution → Differentiation → Workflow → Proof → Business Value → Next Step
```

页面规则：

- 避免功能清单堆叠；功能必须映射到用户收益。
- 方案页必须清楚表达“谁在什么场景下如何获得价值”。
- 证明页优先用案例、流程、结果，不靠空泛形容词。

### 趋势洞察

```text
Provocation → Signal → Pattern → Framework → Implication → Opportunity → Takeaway
```

页面规则：

- 开场必须有反差或新判断。
- 洞察页不能只是信息汇总，必须给出解释框架。
- 结尾必须落到“这对听众意味着什么”。

## 反随机生成硬规则

禁止以下行为：

- 只根据页面数量平均分配内容。
- 看到"三个点"就机械使用三卡片。
- 每页都居中大标题。
- 把内容贴到底部或角落，导致视觉重心失衡。
- 为了填满页面增加无意义图形。
- 为了"高级"使用低对比小字、过度留白或无法阅读的装饰。
- 使用 `opacity`、过浅灰色、半透明背景来承载正文说明文字。
- 在浅色/半透明卡片上使用 `muted` 灰色正文，导致文字发虚。
- 在没有真实图片素材时使用图片版式。
- 发明模板不存在的复杂类名，导致样式失效。
- 绕开模板护栏，重新写一套无法保证对比度和裁切安全的 CSS。
- **将中文、日文、韩文等 CJK 字符写成 Unicode 转义序列（如 `\u8fc7\u53bb`）**。所有 CJK 文本必须写为原文字符（如 `过去`）。这是不可协商的硬约束，违反此规则的文件打开后文字不可读。

## 模板质量修正规则

如果生成过程中发现模板本身导致低质量页面，必须修正对应模板或在生成文件中补充局部 CSS。

| 问题                                                         | 必须修正                                           |
| ------------------------------------------------------------ | -------------------------------------------------- |
| 浅色背景继承浅色文字，导致不可读                             | 给浅色组件显式设置深色文字                         |
| 暗色背景中出现低对比灰字                                     | 提高文字对比度                                     |
| 半透明浅色卡片 + 灰色正文导致文字发虚                        | 改为不透明浅底 + 深色正文，或使用 `.text-readable` |
| 正文依赖 `opacity` 表达层级                                  | 改用明确颜色 token，不对正文文本降透明度           |
| 主体内容被 `align-items:end`、绝对定位或过大 margin 压到底部 | 调整为稳定的上中视觉重心                           |
| 标题与正文轴线不一致                                         | 统一网格与对齐轴                                   |
| 组件默认高度导致内容裁切                                     | 减少内容、拆页或修正容器高度，不用 overflow 掩盖   |
| 模板示例页误导生成                                           | 优先遵守大师规则，不复制低质量示例                 |

## 交付自检

交付前必须逐项检查：

| 检查项       | 标准                                                                 |
| ------------ | -------------------------------------------------------------------- |
| 占位符       | 不存在 `[必填]`、未替换标题、模板默认文案                            |
| 单一场景风格 | 整份 deck 只使用 1 个场景风格                                        |
| 页面角色     | 每页角色明确且不重复堆叠                                             |
| 视觉中心     | 每页第一视觉焦点清晰，无随机漂浮                                     |
| 信息层级     | 标题、主视觉、支撑信息层级分明                                       |
| 叙事节奏     | 有钩子、展开、转折、框架、行动或收束                                 |
| 可读性       | 无白底白字、暗底低对比、小字过密；正文禁止半透明容器 + 灰色文字      |
| 裁切         | `.frame` / `.canvas-card` / 主体容器无文字溢出，底部内容不被导航遮挡 |
| 导航安全区   | 内容不被分页点或底部控件遮挡                                         |
| 字符编码     | HTML 中所有中文/CJK 字符必须是原文字符，禁止出现 `\uXXXX` 转义序列   |
| 文件         | 输出可直接打开的单文件 HTML                                          |

## 错误处理

| 错误场景                       | 处理方式                                                                                                                             |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| 用户只给主题                   | 先补商业叙事蓝图，再生成 PPT                                                                                                         |
| 用户要求风格很多               | 收敛为 1 个使用场景风格，并说明选择理由                                                                                              |
| 内容太多                       | 按叙事角色拆页，绝不缩小字号硬塞                                                                                                     |
| 内容太少                       | 补足逻辑链，不编造数据                                                                                                               |
| 缺少素材                       | 使用排版、框架、对比、数字和留白，不强行找图                                                                                         |
| 模板不符合审美                 | 修改模板或局部 CSS，直到符合大师规则                                                                                                 |
| 用户指出页面低级               | 先诊断违反了哪条 PPT 规则，再修复，不只移动位置                                                                                      |
| 中文/CJK 显示为乱码或 `\uXXXX` | 这是生成时将中文写成了 Unicode 转义序列。必须重新生成整个 HTML 文件，确保所有 CJK 字符为原文字符。此错误不可接受，必须在技能层面杜绝 |
