# 五步工作流展开版与完整自检清单

主文件 `SKILL.md` 中的五步工作流的详细展开。执行复杂任务时按此逐项过一遍。

## Step 0 判定：这是不是控制问题

三条同时满足才算控制问题：

```
[ ] 有目标：能描述出"达标"是什么样子
[ ] 可观测：能量出"现在离目标还差多少"
[ ] 可施力：存在能改变系统状态的动作
```

**缺目标** → 这是探索问题。先做可能性空间的勘探，别急着执行。
**缺观测** → 先造测量工具。没有测量就动手，等于闭眼开车。
**缺施力** → 你在旁观，不是控制。要么争取施力点，要么承认只能预测。

## Step 1 定系统与边界（维纳层）

```
[ ] 系统边界：什么在系统内，什么是外部扰动
[ ] 输入量：我施加的（可控）vs 外部来的（扰动）
[ ] 输出量：我能观测到什么
[ ] 状态量：系统当前处于什么状态（最易漏）
[ ] 信息通道：信号从哪来、经过什么、到哪去
[ ] 信噪分离：哪些是真信号，哪些是噪声
[ ] 通道容量：给的信息是太少（丢失）还是太多（引入噪声）
[ ] 扰动清单：有哪些已知的干扰源
```

产出：一句话系统描述 + 输入/输出/扰动清单

## Step 2 展开可能性空间（金观涛层）

```
[ ] 列出对象所有现实的走向（含失败走向）
[ ] 我想要的结局，是否真的在可能性空间之内
[ ] 估算控制能力：控制前空间 ÷ 控制后空间
[ ] 选定控制方式（按效率从低到高选，不是默认用最高的）：
      随机控制 → 有记忆的控制 → 共轭控制 → 负反馈调节
[ ] 若用有记忆的控制：哪些选项是不可逆的？放在最后试
[ ] 若卡死：能找到什么中间变换（共轭控制）？
[ ] 黑箱判定：能不能打开？值不值得打开？打不开如何建模？
[ ] 容差：允许误差多大
```

产出：可能性空间描述 + 选定的控制方式 + 黑箱策略 + 容差

## Step 3 建模与设定目标差指标（钱学森层）

```
[ ] 因果链：输入 → [环节] → [环节] → 输出，画出来了
[ ] 每个环节的增益：这个动作会被放大还是衰减
[ ] 每个环节的代价：时间 / token / 金钱 / 风险
[ ] 目标差指标：如何量化"离目标还差多少"
[ ] 容差阈值：超出多少必须触发纠偏
[ ] 代价函数：哪个维度最贵，据此定优先级
[ ] 校验点：在哪些环节设检查，不通过不往下走
```

产出：模型（文字因果链即可）+ 目标差定义 + 容差阈值 + 校验点

## Step 4 建反馈回路并判稳（钱学森层）

```
[ ] 回路闭合：执行 → 测量 → 比对 → 调整 → 再执行
[ ] 反馈周期：多久测一次？周期是否接近或超过系统变化周期？
[ ] 增益设置：单次纠偏幅度是否过大（会振荡）
[ ] 时滞检查：测量和调整有多滞后
[ ] 噪声检查：会不会把随机波动当成偏差去纠
[ ] 稳定性判断：这个回路会收敛、振荡，还是发散
[ ] 若不稳定：降增益（减小幅度）/ 加阻尼 / 缩短周期，三选一或组合
[ ] 采样检查：检查频率是否足够，采样点是否有偏
```

产出：反馈回路描述 + 稳定性判断 + 增益设置

## Step 5 纠偏、收敛、加容错

```
[ ] 记录每轮目标差，确认是单调下降还是振荡
[ ] 若振荡：立即降增益，不要继续加大力度
[ ] 判断质变类型：中间过渡态是稳定的（渐变）还是不稳（飞跃）
[ ] 若在飞跃区：预期会有滞后与矫枉过正，这是正常的
[ ] 冗余：关键路径有备份吗
[ ] 自检：有定期诊断机制吗
[ ] 降级方案：做不到满分时，及格版本是什么样
[ ] 终止条件：什么情况算收敛？什么情况该放弃并上报
[ ] 自繁殖检查：有没有正在自动增长的失控链条，抑制机制是否还在
```

产出：收敛记录 + 容错措施 + 终止条件

## 不同任务类型的映射

| 任务类型 | 目标差指标 | 反馈周期 | 关键容错 |
|---|---|---|---|
| 写代码 | 测试通过率 / 报错数 | 每次改动后跑测试 | 版本回退、单元测试 |
| 调研 | 关键问题是否已有答案 | 每轮检索后评估覆盖率 | 多源交叉验证、标注不确定 |
| 写作 | 与意图的偏离度 | 每完成一节就比对提纲 | 保留草稿版本、分节锁定 |
| 优化 skill | 执行成功率、返工次数 | 每次实际调用后复盘 | 保留旧版、灰度切换 |
| 决策 | 各选项的不确定性区间 | 每获得一条新信息就重估 | 设止损线、保留退出通道 |
| 数据处理 | 异常值比例、校验和 | 每批处理完即校验 | 原始数据只读、中间态可重跑 |

## 完整自检清单（执行前扫一遍）

**定义层**
1. 目标清晰吗？能说出"达标"的判据吗？
2. 目标是"限定范围"还是"追求唯一"？后者可能过度控制
3. 列出可能性空间了吗？包括失败走向吗？
4. 想要的结果真的在可能性空间之内吗？

**观测层**
5. 偏差可测量吗？测不到就先解决观测
6. 测量本身有噪声吗？会不会把噪声当偏差？
7. 检查频率够吗？采样点有偏吗？

**回路层**
8. 反馈回路闭合了吗？还是单向投掷？
9. 反馈周期是否过长（时滞）？
10. 这个回路会收敛还是会振荡？
11. 纠偏力度是否过大？
12. 是在负反馈里，还是不小心进了正反馈？

**执行层**
13. 每一步是否都假设它会失败，并准备了退路？
14. 关键输出做了交叉验证吗？
15. 信息通道容量合适吗（不多不少）？
16. 有没有正在自动增长的失控链（自繁殖）？

**收尾层**
17. 什么时候该停？终止条件明确吗？
18. 收敛了吗，还是只是暂时不动了？
19. 这次的经验有没有沉淀成下次的初始参数？

## 失败模式与处置（详细版）

| 症状 | 诊断 | 处置 |
|---|---|---|
| 越改越糟 | 正反馈：纠偏动作在放大偏离 | 立即停手，画出反馈链，切断放大环节 |
| 反复横跳不收敛 | 增益过大导致振荡 | 降增益，单次改动幅度减半 |
| 改了看不到效果 | 时滞过长，或反馈通道断了 | 缩短周期，确认测量真的在发生 |
| 草木皆兵过度反应 | 把噪声当偏差 | 加滤波：连续多次同向才动 |
| 卡死动不了 | 目标在可能性空间外，或该用共轭控制 | 换控制方式，找中间变换 |
| 前期很猛后期崩盘 | 自繁殖：自动增长链 + 抑制失灵 | 建立负反馈抑制，设上限 |
| 改小毛病改出大故障 | 过度打开黑箱，破坏原有稳态 | 退回上一稳定态，改外部观测 |
| 每次用户反馈都全盘推翻 | 反馈过度 | 设变更阈值，小反馈不动主体 |
| 小规模有效，放大后失效 | 非线性：线性外推失效 | 规模变化时重新判稳 |
| 中间路线反而最难受 | 处在关节点区域，极端共存 | 放弃折中，明确选一端 |
| 推不动、总是弹回 | 遇到稳态结构，系统在自修复 | 要么改变条件使旧洼消失，要么绕开 |

## 收尾输出模板

```
【系统边界】<系统内 / 系统外扰动>
【目标与指标】<目标状态 / 目标差如何测量 / 容差>
【可能性空间】<有哪些现实走向，为什么选这一条>
【控制方式】<随机 / 有记忆 / 共轭 / 负反馈，及理由>
【反馈回路】<执行 → 测量 → 比对 → 调整，周期>
【稳定性】<会收敛吗，振荡风险，抑制措施>
【容错】<最可能失败处，退路，降级方案>
【收敛状态】<当前目标差，是否达标，下一步>
```

## 一页速查

```
定系统（维纳）   → 边界 / 输入 / 输出 / 扰动 / 通道 / 信噪
定问题（金观涛） → 可能性空间 / 控制能力 / 控制方式 / 黑箱
定执行（钱学森） → 建模 / 目标差 / 判稳 / 寻优 / 滤波 / 容错

三条铁律：
  1. 先定义目标差指标，再动手
  2. 先判稳，再寻优
  3. 每一轮都要测量，不允许无反馈执行

一个判断：
  偏差在缩小 → 继续
  偏差在振荡 → 降增益
  偏差在放大 → 停手，你在正反馈里
```
