# 截图权限与「立即开始」弹框处理（必读）

> 用途：任何**调用 `captureScreen()` / `images.captureScreen()` / `ocr(...)`** 的手机端脚本，
> 在真正截图**之前**都必须内置下面这段前置代码，否则截图会失败或脚本卡死。
> 这是 AutoJS 的硬性要求，不是可选项。**凡是新建/修改截图类模板，先确认这段代码在不在。**

## 一、为什么必须加

`requestScreenCapture()`（或 `images.requestScreenCapture()`）会触发系统的
「是否允许截取屏幕」弹框，弹框右下角有一个 **「立即开始」** 按钮。

- 这个弹框出现**极快**，且**阻塞截图权限的下发**；
- 如果**没人去点「立即开始」**，权限就不会授予，`captureScreen()` 会返回 `null`，
  OCR 会识别失败；更糟的是部分版本里 `requestScreenCapture()` 会**一直等弹框被处理**，
  导致脚本**卡住、无回执**（就是「OCR 回执为空」那种现象）；
- 在主线程里同步等弹框点击会卡死主流程，所以必须用**后台线程**去点。

## 二、必须粘贴的前置代码（完整，直接照抄）

> 放在 `try {` 之后、在第一次 `captureScreen()` / `ocr(...)` **之前**。
> 语法严格 ES5（`var` only，禁 `let/const/箭头函数`）。

```js
  // 申请截图权限 + 后台线程自动点「立即开始」（详见 references/截图权限与弹框处理.md）
  threads.start(function () {
    text("立即开始").clickable(true).findOne(3000).click();
  });
  if (!requestScreenCapture()) {
    toastLog("请求截图失败");
    result = { ok: 0, err: "请求截图权限失败" };
  } else {
    sleep(500);
    // ↓↓↓ 这里再写你原本的 captureScreen() / ocr(...) 逻辑
  }
```

## 三、逐行解释

1. **`threads.start(function () { text("立即开始").clickable(true).findOne(3000).click(); });`**
   - 单独开一条**后台线程**去点弹框。
   - `findOne(3000)` 表示最多等 3 秒找到「立即开始」这个可点击控件并点击。
   - 弹框出现极快，3 秒内足够点掉；因为跑在别的线程，**不会挡住主线程**后续代码。
2. **`requestScreenCapture()`**
   - 真正去申请截图权限，触发系统弹框。此时后台线程已经在等「立即开始」出现并点它。
   - 返回 `false` 表示申请失败（如权限被拒），直接报错退出，不再截图。
3. **`sleep(500)`**
   - 点完「立即开始」后，弹框**消失需要约 500ms**，等它彻底消失再截图，避免截到弹框本身或权限未就绪。

> 顺序很关键：**必须先 `threads.start(...)` 再 `requestScreenCapture()`**，
> 保证弹框一出现后台线程就能接住。调换顺序会点不到。

## 四、粘贴位置（放在哪）

- 在「任何会触发截图的脚本」里，`captureScreen()` / `ocr(...)` 调用**之前**。
- 典型模板：`screenshot.js`、`crop_screenshot.js`、`ocr.js`。
- 现场一次性脚本（写在 `temp/`）只要用到截图，同样要加。

## 六、新建模板自查（照抄即可，别漏）

新建任何会截图的模板时，默认在 `try` 开头加第二节那段代码，
再在其 `else` 分支里写你的截图/识别逻辑。缺这段的截图模板**一律不可用**。

## 红线 / 注意

- 只在**手机端脚本**里用（PC 侧 Node 没有 `requestScreenCapture` / `threads`）。
- 严格 ES5：`var` / `function`，不要 `let`/`const`/箭头函数（AutoJs6 Rhino 引擎）。
- 不要为这段代码加 `setInterval` 保活；经 `/run` 下发的脚本由中继托管，正常 `exit` 即可。
- 点了「立即开始」后务必 `sleep(500)` 再截图。
