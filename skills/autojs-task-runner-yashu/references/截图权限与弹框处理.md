# 截图权限与授权弹框处理（必读）

> 用途：任何**调用 `captureScreen()` / `images.captureScreen()` / `ocr(...)`** 的手机端脚本，
> 在真正截图**之前**都必须内置下面这段前置代码，否则截图会失败或脚本卡死。
> 这是 AutoJS 的硬性要求，不是可选项。**凡是新建/修改截图类模板，先确认这段代码在不在。**

## 一、为什么必须加，且文案必须多候选

`requestScreenCapture()`（或 `images.requestScreenCapture()`）会触发系统的
「是否允许截取屏幕」授权弹框。

- **授权按钮的文案因厂商 ROM / 系统版本而异**：小米 MIUI 是「立即开始」，
  部分机型是「开始截图」「开始使用」等，英文 ROM 是「START NOW」——
  **硬编码单一文案（如 `text("立即开始")`）在别人手机上会点不到按钮**，导致无法自动授权；
- 这个弹框出现**极快**，且**阻塞截图权限的下发**；
- 如果没人去点授权按钮，权限就不会授予，`captureScreen()` 会返回 `null`，
  OCR 会识别失败；更糟的是部分版本里 `requestScreenCapture()` 会**一直等弹框被处理**，
  导致脚本**卡住、无回执**（就是「OCR 回执为空」那种现象）；
- 在主线程里同步等弹框点击会卡死主流程，所以必须用**后台线程**去点。

## 二、必须粘贴的前置代码（完整，直接照抄）

> 放在 `try {` 之后、在第一次 `captureScreen()` / `ocr(...)` **之前**。
> `?.` 可选链与 `textMatch` 为**用户实测确认可用**的语法（ES6 有条件放开政策见
> `AI_AutoJS编码强制规范.md` §1.0）。

```js
// 申请截图权限：授权按钮文案因 ROM 而异（小米「立即开始」、部分机型「开始截图」等），
// textMatch 正则一次覆盖多候选（用户实测语法可用）；未命中则静候用户手动点。
// 详见 references/截图权限与弹框处理.md
threads.start(function () {
  textMatch(/立即开始|开始截图|开始使用|立即启用|START NOW/)
    .clickable(true)
    .findOne(3000)
    ?.click();
});
if (!requestScreenCapture()) {
  toastLog("请求截图失败");
  result = { ok: 0, err: "请求截图权限失败" };
  exit();
} else {
  sleep(500);
  // ↓↓↓ 这里再写你原本的 captureScreen() / ocr(...) 逻辑
}
```

## 三、逐行解释

1. **`textMatch(/立即开始|开始截图|开始使用|立即启用|START NOW/)`**
   - `textMatch` 是现行 API（旧的 `textMatches` 已弃用），参数支持字符串或 RegExp 字面量；
   - 正则一次覆盖各 ROM 的已知文案，比逐个 `text(...)` 轮询快且省；
   - 遇到清单外的新文案？**直接往正则里加一个词即可**，越长只影响检索速度，不影响正确性。
2. **`.clickable(true).findOne(3000)?.click()`**
   - 最多等 3 秒找到这个可点击控件并点击；`?.` 保证找不到（权限已授予、无弹框）时安全跳过；
   - 因为跑在后台线程，**不会挡住主线程**后续代码。
3. **`requestScreenCapture()`**
   - 真正去申请截图权限，触发系统弹框。后台线程已在等按钮出现并点它；
   - 返回 `false` 表示申请失败（如权限被拒），按各模板自己的失败分支回执退出；
   - **自动点击只是加速手段，成败以本函数返回值为准**——未命中文案时弹框仍停在屏幕上，
     用户手动点一下同样生效（授权在 App 存活期内持久，人工仅需每台设备一次）。
4. **`sleep(500)`**
   - 点完授权按钮后，弹框**消失需要约 500ms**，等它彻底消失再截图，避免截到弹框本身或权限未就绪。

> 顺序很关键：**必须先 `threads.start(...)` 再 `requestScreenCapture()`**，
> 保证弹框一出现后台线程就能接住。调换顺序会点不到。

## 四、粘贴位置（放在哪）

- 在「任何会触发截图的脚本」里，`captureScreen()` / `ocr(...)` 调用**之前**。
- 典型模板：`screenshot.js`、`crop-screenshot.js`、`ocr.js`、`tap-text.js`（第 3 级 OCR 降级时）、
  `unfollow-official-accounts.js`。
- 现场一次性脚本（写在 `temp/`）只要用到截图，同样要加。

## 六、新建模板自查（照抄即可，别漏）

新建任何会截图的模板时，默认在 `try` 开头加第二节那段代码，
再在其失败分支里写你的失败回执、`else` 分支里写截图/识别逻辑。缺这段的截图模板**一律不可用**。

## 红线 / 注意

- 只在**手机端脚本**里用（PC 侧 Node 没有 `requestScreenCapture` / `threads`）。
- 语法默认 ES5（`var`/`function`）；本片段中 `?.` 与 `textMatch` 是**用户实测确认**的例外
  （ES6 有条件放开政策见 `AI_AutoJS编码强制规范.md` §1.0）。
- 不要为这段代码加 `setInterval` 保活；经 `/run` 下发的脚本由中继托管，正常 `exit` 即可。
- 点了授权按钮后务必 `sleep(500)` 再截图。
