# delete-folder · 删除指定的文件夹（递归）

## ⚠️ 二次确认（强制，不可逆）—— AI 绝不直删

本模板是**不可逆删除**。无论用户语气多肯定，AI 都**绝对不能直接调用本模板去删除任何文件夹**。执行前必须严格走下面三步：

1. **复述路径**：把将要删除的**完整绝对路径**明确地念/写给用户看（例如：「你确定要删除 `/sdcard/脚本/old_demo` 这个文件夹吗？里面的内容会全部消失、无法恢复。」）。
2. **等待确认**：必须收到用户**明确同意**（如「确定」「删」「yes」等）后才能继续；模糊、沉默、未回复都不算确认。
3. **再下发**：确认到位后，才执行 `node run-task.js delete-folder --args '{"path":"<完整路径>"}'`。

任何情况下都不得：
- 用户只说「清理一下」「把那个目录删了」却未给明确路径 + 明确确认时，自行推断路径并删除；
- 把删除和其他步骤合并、跳过确认一次性连跑；
- 以「用户大概想删」「上一轮提过」作为跳过确认、直接执行的理由。

> 这是硬红线，高于一切效率考量。脚本内置的 /sdcard 安全护栏只防系统目录，防不了「用户临时反悔」——**二次确认才是真正兜底**。

## 使用场景
- 清理手机上不再需要的文件夹（工程目录、缓存目录、临时目录等）。
- 用户明确给出要删的文件夹绝对路径（必须在 /sdcard 下）。

## 什么时候不该用
- 删的是"已部署的工程" → 也可用 `delete_project`（PC 脚本，默认删 /sdcard/脚本/<工程名>，支持 `--path` 指定任意 /sdcard 路径）；本模板是更通用的"按任意 /sdcard 路径删除文件夹"。
- 只想删单个文件 → 本模板只处理文件夹（文件请用 files.remove，本模板会拒绝并提示）。
- 想删系统目录 / 应用私有数据 → 被安全护栏拒绝，不提供此能力。

## 参数细节与坑
- `path`（必填）：要删除的文件夹绝对路径；必须位于 sdcard 存储内。传入路径会先做规范化（`java.io.File.getCanonicalPath()` 解析符号链接别名与 `..`），再与 `files.getSdcardPath()` 动态根比较——别名形式与物理形式的输入都被接受，代码中不写死任何路径字符串。
- 安全护栏（硬规则，脚本内置，双重保险）：
  - 只允许 sdcard 存储内路径，拒绝 `/system`、`/data`、`/`、sdcard 根（别名或物理形式）等一切系统/根路径；
  - 目标不存在 → 幂等返回 `{ok:1, deleted:false, note:"目标不存在, 无需删除"}`，不报错；
  - 目标是文件（非文件夹）→ 拒绝，本模板只删文件夹。
- 返回字段：
  - `deleted`：是否执行了删除（存在才删，不存在为 false）；
  - `success`：files.removeDir 的返回值，是否全部内容删除成功（boolean）；
  - `path`：实际处理的路径；
  - `note`：幂等/说明信息。

## 错误处理与兜底
- 缺参数：`{ok:0, err:"缺少参数 path（必须是字符串，要删除的文件夹绝对路径）"}`。
- 越权路径：`{ok:0, err:"仅允许删除 /sdcard 下路径，已拒绝: <path>"}`。
- 删根：`{ok:0, err:"拒绝删除根目录: <path>"}`。
- 是文件：`{ok:0, err:"指定路径不是文件夹（是文件）: <path>；本模板只删文件夹"}`。
- 成功：`{ok:1, deleted:true, path, success:true}`。

## 示例调用
```bash
# 删除指定文件夹（⚠️ 需先与用户确认完整路径！）
node run-task.js delete-folder --args '{"path":"/sdcard/脚本/old_demo"}'
```

## 红线提醒
- ⚠️ **不可逆删除 · 绝不直删**：删除后无法恢复。AI **绝不**自行决定删除——必须先把**完整路径**念给用户、拿到其**明确二次确认**后，才能下发执行。这是硬红线，高于一切效率考量。
- **确认三步缺一不可**：① 复述完整路径并说明后果 → ② 等用户明确同意 → ③ 再调用。模糊 / 沉默 / 未回复都不算确认。
- 仅限 /sdcard 存储内，不碰系统目录，无越权风险；脚本内 /sdcard 护栏只防系统目录，**二次确认才是防「误删 / 反悔」的真正兜底**。
