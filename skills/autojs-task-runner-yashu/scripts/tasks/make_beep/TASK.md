# make_beep · 凭空生成蜂鸣/滴声提醒音

## 这个声音是怎么「凭空」造出来的

手机里没有任何音频文件也没关系。脚本不下载、不读取任何素材，而是**在手机端用 JS 现算音频波形**：

1. 取采样率 8000Hz、单声道、16-bit PCM（最简单、兼容性最好）。
2. 按 `sample = sin(2π·freq·i/sr) × 0.8 × 32767` 逐点算出正弦波振幅（×0.8 留余量防削顶）。
3. 手工拼出标准 **WAV 文件头**（RIFF/WAVE/fmt/data 区块，小端字节序，共 44 字节）+ 波形数据字节。
4. 用 `files.writeBytes()` 一次性写盘，得到一段合法 WAV —— 即电脑蜂鸣器那种「滴」声。
   本质和电脑主板蜂鸣器一样：都是程序直接合成单频音，而非播放现成录音。

> 类比：电脑 `echo ^G` / 蜂鸣器靠硬件发声；这里靠软件合成等价单频音写进 WAV，再交给系统播放器播，效果同「滴」。

## 使用场景
- 任务到点 / 步骤完成想「响一下」提醒老板（替代震动，更醒目）。
- 手机没有任何音频素材，又需要出声（闹钟、到点提示、流程结束信号）。
- 当其他任务模板的「收尾提示音」：跑完关键步骤后接一条 `make_beep`。

## 什么时候不该用
- 想要**音乐 / 人声 / 复杂提示音**：本模板只能合成单频「滴」声，先 `send_file_to_phone` 把真实音频传上手机再 `media.playMusic` 播放。
- 只想**静默振动**：用 `device.vibrate(ms)` 即可，不必发声。

## 参数细节与坑
- `freq` 选填，频率 Hz，默认 1000（电脑滴声常用 1k）。想更尖锐给 1500，更低沉给 600。
- `dur` 选填，时长(秒)，默认 0.3。做「滴—」就 0.3；要「滴滴」两声请在调用侧连发两次或自行拼双音。
- `path` 选填，落盘路径，默认 `/sdcard/Download/beep.wav`。
- **必坑（重要）**：`media.playMusic()` 是**非阻塞**命令——它只「发起播放」就立刻返回，脚本若此时结束，播放器还没来得及出声就被杀掉，结果**完全没声音**。
  因此脚本必须：`media.playMusic(path)` → `media.getMusicDuration()` 取时长 → `sleep(时长)`，等声音真正播完才让脚本退出。本模板已内置这三步。

## 错误处理与兜底
- `getMusicDuration()` 偶发在播放器 ready 前返回 0，脚本已加「sleep(50) + 重试 10 次」兜底；仍拿不到则退回理论时长 `dur*1000` ms，保证至少等够时间。
- `files.writeBytes` 失败（如路径无写权限）会进 `catch` 回 `{ok:0, err:"..."}`。

## 示例调用
```bash
# 默认：1000Hz、0.3 秒，落到 /sdcard/Download/beep.wav 并播放
node run_task.js make_beep
# 自定义：1500Hz、0.5 秒
node run_task.js make_beep --args '{"freq":1500,"dur":0.5}'
```

## 红线提醒
- 仅合成单频提示音，**不**读取/上传用户任何音频隐私；
- 音量跟随系统媒体音量，调用前可用 `device.getMusicVolume()` 核对是否静音。
