# tap_point · 点按屏幕坐标

## 使用场景
- 目标控件没有稳定文字或 resource-id，只能通过坐标点按（如游戏按钮、画布区域、自定义 View）。
- 多步任务里前一步 `inspect_control_by_coord` 拿到坐标后，用坐标兜底点按。

## 什么时候不该用
- 能拿到文字/ID 时优先用 `tap_text` / 稳定选择器——坐标随屏幕分辨率、字号、刘海/导航栏变化会漂移，脆弱。
- 系统导航类（返回/桌面）用 `key`，别用坐标模拟。

## 参数细节与坑
- `x`、`y` 必须是数字（像素，屏幕坐标系，原点左上）。
- 缺参或类型不对直接返回 `{ok:0, err:"缺少参数 x 或 y（必须是数字）"}`，不会静默用 0 瞎点。

## 错误处理与兜底
- 成功 `{ok:1}`；坐标越界通常也不报错（系统 click 静默忽略），所以"点了但没反应"时要靠后续步骤截图核验。

## 示例调用
```bash
node run_task.js --path tasks/tap_point/tap_point.js --args '{"x":767,"y":1517}'
```

## 红线提醒
- 坐标点按不稳定，复杂任务里尽量先用 `inspect_control_by_coord` 把坐标换成稳定选择器，再点。
