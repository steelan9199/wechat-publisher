# unfollow_official_accounts_fast · 批量取关微信公众号（长按直取关版）

> 本模板是 `unfollow_official_accounts` 的**提速版**：旧版要进公众号详情页再点两下按钮，步骤多、慢；
> 本版直接从「通讯录 → 公众号」列表页**长按列表项**弹菜单，少跳一级页面，速度快很多。
> 所有「坑」与判定逻辑都来自 2026-08-19 的实测与旧版经验，**出问题先读「已知风险 & 修补点」**。

## 使用场景
- 微信关注公众号数量到达上限，需把已关注的公众号逐个取关清空。
- 起点：用户手动把手机停在 **「通讯录 → 公众号」列表页**（顶部有「公众号」标题，右侧有 A–Z 索引字母）。
- 该列表页**禁止 AutoJS 无障碍分析** → 列表相关操作全部用 `ocr.detect` 拿坐标 + `click/press`。
- 唯一能用无障碍分析到的，是**长按后弹出的「不再关注」小弹框**（它是一个 textView），用 `textContains("不再关注")` 找到并点击。
- 确认取关的「确认框」（含「仍然关注」「不再关注」）**无障碍分析不到** → 用 OCR 按坐标定位右下角「不再关注」按钮再点。**注意**：确认框标题也含「不再关注」（如「将不再关注该公众号？」）且在屏幕顶部，定位时**必须排除顶部标题、只取底部按钮**（见阶段三 / 已知风险 4）。

## 操作流程（脚本逐轮做的事）

> **核心原则**：每次 `press` / `click` 之后，等合适时长 → 截屏 OCR / 无障碍复核「是否在期望页面」，符合才继续，否则停下用人话提示。
> 全程打印三要素日志：**① 当前在哪个页面/准备做什么 → ② 操作完处于哪个页面 → ③ 该页面是否通过审核**。

**页面状态机**：`LIST`(公众号列表页，顶部含「公众号」) → `POPUP`(长按菜单弹框，含「不再关注」，无障碍可分析) → `CONFIRM`(确认取关弹框，含「仍然关注」/「不再关注」，OCR 分析) → 回到 `LIST`。

1. 启动：申请截图权限（后台线程自动点「立即开始」弹框），`sleep(800)`；**只此一次**。
2. **初始审核**：确认手机一开始就停在 `LIST`（顶部含「公众号」）；不在则直接中止，提示先手动进入「通讯录 → 公众号」列表页。
3. 进入循环（上限 `maxLoop`，默认 200），每轮 4 个阶段：
   - **阶段一（LIST→POPUP）**：`sleep(300)` 等列表稳定 → 截屏 OCR → 找「公众号」标题下边缘 → 其下方最靠上、非杂字、2~20 字的第一个公众号 → 取坐标 → `press(cx,cy,1000)` 长按 1 秒 → `sleep(400)`。期望 `POPUP`（无障碍检测到「不再关注」）；否则中止报 `长按后未弹出'不再关注'菜单…`。
   - **阶段二（POPUP→CONFIRM）**：无障碍 `u.click()` 点菜单里的「不再关注」→ `sleep(700)` → 多次重查 OCR（最多 4 次，防漏识）确认含「仍然关注」或「不再关注」。期望 `CONFIRM`；否则中止报 `点击菜单'不再关注'后未出现确认弹框…`。
   - **阶段三（CONFIRM→LIST）**：用 `findUnfollowButton(det,img)` 按坐标定位确认框右下角「不再关注」按钮（先以「仍然关注」左按钮为锚、找同排右侧按钮；兜底取下半屏最靠右者；两者都排除顶部标题）→ `clickCenter` 点击 → `sleep(3000)`（确认框消失、列表刷新）→ 多次重查（最多 4 次）：须**同时满足**「回到 `LIST`（顶部含『公众号』）」**且**「确认框已关闭（『仍然关注』『不再关注』文字均不再出现）」才算成功（双校验，防止『点到标题→框没关→背景列表可见→误判回列表』的死循环）。期望 `LIST`；否则中止报 `确认取关后未回到公众号列表页（或确认框未关闭…）`。
   - 一轮完成：`done+1`。回到第 3 步继续下一轮（每轮都重新截图选「第一个」号）。
4. 终止条件：
   - 列表已空（挑不到第一个公众号）→ `{ok:1, msg:"列表已空，取关完成"}`；
   - 初始不在列表页 → `{ok:0, err:"脚本开始时不在公众号列表页…"}` 中止；
   - 任一阶段页面审核未过 → `{ok:0, err:...}` 中止；
   - 跑满 `maxLoop` → `{ok:0, err:"已达循环上限..."}`。

## 为什么「每轮只点第一个」
本列表（通讯录 → 公众号）**取消关注后，下方的公众号不会上移重排**（与微信消息列表取关行为不同）。因此每轮的「第一个」恒为某个仍关注的号，脚本每轮重新截图挑最靠上的那个即可，无需处理项上移。

## 参数细节与坑
- `maxLoop` 选填：默认 200，防死循环；要清很多号可调大（如 500）。
- **坐标即 `ocr.detect` 返回的 `bounds` 中心**，与 `click(x,y)`/`press(x,y)` 同坐标系（设备像素），无需换算。
- **长按用 `press(cx, cy, 1000)`**（按住 1000ms 触发长按菜单）；不要用 `gestures` 或 `longClick`（实测 `press` 最稳）。
- 选取「第一个公众号」以「公众号」标题下边缘为锚点：OCR 偶发把「最近更新」「最近关注」合并成一项、把右侧 A–Z 索引字母识别出来，都会被 `isChrome()` 黑名单过滤，且强制在标题下方，分辨率无关。
- **`isChrome()` 只排除「标题 + 单字母索引」**：页面规则（实测）＝通知栏下方只有「公众号」标题，其下方、且非单个 A–Z/# 字母的项必定是公众号。所以 `isChrome` 只过滤标题本身（`公众号`/`订阅号`/`订阅号消息`）与右侧 A–Z/# 单字母索引，**绝不用子串过滤**，避免「按键精灵公众号」这类名字被误杀而永远留着。

## 错误处理与兜底
- 长按后无障碍**未检测到「不再关注」菜单** → 立即停，回报 `长按后未弹出'不再关注'菜单…`（可能没真按到列表项中心，或微信未弹菜单）。
- 点菜单「不再关注」后 OCR **找不到「仍然关注」/「不再关注」确认框** → 立即停，回报 `点击菜单'不再关注'后未出现确认弹框…`。
- 确认框内 OCR **定位不到「不再关注」按钮坐标**（标题干扰 + 漏识）→ 立即停，回报 `确认弹框已出现，但定位不到'不再关注'按钮坐标（可能 OCR 漏识）…`。
- 确认取关后**未回到列表页** → 立即停，回报 `确认取关后未回到公众号列表页…`。
- 列表为空（挑不到第一个公众号）→ 视为成功，回报 `列表已空，取关完成`（不是异常）。
- **异常/未正常完成停止时**：`onExit` 会播放 10 次 beep（每次间隔 2 秒，约 23 秒）提醒你，正常取关完成（ok:1）不响。需 `/sdcard/Download/beep.wav` 事先存在。

## 已知风险 & 修补点（出问题照这里改）
1. **「公众号」标题锚点识别不到 / 账号名含「公众号」被误杀**：`isChrome()` 已把「公众号」「订阅号」「订阅号消息」限制为**完整标题**匹配，避免真实账号名（如「按键精灵公众号」「XX订阅号」）被当杂字过滤。若某机型/改版后列表页顶部标题不是精确这三字之一（如出现空格/变形），标题可能漏过滤，但 `titleBottom` 仍靠 `topHasOfficial` 的 indexOf 定位，不影响选号；若发现标题被当成账号误点，可把 `isChrome` 里改成 `t.replace(/\s+/g,"") === "公众号"` 等更宽匹配。
2. **页面布局不符（无「公众号」标题 / 出现搜索框等）**：当前页面规则假设通知栏下方只有「公众号」标题、无其他 UI 条目，故 `isChrome` 不做子串过滤。若改版后出现搜索框、分类标签等，它们会出现在标题下方且非单字母 → 会被当成账号误点。→ 按实际页面再加 `isChrome` 精确匹配项（如 `搜索`、`游戏` 等完整词），不要再用子串。
3. **OCR 把右侧 A–Z / # 索引字母误当成账号**：`isChrome()` 已用正则 `/^[A-Za-z#]$/` 过滤单字母；若 OCR 把某个字母识别成多字符（如「AB」），会漏过滤而误点。→ 在 `isChrome` 追加更宽的正则（如 `/^[A-Za-z#]{1,3}$/`）。
4. **长按没弹出菜单（POPUP 未检测到）**：可能是落点偏了或长按时长不够。→ 确认 `press(cx,cy,1000)` 落点在账号**名字矩形内**；可把 1000ms 调到 1200ms；坐标来自 `bounds` 中心，一般没问题。
5. **确认框「不再关注」按钮定位（标题干扰陷阱，已修复）**：确认框标题也含「不再关注」（如「将不再关注该公众号？」）且在顶部，若直接取第一个匹配会点到**标题**而非按钮 → 框关不掉、背景列表仍可见 → 旧版误判回列表并**无限空转**。`findUnfollowButton` 已用「锚定『仍然关注』左按钮找同排右按钮 + 下半屏最靠右兜底」排除标题；点后还用「确认框已关闭（两按钮文字均消失）」双校验兜底。若某机型 OCR 把「仍然关注」识别成别的字导致锚点法失效，可放宽 `findText(det,"仍然关注")` 匹配串，或调大下半屏阈值 `h*0.5`。
6. **`detectPage`/页面判定顺序敏感**：本版用 `titleBottom` 锚定 + `hasText(det,"仍然关注"|"不再关注")` 判 CONFIRM，逻辑简单清晰；阶段三按钮定位靠 `findUnfollowButton`（内部 `findText(det,"仍然关注")` 做左按钮锚点 + `findText` 收集「不再关注」项）。若微信把确认按钮文字从「不再关注」改成「确认」、或左按钮从「仍然关注」改成别的字，改对应 `findText` 匹配串即可。
7. **坐标偏移（刘海/全面屏/缩放）**：`click/press` 用设备像素；若手机改了显示缩放或换设备分辨率，包围盒中心可能偏。→ 重新空跑一轮校准，必要时做比例换算。
8. **`beep.wav` 不存在**：异常时 `media.playMusic` 抛错，但已被 `try/catch` 吞掉，不影响结果回传、只是没声音。→ 把 `beep.wav` 放到手机 `/sdcard/Download/` 即可。
9. **OCR 漏识生僻字账号（如「彪彪在努力」）导致被永久跳过**：实测该 OCR 引擎对「彪」字**完全不认**（整屏 40 个识别项里连近似项都没有），且**多次截图亦无效（已验证）**。于是 `pickFirstAccount` 选中的是它下方账号、该账号永远轮不到 → 表现为"跳过某账号只取关下方"。当前保留**单次截图**（与全脚本一致）。若要真正取关这类账号，须换更强 OCR（PaddleOCR / 微信 UI 控件）或改"基于固定坐标点第一个头像"的方案，否则该账号会一直被遗留。

## 红线提醒
- 本操作**不可逆**（取关后需重新搜索关注）。脚本仅在用户手动停在列表页后、由用户主动触发运行；符合「删除类不可逆操作前先确认」原则（用户已明确授权清空）。
- 只动「通讯录 → 公众号」列表，不碰支付/转账等。
- 与旧版 `unfollow_official_accounts` 的区别：旧版从「微信消息页 → 公众号」进详情页取关（步骤多、慢，且详情页按钮也需 OCR）；本版从「通讯录 → 公众号」列表页**长按直取关**，更快。两个脚本都保留，互不替换。
