# 功能完整性分析指南

对 check.js 解析出的每个功能，读取目标 SKILL.md 正文中该功能对应的描述段落，进行以下静态分析。

## 分析维度

### a) 触发条件清晰度

- 功能描述是否使用了明确的触发句式（如"当用户说 X 时"、"当用户需要 X 时"）
- 触发条件是否足够具体，能从用户输入中可靠识别
- 是否存在与其他功能触发条件重叠/歧义的情况

### b) 执行步骤完整性

- 功能是否有明确的执行步骤描述（非仅有一个功能名）
- 步骤中是否引用了不存在的工具、脚本或文件
- 步骤逻辑是否完整（从触发到产出结果，是否有断链）

### c) 引用资源存在性

- 若功能引用了 `scripts/` 下的脚本，检查该脚本文件是否存在
- 若功能引用了 `references/` 下的参考文件，检查该文件是否存在
- 若功能声明依赖特定工具（如 Python、特定 Node 包），检查 `scripts/` 目录下 `package.json` 或 `requirements.txt` 是否声明了对应依赖，以及 `node_modules` 是否存在

### d) 脚本可执行性（仅当功能涉及 scripts/ 且该目录有 package.json）

- 检查 `scripts/package.json` 中是否声明了 `scripts.test` 命令
- 若有 `test` 命令，在 `$TARGET_DIR/scripts` 目录下执行 `npm test`（如果 `node_modules` 已安装）或先执行 `npm install` 再执行 `npm test`
- 脚本测试结果纳入该功能的分析结论

## 判定标准

| 结果 | 条件                                                                             |
| ---- | -------------------------------------------------------------------------------- |
| 通过 | 触发条件清晰 + 执行步骤完整 + 所有引用资源存在 + （如涉及脚本）脚本测试通过      |
| 警告 | 存在非致命问题，如触发条件略微模糊、可选引用资源缺失、脚本测试未覆盖             |
| 失败 | 触发条件缺失或严重模糊、执行步骤断链、引用的必需资源不存在、脚本测试失败         |

## 重要规则

- 每个功能独立分析，一个功能的失败不影响其他功能
- 只分析 SKILL.md 中声明的内容，不对未声明的潜在功能做假设
- 分析过程中不修改目标 skill 的任何文件
- 若目标 skill 的 `scripts/` 需要 `npm install` 才能运行测试，执行安装，但必须在报告中注明
