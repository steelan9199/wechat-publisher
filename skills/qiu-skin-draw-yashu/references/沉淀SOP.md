# 沉淀SOP

> **何时读我**：用户说出触发词（沉淀/存为脚本）时。平时不读。

**用户一说「沉淀」或「存为脚本」，立刻走本节 SOP，把刚才画好的作品固化成可复现脚本。不要等第二次确认，也不要反问要不要做。**

## 触发词（双通道，任选其一即触发）

| 用户说 | 触发 |
|---|---|
| 沉淀一下 / 沉淀这只老虎 / 把这张画沉淀 / 沉淀它 | ✅ |
| 存为脚本 / 存成脚本 / 存一个脚本 | ✅ |
| 闲聊中提到"沉淀经验""沉淀总结"（非画作对象） | ❌ 不触发 |

判断标准：**宾语是当前已经画在画板上的那幅画**。省略宾语（"沉淀一下"）默认指最近一次完成的作品。

## ⛔ 铁律：脚本只执行，绝不读进上下文（2026-09-18 用户指定）

生成出来的 `draw_<题材>.js` 通常 20KB+，其中一半以上是坐标数字。**把它 Read 进上下文是纯粹的 token 浪费，收益为零。**

- ✅ **正确**：读薄文档 → 拼命令 → `run-task.js` 下发执行 → 只读回执 JSON
- ❌ **禁止**：`Read` / `cat` / `grep -C` 查看已生成脚本的内容
- ❌ **禁止**：为了"看看它怎么写的"而打开脚本——那是给人看的记录，不是给 AI 的输入
- 唯一例外：**改造型**时走生成器/Patch 路线，同样不整篇读；如确须精确改某一处才用 `Read` 的 `offset/limit` 定点读取

> 推论（反推薄文档该写什么）：薄文档必须**自足到"不读脚本也能正确调用"**。凡是调用前需要知道的东西，一律写进薄文档；凡是只有改代码才需要的细节，一律留给脚本。

## 沉淀 SOP（轻量版 + 薄文档，约 1~2 分钟）

1. **先清板重画一次**（用户指定，不可省）：用即将沉淀的那套数据，从空白画板完整重画一遍——`stage 0`（含清空+铺底色）→ 逐 stage 到结束。目的：证明脚本能**从零复现**。重画完成才往下走；若重画结果与原稿明显不符，先修 dataset 再重来。
2. **生成自包含脚本** `scripts/draw_<题材>.js`：
   - **零硬编码坐标**：运行时只查 `qiu-calib` / `qiu-board` / `qiu-brush-width` 三个 `storages`，缺标定就报错给补测指引，绝不猜值；
   - 造型数据存**归一化坐标** `(u,v)=((x-cx)/r,(y-cy)/r)`，运行时 `x=cx+u*r, y=cy+v*r`；
   - 清空沿用 `clearRounds` 默认 2 的幂等写法（**最危险坑**：清空动作必须幂等，见 `references/踩坑记录.md`）；
   - 支持 `palette` 改色、`stage`/`from`/`to`、`dryRun`、`maxMs`；
   - **直接照抄 `scripts/draw_tiger.js` 的结构**（含头部注释范式与 `events.broadcast.emit("autojs_result")` 回执），只换数据段与 `KEY` 名字表。**抄结构是允许的"读"，日常工作调用则是禁止的读。**
3. **写薄文档** `references/<题材>.md`——**控制在 30 行以内**（见下方清单）。
4. **归档数据与生成链**到 `scripts/_src/<题材>/`：原始绝对坐标 JSON、生成器 `.py`、脚本主体模板、还原精度校验脚本。生成器与校验脚本必须用 `__file__` 相对路径，**不许依赖 temp 目录**。
5. **自动存预览图**：成品图存 `outputs/<题材>.png`，并在回执文案里给出路径。
6. **收尾验证**（到此为止）：`check-autojs-syntax.cjs` 语法门禁 + `run-task.js --args '{"dryRun":true}'` 一次，确认 `missing` 为空、`paths` 数与原稿一致。**只看回执 JSON，不读脚本。**

## 薄文档固定 8 项（≤30 行，多了就是写长了）

```
1 一句定位    画的是什么、几 stage / 几笔
2 文件路径    脚本 / _src / 预览图 三条路径
3 执行命令    可直接复制的 run-task.js 命令行（含逐 stage 与全跑两种）
4 参数表      palette slot、stage 编号含义、dryRun/from/to/maxMs
5 默认配色    slot → 色 key
6 回执字段    ok 取值含义、nextStage、missing/errors 怎么读
7 题材专属坑  本次踩到的、脚本里没写清的原因
8 无效方案    当时试过但不行的替代画法（防止以后重蹈）
```

> 前 3 项是给 AI 的**接口卡**：读完就能正确执行，完全不需要打开脚本。后 5 项是给未来的上下文。

## 轻量版刻意不做的事

- ❌ 不做真机双次复现验证（脚本生成后只跑一次重画 + dryRun）
- ❌ 不在 SKILL.md 里登记该作品、不建作品库总表
- ❌ 不写超过 30 行的长文（`references/TIGER.md` 是早期完整版范例，**新题材不走那套**；它顶部已加接口卡，AI 读接口卡即可）
