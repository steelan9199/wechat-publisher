# 基线评测

## 什么时候读我

当需要在改造前建立测试任务、衡量触发质量、任务成功率、关键错误或上下文负担时，读本文件。

## 1. 评测集组成

至少覆盖以下类别：

1. **明显触发用例**：用户明确提出目标 Skill 应处理的任务。
2. **改写触发用例**：使用同义词、口语化表达、省略关键词或描述目标而非动作。
3. **非触发用例**：相似但不应触发该 Skill 的请求。
4. **典型任务用例**：从接收到交付的完整任务。
5. **历史事故回放**：过去真实踩坑、投诉、返工或失败案例。
6. **边界与失败注入**：缺失输入、无效链接、权限不足、依赖失败、空文件、格式错误。
7. **代码/脚本用例**：关键函数、命令、路径、输入输出和异常处理。
8. **组合冲突用例**：多个 Skill、规则或工具同时可能适用。

## 2. 核心指标

| 指标 | 口径 |
|---|---|
| 触发召回率 | 应触发的用例中，实际正确触发的比例 |
| 触发精确率 | 实际触发的用例中，确实应触发的比例 |
| 漏触发率 | 应触发但未触发的比例 |
| 误触发率 | 不应触发却触发的比例 |
| 任务成功率 | 输出满足契约和验收标准的比例 |
| 关键错误率 | 造成高风险或关键风险失败的比例 |
| 规则命中率 | 任务需要某规则时，该规则被读到或被执行的比例 |
| 指针覆盖率 | 按需文件被主流程明确引用的比例 |
| 孤儿资产数 | 留存文件中无入口、无用途或无引用的数量 |
| 常驻篇幅 | SKILL.md 及强制读取内容的行数/token 估算 |
| 无关上下文比例 | 常驻内容中与当前任务无关部分的估算比例 |
| 回归通过率 | 改造后基线用例通过的比例 |

## 3. 阈值原则

阈值必须按风险等级和业务目标校准，不应把固定数值当成通用真理：

- 关键安全、隐私、法律或数据破坏项：优先追求零关键错误，必要时引入人工评审。
- 高频任务：优先提高触发召回率和任务成功率。
- 容易误触发的技能：优先提高触发精确率。
- 格式和风格项：可使用较低权重或事后验收。
- 无法自动判断的结果：使用专家评审、成对比较或明确 rubric。

## 4. 证据等级

| 等级 | 证据 |
|---|---|
| 强 | 自动化测试、可重复实验、多个真实任务、官方/权威来源 |
| 中 | 专家走查、单次回放、少量样本、可解释的静态检查 |
| 弱 | 主观判断、未复现事故、无来源经验 |
| 无效 | 与任务无关、无法复现、来源不明或被证伪 |

基线不足时，可以继续诊断，但不得宣称改造后“能力没有降级”。
