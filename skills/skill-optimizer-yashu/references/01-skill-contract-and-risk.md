# Skill 契约与风险分级

## 什么时候读我

当需要确认目标 Skill 的使命、边界、用户、触发条件、风险等级或变更类型时，先读本文件。

## 1. 建立 Skill 契约

至少确认以下信息：

| 项目 | 要回答的问题 |
|---|---|
| 使命 | 这个 Skill 帮助 Agent 完成什么？不负责什么？ |
| 用户与场景 | 谁会使用？在什么任务、行业、平台或流程中使用？ |
| 触发表达 | 用户会怎样提出需求？包括口语化、同义替换和关键词。 |
| 不触发场景 | 哪些相似请求不应由该 Skill 处理？ |
| 输入 | 文件、链接、数据、权限、上下文或用户指令是什么？ |
| 输出 | 最终交付文件、消息、代码、表格、媒体或操作结果是什么？ |
| 依赖 | 依赖哪些工具、Skill、API、脚本、模板、网络或本地环境？ |
| 成功标准 | 什么结果算成功？由哪些测试、验收单或人工判断证明？ |
| 风险 | 错误会造成安全、法律、财务、隐私、数据、声誉或流程损失吗？ |

信息缺失但不影响低风险诊断时，可先记录假设；影响改造范围、行为或高风险决策时，必须向用户确认。

## 2. 风险分级

| 等级 | 典型特征 | 改造策略 |
|---|---|---|
| 低 | 格式、文案、示例、非关键排版；错误容易修复 | 小步调整，抽样检查 |
| 中 | 多步流程、文件移动、模板变化、一般业务输出 | 蓝图确认，回放典型任务 |
| 高 | 代码执行、客户交付、数据处理、权限、外部系统写入 | 备份、测试、失败注入、人工确认 |
| 关键 | 安全、隐私、法律、重大资金、不可逆操作、人身或重大声誉风险 | 从严门禁；必要时拒绝或要求专业评审 |

## 3. 变更类型

| 类型 | 是否改变可观察行为 | 审批与验证要求 |
|---|---|---|
| 文档结构调整 | 通常不改变 | 蓝图、链接检查、走查 |
| 文件移动/重命名 | 可能影响路径 | 引用扫描、路径测试、冒烟检查 |
| 行为保持型重构 | 不应改变 | 小步修改、测试或快照对比 |
| 脚本/工具变更 | 可能改变 | 单独列项、单元/集成测试 |
| Bug 修复 | 改变错误行为 | 复现用例、回归测试、用户批准 |
| 功能新增/变更 | 改变能力或输出 | 需求确认、验收测试 |
| 规则退休 | 可能改变决策 | 证据、影响分析、明确批准 |

## 4. 边界规则

- 不得把“优化 Skill”扩展成未经请求的业务流程重设计。
- 不得因重构便利而改变用户指定的技术栈、格式或交付形态。
- 对外部系统、共享目录、账号、消息、日历、工单等写入动作，必须确认目标和授权。
- 同一蓝图中同时存在多种风险等级时，按最高风险项设置门禁。
