# 规则生命周期治理

## 什么时候读我

当需要合并、改写、暂停、退休、删除或恢复规则时，读本文件。

## 1. 生命周期状态

| 状态 | 含义 |
|---|---|
| 有效 | 当前适用，来源和验证方式明确 |
| 待确认 | 含义、来源、适用范围或风险尚不清楚 |
| 合并 | 与其他同义规则归并，保留来源映射 |
| 改写 | 保留规则意图，但调整触发条件、动作、例外或表达 |
| 自动化 | 转为脚本、schema、lint、测试或校验器 |
| 暂停 | 暂时不适用，保留记录并设定复核条件 |
| 退休 | 不再作为执行规则，仅保留历史或审计价值 |
| 恢复 | 已暂停/退休规则因新证据重新生效 |

## 2. 合并规则

适用于：

- 多条规则表达同一约束。
- 示例重复、说明重复或动作重复。
- 不同文档对同一动作给出等价要求。

合并要求：

- 保留最完整、最可执行的表述。
- 记录被合并规则 ID 和原位置。
- 合并后仍保留原规则的关键例外。
- 若规则风险等级不同，先解决冲突再合并。

## 3. 改写规则

优先把抽象表述改成：

```text
当遇到 X 场景时，执行 Y；若出现 Z 例外，改为 W 或请求确认。
```

无法写成条件句时，可补充：判定标准、正反例、决策表、检查问题或流程图。不要仅凭“写不出触发条件”就删除原则性规则。

## 4. 暂停规则

适用于：

- 当前平台或流程已变化，但未来可能恢复。
- 规则与新流程冲突，尚需业务确认。
- 规则风险较高但证据不足。

暂停记录应写明：暂停原因、触发恢复的条件、负责人或复核时间。

## 5. 退休规则

规则退休需要至少一种证据：

- 来源失效或被新版本替代。
- 与现行法律、政策、平台规则冲突。
- 经评测证明规则导致错误或过度限制。
- 对应功能、脚本或流程已经移除。
- 与其他规则重复且无独立信息。
- 用户明确批准删除。

退休前检查：

1. 是否有其他规则引用它。
2. 是否有模板、示例、脚本或测试依赖它。
3. 是否需要保留审计痕迹。
4. 是否应转为历史案例或评测用例。
5. 是否需要同步更新索引和链接。

## 6. 可追溯要求

所有规则的去向必须属于：新位置、合并项、改写项、暂停项、退休项、评测案例或用户批准的删除项。禁止无记录消失。
