# 诊断报告与改造蓝图

## 什么时候读我

当需要整理问题、评级风险、提出文件级改造方案或请求用户批准时，读本文件。

## 1. 问题分类

| 类型 | 典型问题 |
|---|---|
| 路由问题 | description 模糊、触发词过泛、漏触发、误触发、与其他 Skill 冲突 |
| 可发现性问题 | 关键规则没有内联或指针、文件孤儿、入口不可达、规则沉底 |
| 认知负担问题 | SKILL.md 过长、无关规则常驻、关键信息被埋、重复说明过多 |
| 一致性问题 | 规则互相矛盾、术语不统一、路径失效、示例与规则冲突 |
| 正确性问题 | 外部事实错误、链接失效、命令不可用、规则已过时 |
| 完整性问题 | 缺少异常处理、边界条件、验收标准、回滚步骤、非触发说明 |
| 代码问题 | 脚本无测试、职责混杂、依赖不明、路径脆弱、缺少头注 |
| 生命周期问题 | 旧规则无状态、无负责人、无复核时间、退休流程缺失 |
| 验证问题 | 没有评测集、事故无法回放、验收单不可判定 |

## 2. 严重度评级

- **P0 关键**：可能导致安全、法律、隐私、重大财务、不可逆数据损失或严重对外后果。
- **P1 高**：任务大概率失败、关键能力不可用、脚本无法运行或交付错误。
- **P2 中**：流程受阻、需要返工、规则遗漏、可恢复但影响效率。
- **P3 低**：格式、措辞、排版、轻微不统一。

## 3. 诊断报告内容

1. 目标 Skill 路径、审计范围、日期和一句话结论。
2. Skill 契约摘要与风险等级。
3. 资产盘点表和引用/依赖关系。
4. 规则记录与标签统计。
5. 基线评测结果。
6. 问题清单：证据、影响、严重度、责任文件、建议动作。
7. 冲突、重复、孤儿、沉底、失效规则和死链清单。
8. 改造蓝图：新增、移动、合并、改写、暂停、退休、删除、脚本变更。
9. 备份、测试、回滚和验证方案。
10. 残余风险与不处理项。

## 4. 蓝图方案

重大改造建议提供：

| 方案 | 适用情况 | 特点 |
|---|---|---|
| 保守方案 | 风险较高或时间有限 | 只做结构调整、指针、备份和必要修复 |
| 推荐方案 | 大多数治理任务 | 修复主要路由、规则生命周期和回归评测 |
| 完整重构 | 原结构明显失效或用户授权重写 | 重新设计契约、架构、模板、示例和评测 |

每个文件级动作必须写明：动作类型、对象、目标位置、内容要点、对应问题、风险、验证方式和回滚方式。

## 5. 批准门

用户明确批准前，不得执行写入。用户给出的是长期授权时，也应在蓝图中说明本次将利用该授权执行哪些动作；若出现蓝图外的高风险变更，仍需再次确认。
