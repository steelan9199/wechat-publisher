# 治理规范：文档类资产（SKILL.md / references / checklists / examples）

## 总原则

- 文档治理 = 给规则「搬家」，不是重写内容，更不是删除知识。
- 改完后任何一条原规则都必须可追溯：要么在新位置，要么在「申请删除清单」里。
- 保持目标 skill 原有语言风格与术语，不擅自更换技术栈口径。

## SKILL.md 治理

1. 结构固定为：frontmatter（name / description）→ 标题与一句话定位 → L0 红线 → L1 主干流程 → L2 索引区 → L3/L4 引用区。
2. description 必须写明：触发场景 / 触发词 + 能力概述 + 关键产物，确保技能本身可被发现（技能级可发现性）。
3. 红线置顶，条数 3-7，每条带熔断条款。
4. 主干只保留有序流程；场景细则全部移出，原位置只留一行指针。
5. 主文件不承载完整场景规则正文，不塞大段示例。

## references/ 治理（L2 归宿）

- 一个场景 / 主题一个文件，文件名以「动作或场景」命名（如 `导出规范.md`、`客户数据处理.md`），不以抽象分类命名。
- 每份场景文件开头用一句话写明「什么时候读我」（「当遇到 X 需求时读本文件」）。
- 文件内部仍按 L0-L4 思路组织：先给该场景的硬红线（若有），再给操作步骤，再给验收点与判例。
- 主文件指针与场景文件双向可追溯：主文件写「先读 xx」，场景文件首行写明触发场景。
- 拆分顺序：先按「动作」聚类全部规则 → 合并同义 → 落成文件 → 最后回主文件挂指针。

## checklists/ 治理（L3 归宿）

- 所有格式 / 审美 / 统一性条目集中到此，一张验收单对应一类产物。
- 每条写成可判定项，如 `- [ ] 标题 ≤ 20 字（合格 / 不合格）`。
- 在 L1 交付前一步显式引用：「完成后对照 `checklists/xxx.md` 逐项自检，不合格项返工」。

## examples/ 治理（L4 归宿）

- 抽象规则判例化：反例 ❌ + 正例 ✅ + 一句点评，成组存放。
- 判例在对应规则处挂引用（如「语气要求见 `examples/xxx.md`」）。

## 文档级禁止事项

- 禁止把多个不相关场景塞进同一 reference 文件（会重新变成「大而全手册」）。
- 禁止在主文件保留「以防万一」的规则正文，用指针代替。
- 禁止改动文档中的外部事实、数字、链接内容；发现失效链接可标注，但不编造替代。
