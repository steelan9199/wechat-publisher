# 审计标准：信息架构（IA）与可发现性（Findability）

## 基本判定

- **信息架构**：知识放在哪、怎么分类、做哪件事时能看到哪部分的摆放规则。
- **可发现性**：需要某条知识的模型，在需要的那一刻，能不能马上找到它。IA 是设计图纸，可发现性是验收指标。
- 铁律：给 AI 看的东西，放错位置等于不存在。审计只认「会不会被读到」，不认「写没写」。

## 单条规则可发现性判定

对每条规则回答 4 个问题：
1. 触发点是什么？（做哪个动作的那一刻需要它？）
2. 规则当前位置与触发点是什么关系：贴在动作旁边 / 藏在按分类命名的章节里 / 没有对应位置？
3. 模型沿 L1 主干流程执行时会不会经过它（内联步骤，或该步骤上的直达指针）？
4. 触发概率：每次相关任务必见 / 极少数任务才翻到 / 永不可达？

判定分档：
- **浮在必经之路（高）**：位于触发动作的同一步骤内，或该步骤挂有直达指针；相关任务 100% 经过。
- **可检索但不在必经路（中）**：已物理隔离且有索引，但指针挂在非主干位置，依赖模型主动翻。
- **沉底（低）**：躺在分类章节 / 文件深处，主干上既无内联也无指针 → 判 ❌，必须搬家。
- **死规则（零）**：无触发条件、无任何引用 → 判 ❌。

## 两种正确上架手法

| 手法 | 适用 | 做法 |
|---|---|---|
| 内联 | 高频且致命 | 规则直接写进 L1 对应步骤（如装信封前「先盖章、再封口」） |
| 挂指针 | 庞杂 / 低频 | 在 L1 对应步骤写「做 X 前，先读 `references/xxx.md`」 |

「既无内联也无指针」即为翻车架构，必改。

## 可发现性评分（量化）

- 单条规则得分：高 = 1 / 中 = 0.5 / 低 = 0 / 死规则 = 0。
- 目标 skill 总分 = 规则得分之和 ÷ 规则总数；目标 ≥ 0.9。< 0.7 判 ❌，0.7-0.9 判 ⚠️。
- L0 红线的可发现性必须全部为 1，否则直接 ❌。
- 另报四项指标：沉底规则数（目标 0）、孤儿文件数（目标 0）、死规则数（目标 0）、指针覆盖率（L2 文件被 L1 引用的比例，目标 100%）。

## 注意力税审计

- 统计常驻内容（SKILL.md 主文件 + 流程中强制读取的文件）的规则数量与估算篇幅。
- 判定：L0 + L1 是否精简到可每次在场？是否存在大量与当前任务无关的常驻条目（对每次推理收「无关税」）？
- lost in the middle 检查：关键规则 / 红线是否被埋在长文档中部？是则判 ⚠️/❌ 并前移。

## 新人走查法（必做）

假装自己是第一次执行该任务的模型，从 L1 第一步走到最后一步，逐步记录：
- 这一步我需要知道什么？
- 这些信息此刻在不在我的视野里（步骤正文，或该步指针所指文件）？
- 不在 → 记录缺口，该位置就是提醒 / 指针的安放点。

走查发现的全部缺口进入改造蓝图。
