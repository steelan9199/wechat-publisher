# 审计标准：五层效力体系

本文件是审计目标 skill 的强制对标标准与治理依据。每个层级的审计结论分三档：✅ 合格 / ⚠️ 部分合格（必须给出修法）/ ❌ 不合格。

## 总览

| 层级 | 名称 | 准入条件 | 数量阈值 | 形态要求 | 出场时机 |
|---|---|---|---|---|---|
| L0 | 宪法层（红线） | 违反即任务失败 / 不可逆损失 / 对外闯祸 | 3-7 条，砍到个位数 | 每条配熔断条款，置顶 | 事前常驻，凌驾一切场景 |
| L1 | 主干法（流程层） | 决定任务主干怎么走的步骤 | 一条主线 | 有序编号流程，非并列清单 | 事前常驻 |
| L2 | 场景法规（条件层） | 「当遇到 X 时才……」 | 规则的大多数 | 显式触发条件 + 物理隔离 + 索引指针 | 事中按需加载 |
| L3 | 验收单（偏好层） | 违反不致命，只影响美观 / 统一 | 不限 | 独立验收单，可逐项判定 | 事后自检 |
| L4 | 判例层（示例） | 可用好坏对照讲清楚 | 不限 | 反例 / 正例成对 | 全程参考 |

## L0 审计口径

准入测试（逐条问）：
1. 「违反它，会死人吗？」——任务直接失败？损失不可逆？会伤害他人或对外闯祸？
2. 它是全局生效，还是只在某个场景生效？只在具体场景致命的，原则上归 L2 挂指针，并在 L1 对应步骤内联提醒，不占 L0 名额。

硬性阈值：
- 数量必须 3-7 条；超过 7 条判 ❌，须把不满足准入测试的条目下沉。
- 每条必须 100% 配熔断条款，包含三要素：**触发信号（一旦遇到……）+ 立即停止 + 向用户确认后再执行**；缺任一要素判 ❌。
- 红线必须位于 SKILL.md 正文前部最高醒目位置；埋入中后部判 ⚠️。

常见不合格：
- 「全都是红线」：几十条都声称至高无上 → 实际没有至高无上，重走准入测试。
- 只写「不得 X」，没写违反时模型该做什么 → 熔断缺失。

## L1 审计口径

- 形态必须是一条有先后顺序的编号流程（第 1 步……第 N 步……）；以并列「你应该 / 你必须」清单呈现主干判 ❌。
- 主干必须覆盖任务从接收到交付的完整路径；存在关键动作无步骤承接（如寄件流程没有盖章提醒）判 ❌，并指出缺口位置。
- L0 + L1 是唯一每次都在场的部分，须保持精简；L1 单步内混入大段场景细则判 ⚠️，细则应下沉 L2 并在该步挂指针。
- 存在确认门 / 熔断门的，必须在流程中显式标出，缺失判 ⚠️。

## L2 审计口径

三条硬性要求，任一不满足判 ❌：
1. **触发条件显式**：每条规则能改写为「当遇到 X 情况时，执行 Y」。干巴巴的「输出要规范、注意质量」属无触发器死规则，须补「当……时」；补不上则改判例或列入删除申请。
2. **物理隔离**：场景规则必须拆入独立文件（通常在 references/ 下），仅靠同一文件内小标题分区判 ❌——模型不会跳过无关段落，全文都会读入。平台确实不支持多文件时，降级为「主提示词保留场景索引 + 规则正文入可检索资料库」，并在报告中标注降级。
3. **索引指针可达**：主文件 L1 对应步骤上必须有指针，写明「当遇到 X 时，先读 `references/xxx.md`，再动手」；规则文件存在但主流程无指针 = 孤儿文件，判 ❌。

打包标准：按「做哪个动作时会用到它」打包，不按分类学、不按踩坑时间打包。

## L3 审计口径

- 「标题不超过 N 字、段落空行、结尾行动号召、代码加注释、用词统一」等违反了不致命的条目，必须 100% 移出执行期文档，编入独立《输出验收单》。
- 验收单须可逐项判定（合格 / 不合格、有 / 无），笼统表述判 ⚠️。
- 执行期主文档仍残留格式偏好条目判 ⚠️；残留量大判 ❌。
- L1 流程末尾须显式安排「输出后对照验收单自检」步骤，缺失判 ⚠️。

## L4 审计口径

- 凡含主观 / 抽象形容词的规则（「语气专业但不生硬」「简洁优雅」），审计时测试：能否给出反例 + 正例对照？能则必须配判例，缺判例判 ⚠️。
- 判例必须成对（反例 ❌ / 正例 ✅）并可附一句点评；只有正例没有反例判 ⚠️。
- 判例文件须在主文件或相关规则处挂引用指针。

## 审计输出要求

对每条规则记录：规则原文摘要（出处文件与位置）→ 三标签（后果 / 场景 / 时机）→ 建议层级 → 不符合项 → 改造动作。
对每个层级给出：结论（✅/⚠️/❌）+ 量化数据（如「L0 共 14 条，超标 7 条；熔断覆盖率 40%」）+ 修法清单。
