# 资产盘点与规则抽取

## 什么时候读我

当需要列出目标 Skill 全部资产、识别依赖关系、抽取原子规则或建立规则追踪表时，读本文件。

## 1. 资产盘点

递归列出全部文件，并按以下类型登记：

- `SKILL.md` 与 frontmatter
- references / 说明文档
- checklists / 验收单
- examples / 示例与判例
- scripts / 可执行代码
- assets / 模板、图片、字体、静态资源
- evals / 测试用例或评测数据
- 配置文件、许可证、数据文件
- 隐藏文件、临时文件、备份文件

每个文件至少记录：路径、类型、大小或行数、被谁引用、引用了谁、用途、维护状态、风险备注。

**符号链接必须显式处理。** 技能根目录本身常常是指向别处的符号链接（技能管理器把真身放在别的目录），技能内部也可能把子目录链接到共享资产。盘点时必须跟随链接，并同时记录「链接路径」与「真实路径」——否则内容会被静默漏掉：引用能解析、文件却从未进入清单，既不报错也不报孤儿；改造时还容易改到副本或改错位置。不跟随链接的盘点工具（bash `find` 的默认行为即如此）会给出偏少的文件数，不能用它下结论。

判定链接不要靠肉眼或记忆，直接让工具报出来：

```powershell
# 1) 单个技能根是否为链接，以及真实内容路径
Get-Item "C:\Users\Administrator\.workbuddy\skills\<skill-name>" |
  Select-Object Name, LinkType, Target

# 2) 全库扫描，一次看清每个技能根是链接还是实体目录
Get-ChildItem "C:\Users\Administrator\.workbuddy\skills" -Force |
  ForEach-Object { [pscustomobject]@{
      Name   = $_.Name
      IsLink = $_.LinkType -ne $null
      Target = ($_.Target -join ";")
  } } | Format-Table -AutoSize
```

校验器把跟随到的内部目录链接列在 `symlinked_dirs_followed`、文件链接列在 `symlinked_files`，技能根是链接时还会在 `warnings` 里给出真实路径。以这三个字段为准做盘点，不要自行假设。

## 2. 引用与依赖图

检查：

- Markdown 链接和相对路径
- 脚本调用、import、require、模块路径
- 文档中提到但不存在的文件
- 文件存在但没有入口引用的孤儿资产
- 重复模板、重复示例、重复规则
- 外部命令、网络、API、权限、环境变量和依赖版本

## 3. 原子规则抽取

将自然语言文档拆成可追踪规则。一条规则只表达一个可判断的约束或决策；过长规则拆分为多条，并保留共同来源。

每条规则记录：

| 字段 | 说明 |
|---|---|
| ID | 唯一编号，如 `R-001` |
| 原文与出处 | 文件路径、章节、行号或引用位置 |
| 类型 | 安全、法律、隐私、流程、工具、格式、概念、示例、事实 |
| 触发条件 | 当遇到什么场景时需要它 |
| 推荐动作 | 应执行、避免、检查、拒绝或交付什么 |
| 例外 | 哪些条件下不适用或采用其他规则 |
| 理由 | 为什么存在，对应什么风险、事故或要求 |
| 来源 | 官方文档、法律、标准、历史事故、专家经验或用户要求 |
| 风险等级 | 低/中/高/关键 |
| 置信度 | 已验证、大概率成立、待确认、冲突、已失效 |
| 当前位置 | 内联、reference、checklist、example、脚本、资产 |
| 建议位置 | 内联、指针、reference、checklist、example、自动化校验、退休 |
| 验证方式 | 测试、验收项、事故回放、人工评审或反例 |
| 生命周期 | 有效、待确认、合并、改写、暂停、退休 |

## 4. 抽取注意事项

- 不要因为规则写得抽象就立即删除；先尝试补充触发条件、判定标准和示例。
- 不要把示例、解释、原则和操作步骤混在同一条规则中。
- 同义规则合并时保留最完整表述，并记录被合并规则 ID。
- 无法判断含义、来源或适用范围的规则，标记为“待确认”，不得擅自改写。
- 所有修改建议必须能从原规则或证据追踪到新位置。
