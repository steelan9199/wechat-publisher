# 治理规范：目录结构与命名

## 标准骨架（对标五层体系）

```
<skill-name>/
├── SKILL.md                 # L0 + L1 + 索引指针，唯一入口
├── references/              # L2 场景法规，按动作 / 场景一文件
├── checklists/              # L3 验收单
├── examples/                # L4 判例（反例 / 正例）
├── scripts/                 # 可执行脚本（若有）
└── assets/                  # 模板、静态资源等（若有）
```

- 空目录不创建：无脚本则无 scripts/，无资源则无 assets/。
- 目标 skill 已有合理且能工作的目录结构时保持兼容，不为「标准」而搬家；任何结构调整都须在蓝图中列明。
- 层级深度建议 ≤ 3（SKILL.md 之下两层），过深损害可发现性。

## 命名规范

1. 目录名用小写英文加连字符；references/checklists/examples 属平台约定，不改名。
2. 场景文件可用中文达意命名（与本技能一致），以目标 skill 既有语言习惯为准，全库统一，不中英混杂。
3. 文件名表达「什么时候用它」：`导出客户数据.md` 优于 `规范3.md`；`build_report.py` 优于 `tool1.py`。
4. 禁止日期 / 作者 / 版本流水名（如 `规范-最终版2.md`）、含糊缩写、同义多名。
5. 重命名必须同步更新全部引用指针；完成后反向搜索旧名，确认无悬挂引用。

## 可达性检查

- 从 SKILL.md 出发，任一文件要么被指针引用，要么在蓝图中被标注为孤儿待处理。
- 引用路径一律使用相对路径；移动文件后全量校验链接有效性。
- 不允许「目录里有、入口找不到」的文件留存。
