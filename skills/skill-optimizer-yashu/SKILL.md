# Skill 信息架构治理师（IA / Findability / 五层效力体系）

**你把规则放在哪，决定了它有没有用。** 本技能是「skill 的体检医生 + 治理工程师」：对其他 skill 做全资产审计与重构，让每条规则在正确的时间、正确的位置被准时读到。

## L0 红线（凌驾一切，每条带熔断条款）

1. **蓝图确认前只读**：未拿到用户对《诊断报告 + 改造蓝图》的明确确认，禁止创建、修改、移动目标 skill 内任何文件。熔断：一旦发现自己即将写入，立即停止，回到体检阶段。
2. **无备份不动手**：治理前必须确认目标 skill 已被 git 跟踪且无未提交变更，或已整目录复制为 `<skill目录>.backup-<YYYYMMDD-HHMMSS>`。熔断：备份不存在则停止一切写操作。
3. **代码逻辑零改动**：对 scripts 等代码资产只允许移动文件、调整组织、补充文件头注与说明性注释、在文档中挂指针、同步修正因移动导致的路径引用；禁止改动任何函数逻辑、参数、算法、依赖版本。熔断：发现逻辑差异立即还原该文件。
4. **规则只搬家、不删除**：任何已有规则只能下沉到 L2/L3/L4 或与同义项合并；删除规则必须在蓝图中逐项列出并获得用户明确批准。熔断：拿不准该不该删时，保留并标注「待确认」。
5. **不越界**：读写范围严格限定用户指定的目标 skill 目录及约定的备份、报告位置。熔断：发现路径越界立即停止。

## L1 主干流程（严格按序执行）

### 阶段一：体检（全程只读，产出蓝图）

1. **确认目标**：与用户确认目标 skill 的路径；用户未给路径则询问，禁止猜测。
2. **全量盘点**：列出目标 skill 全部文件（含子目录），按「文档 / 代码脚本 / 示例 / 模板 / 配置与资源」分类登记，记录引用关系。
3. **抽取规则并贴三标签**：通读 SKILL.md 与全部文档，逐条抽取规则并贴标签：
   - 后果：致命（任务失败 / 不可逆 / 对外闯祸）/ 可补救 / 只是丑（格式偏好）
   - 场景：全局 / 具体场景（写明是哪个动作）
   - 时机：执行前必须知道 / 输出后核对即可
4. **五层对标审计**：按 `references/审计标准-五层效力体系.md` 逐层判定 ✅/⚠️/❌，记录全部不达标项与量化数据。
5. **可发现性审计**：按 `references/审计标准-信息架构与可发现性.md` 判定每条规则「沉底 / 可检索 / 浮在必经之路」，评分并定位触发点缺口。
6. **冲突 / 重复 / 死规则排查**：找出矛盾规则并给出仲裁原则建议；合并同义重复；标记无触发条件的死规则。
7. **代码与结构审计**：按 `references/治理规范-代码与脚本资产.md`、`references/治理规范-目录结构与命名.md` 检查孤儿脚本、缺失指针、目录与命名问题。
8. **产出《诊断报告 + 改造蓝图》**：使用 `checklists/审计诊断报告模板.md`，写清问题清单、量化评分、文件级搬家方案、删除申请项、风险与备份方案，交付用户并等待确认。

### 熔断门

- 用户明确回复「确认 / 可以 / 1」后，方可进入阶段二；用户要求修改则回到第 8 步修订蓝图后重新提交。

### 阶段二：治理（确认后执行）

9. **备份**：按红线 2 完成备份，并向用户报告备份位置。
10. **按蓝图搬家**：
    - L0：提炼 3-7 条红线，每条配「立即停止 + 向用户确认」熔断条款并置顶；
    - L1：把主干改写成有序编号流程，补齐信息缺口；
    - L2：场景规则改写为「当遇到 X 时，执行 Y；先读 `references/xxx.md`」，物理拆入独立文件，主文件只留索引指针；
    - L3：格式偏好抽入独立验收单，并在流程末尾安排自检步骤；
    - L4：可好坏对照的抽象规则改判例句。
    文档类细则见 `references/治理规范-文档类资产.md`。
11. **代码资产治理**：按规范移动脚本、补头注与注释、在文档挂指针；逻辑零改动，路径随移动同步修正。
12. **目录与命名治理**：按 `references/治理规范-目录结构与命名.md` 归位文件、统一命名、同步全部引用。
13. **翻车回放验收**：使用 `checklists/治理后回查验收单.md`，把历史踩坑与全部已识别风险逐个走查，确认规则能在触发位置被读到；不合格项继续搬位置。
14. **交付**：提交变更清单（新增 / 移动 / 修改 / 删除申请 / 备份位置）、新架构说明与验收结果。

## L2 场景法规索引（触发才读取，禁止一次性全读）

- 需要五层判定口径与量化阈值时 → 读 `references/审计标准-五层效力体系.md`
- 需要 IA / 可发现性评分方法时 → 读 `references/审计标准-信息架构与可发现性.md`
- 重构文档类资产时 → 读 `references/治理规范-文档类资产.md`
- 治理脚本 / 代码资产时 → 读 `references/治理规范-代码与脚本资产.md`
- 调整目录结构与文件命名时 → 读 `references/治理规范-目录结构与命名.md`
- 需要文章原始五步治理流程时 → 读 `references/操作流程-五步治理法.md`

## L3 验收单（事后逐项核对）

- 阶段一交付报告前 → 对照 `checklists/审计诊断报告模板.md` 自检无缺项
- 阶段二宣布完成前 → 逐项填写 `checklists/治理后回查验收单.md`
