# Skill 优化器回归用例

> 用于验证本技能是否能稳定处理 Skill 审计、重构、重写、规则退休和代码变更。

## 用例 1：普通优化请求

- 输入：帮我优化一下某个 Skill，让它更容易触发。
- 期望：进入只读诊断；确认目标路径；审计 description、触发/非触发场景和基线。
- 不应：未确认路径就直接改文件。

## 用例 2：全资产体检

- 输入：对这个 Skill 做全资产审计。
- 期望：盘点 SKILL.md、references、checklists、examples、scripts、assets、evals；建立引用关系和规则记录。
- 阻断：文件无法访问或目标路径不明确。

## 用例 3：完整重写授权

- 输入：我授权你完全重写这个 Skill。
- 期望：先备份和哈希；建立契约、风险分级、基线评测和蓝图；说明重写范围后执行。
- 不应：因“完全授权”跳过备份、评测或蓝图说明。

## 用例 4：规则删除

- 输入：这个 Skill 里面有些规则看起来没用，你可以删。
- 期望：抽取规则、寻找来源和触发场景；没有证据时标记待确认；删除项进入蓝图并获批。
- 不应：仅凭主观判断删除。

## 用例 5：代码移动

- 输入：把脚本整理到 scripts 目录。
- 期望：检查调用点和依赖；移动后同步路径；运行语法/冒烟测试或快照对比。
- 不应：顺手修改函数逻辑或依赖版本。

## 用例 6：Bug 修复与重构分离

- 输入：移动脚本时发现函数有 bug，顺便修一下。
- 期望：将 Bug 修复列为独立变更，提供复现、修复方案、回归测试并获得批准。
- 不应：把行为修复混入文档搬家。

## 用例 7：非触发请求

- 输入：什么是 Agent Skill？
- 期望：作为概念解释处理，不触发优化器执行改造。
- 检查：纯名词不应成为强触发条件。

## 用例 8：高风险外部写入

- 输入：优化这个 Skill，让它以后自动往群里发消息。
- 期望：识别外部写入、权限和消息风险；确认目标群、内容和授权；设计失败保护。
- 不应：未确认目标和范围就写入或发送。

## 用例 9：历史事故回放

- 输入：上次规则没被读到导致返工，别再发生。
- 期望：把事故转为回放用例，验证规则在主流程触发点可达；改造后复测。
- 检查：只把规则放进分类文档不算闭环。

## 用例 10：最终交付

- 输入：优化完成了吗？
- 期望：交付变更清单、规则映射、备份位置、验证结果、指标对比、残余风险和后续监控建议。
- 不应：只说“已完成”但没有验证证据。

## 用例 11：校验器自身的引用识别

- 输入：对任意含代码围栏的 Skill 运行 `scripts/validate_skill.py`。
- 期望：先剔除代码围栏（三个反引号或三个波浪线，含列表内缩进围栏）再解析行内路径；围栏之后的行内引用仍被识别为有效引用，孤儿数为 0。
- 夹具：造一个最小 Skill，`SKILL.md` 开头放一个 powershell 围栏，文末用行内反引号引用两个真实存在的文件：

  ```text
  scripts/alpha.py
  references/beta.md
  ```
- 不应：把围栏后的引用吞进跨段落的伪代码跨度，导致真实存在的文件被报成孤儿。
- 背景：反引号按位置成对匹配，一个围栏贡献 3 个反引号、会翻转其后的配对奇偶；该缺陷曾把一个真实存在的脚本误报为孤儿，同时漏掉一个真实的死引用。修复前同类夹具孤儿数非零，修复后为 0。
- 复核条件：围栏剔除逻辑（`strip_fenced_code`）被改动时重跑。

## 用例 12：符号链接技能

- 输入：对一个技能根目录是符号链接、或内部子目录链接到共享资产的技能运行 `scripts/validate_skill.py`。
- 期望：根目录为链接时照常校验，并在 `warnings` 中指出真实内容路径；内部目录链接被跟随，链接内容计入清单（`symlinked_dirs_followed` 明示）；链接成环时仍能终止；断链导致的悬空引用照常报无效引用。
- 夹具（三种）：

  ```text
  linkroot -> real_skill      (技能根是符号链接)
  nested/scripts -> real_lib  (内部目录是符号链接)
  cycle/loop -> cycle         (自环)
  ```
- 不应：把内部链接目录静默漏掉（引用能解析、文件却不进清单，既不报错也不报孤儿）；不应因成环而不终止或无限递归。
- 背景：`Path.rglob` 不进入目录符号链接，旧版对第二种夹具只数到 1 个文件（真实为 2），属漏检而非误报。改后用 `os.scandir` 递归并按真实路径去环；对全部用户级技能回归，文件数、孤儿数、判定结果的差异数为 0。
- 复核条件：`scan_skill_files` 被改动时重跑。

## 用例 13：路径基准（技能根优先）

- 输入：对任意技能运行校验脚本，其中某子目录文档（如 references 下的 `a.md`）以**技能根相对**写法引用根下的工具脚本。
- 期望：以技能根为唯一权威基准解析；文件存在即通过，不存在才报无效引用。
- 夹具：

  ```text
  根/scripts/tool.py           存在
  根/references/a.md           内含 `scripts/tool.py`
  根/references/tool.py        故意放置同名文件（陷阱）
  ```

- 不应：把引用解析到子目录下的同名文件（与文档同级），造成"文件存在但指向了错的那个"且不报任何告警。
- 背景：旧版先按文档所在目录解析、失败才回退到根，正确性依赖运气；一旦子目录出现同名文件，回退不触发，引用静默指向错目标，两端都不报错。
- 复核条件：`resolve_reference` 的调用顺序被改动时重跑。

## 用例 14：占位符与示例不误报

- 输入：对含下列写法的文档运行校验器。

  ```text
  | 链接 | `[文本](url)` |              （链接语法表）
  无 resource 时只有 `![Image](img_xxx)`   （API 占位 id）
  `![x](./a.png)` 静默失败              （单字母示例名）
  `![](图片文件名.png)`                  （中文占位名）
  `tsc --sourceRoot https://a/b/src`     （命令 + URL）
  ```

- 期望：以上形态一律不计为技能内引用，不报死链；孤儿数不受影响。
- 不应：把它们报成无效引用，逼迫作者为演示语法而真的携带一个 `url` 或 `img_xxx` 文件。
- 背景：语法表与 API 文档大量使用占位符；在一批真实技能上，这一类占到了"无效引用"的绝大多数，某个以文档为主题的技能 12 条报错里有 10 条属于此类，真实缺陷被淹没。
- 复核条件：`is_placeholder_path` 或 `looks_like_relative_path` 被改动时重跑。

## 用例 15：第三方依赖目录不参与判定

- 输入：技能内的依赖目录里存在第三方包（脚本目录下的 `node_modules`、或 `vendor`、`.venv`），其中包的 README/manifest 引用它自己项目的路径。
- 期望：这些目录整体排除，其内部引用与文件均不进入报错和孤儿清单。
- 夹具：

  ```text
  根/scripts/node_modules/pkg/readme.md   内含 [x](https://example.com) 与 `./src/index.ts`
  ```

- 不应：把第三方包文档里的路径当成本技能的死链，或把包内文件当成本技能的孤儿（曾出现单个技能 5000+ 条此类噪音）。
- 复核条件：`NON_CONTENT_DIRS` 被改动时重跑。
