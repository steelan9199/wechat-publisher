# 诊断阶段验收单

> 交付《诊断报告 + 改造蓝图》前逐项检查；任一关键项缺失，应补齐后再提交。

## A. 目标与契约

- [ ] 已确认目标 Skill 的名称、路径和读写范围
- [ ] 已说明 Skill 的使命、用户、典型任务和不负责事项
- [ ] 已列出触发表达、改写表达和不触发场景
- [ ] 已确认输入、输出、依赖工具和成功标准
- [ ] 已完成风险分级

## B. 资产盘点

- [ ] 已递归列出全部文件和目录
- [ ] 已按文档、脚本、示例、模板、资源、配置、评测等类型分类
- [ ] 已记录文件大小或行数
- [ ] 已建立引用和依赖关系
- [ ] 已标记孤儿文件、死链、重复文件和疑似废弃资产

## C. 规则抽取

- [ ] 已为每条原子规则分配唯一 ID
- [ ] 已记录原文、出处、触发条件、动作和例外
- [ ] 已记录来源、理由、风险等级和置信度
- [ ] 已标记待确认、冲突、重复、失效或无触发规则
- [ ] 每条规则都有建议去向或验证方式

## D. 基线评测

- [ ] 已设计明显触发和改写触发用例
- [ ] 已设计非触发和冲突路由用例
- [ ] 已设计典型任务和历史事故回放
- [ ] 已设计边界条件、失败注入和必要的代码测试
- [ ] 已记录改造前指标和证据等级

## E. 报告与蓝图

- [ ] 问题按类型、严重度、证据、影响和建议动作列出
- [ ] 文件级动作写明对象、目标位置、风险、验证和回滚方式
- [ ] 规则修改、暂停、退休或删除有证据和审批项
- [ ] 重大改造提供保守方案、推荐方案或完整重构方案
- [ ] 报告明确请求用户批准，且未在批准前执行写入
