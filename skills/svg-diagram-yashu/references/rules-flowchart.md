# 流程图 · 专属视觉规则

> 本文件是流程图（flowchart）的专属视觉规则。绘制流程图时，除遵守 `design-system.md` 和 `svg-drawing-knowledge.md` 外，**必须**遵守本文件。
>
> 流程图表达「过程、算法或工作流的执行顺序」。它靠**形状区分步骤语义**、靠**箭头表达流向**——这与架构图（靠颜色和位置分组）有本质区别。

---

## 1. 视觉特征

流程图的核心视觉语法是三个字：**形、向、支**。

- **形**——形状本身携带语义。读者看到菱形就知道是判断，看到椭圆就知道是起止。**形状用错 = 语义错**，这是流程图最严重的错误。
- **向**——箭头表达执行方向，通常自上而下（纵向）或从左到右（横向）。同图方向必须统一。
- **支**——判断节点产生分支，分支出口必须标注条件（"是/否"、"成功/失败"），合流处要清晰。

### 两类布局

| 布局 | 适用场景 | 主方向 |
|------|----------|--------|
| 纵向流程 | 步骤多（>4 步）、有回环、有分支合流 | 自上而下 |
| 横向流程 | 步骤少（≤4 步）、线性无分支 | 从左到右 |

默认用纵向。横向只在线性短流程时用。

---

## 2. 形状语义（流程图的核心，必须严格遵守）

| 形状 | 语义 | SVG 画法 | 尺寸 |
|------|------|----------|------|
| 椭圆 / 圆角终端框 | 起始 / 结束 | `<rect rx="22">`（圆角=高/2）或 `<ellipse>` | 高 44，宽按字 |
| 矩形 | 处理 / 步骤 / 动作 | `<rect rx="4">`（小圆角） | 高 48，宽按字 |
| 菱形 | 判断 / 分支 | `<path>` 四点连线 | 高 72，宽按字×1.4 |
| 平行四边形 | 输入 / 输出 | `<path>` 斜边 | 高 48，宽按字 |
| 圆形 | 连接符 / 子流程入口 | `<circle>` | 直径 28 |
| 双竖线矩形 | 子流程 / 预定义过程 | `<rect>` 左右各加一条竖线 | 高 48，宽按字 |

### 形状使用铁律

1. **起止必须用椭圆/圆角终端框**——不要用矩形当起点。
2. **判断必须用菱形**——不要用矩形加问号当判断。
3. **菱形必须有 ≥2 个出口**——只有一个出口的菱形是错的，应该用矩形。
4. **输入输出用平行四边形**——用户输入、文件读取、结果输出。
5. **同图同类形状尺寸统一**——所有矩形同高、所有菱形同高。

## 3. 坐标模板

### 3.1 纵向流程（推荐）

```
画布:       viewBox="0 0 680 H", H = 最底节点底边 y + 20（底部留白 ≥20px，保证终止节点下沿圆角完整可见，不被裁切）
标题:       x=340, y=34 (居中)
主轴 cx:    340 (画布水平中心)
节点 y 间距: 80px (节点高 48 + 间隙 32)
  起始:     y=70
  步骤1:    y=150
  判断:     y=230 (菱形中心)
  步骤2:    y=330 (判断"是"分支)
  步骤3:    y=330 (判断"否"分支, 偏移到 cx±140)
  合流:     y=410
  结束:     y=520, height=44 → 底边 y=564 → H=600

分支偏移:   左路 cx=200, 右路 cx=480 (距主轴 ±140)
合流圆点:   (340, 410), r=4, 灰 600 填充
```

### 3.2 横向流程（线性短流程）

```
画布:       viewBox="0 0 680 200", H=200
节点 cx:    等间距排列
  4 节点:   cx=110/290/470/... (间距 180, 但 4 个超画布)
  3 节点:   cx=140/340/540 (间距 200)
节点 cy:    100
连线:       水平箭头, y=100, 从左框右边到右框左边
```

### 3.3 判断分支模板

```
        [判断菱形] cx=340, y=230
         /        \
    "是" /          \ "否"
       /            \
  [步骤A] cx=200   [步骤B] cx=480
  y=330            y=330
       \            /
        \          /
         [合流圆点] (340, 410)
              |
         [下一步]
```

- "是/否"标签写在分支线**上方**，距线 8px。
- 分支线用斜线（从菱形底角到步骤顶边中点）。
- 合流后继续向下。

## 4. 节点尺寸

| 形状 | 高度 | 宽度公式 | 备注 |
|------|------|----------|------|
| 椭圆（起止） | 44 | `字数 × 7 + 32`（椭圆要更宽留白） | `rx="22"` |
| 矩形（处理） | 48 | `字数 × 7 + 24` | `rx="4"` |
| 菱形（判断） | 72 | `字数 × 9 + 28`（菱形对角线要留文字空间） | 用 `<path>` |
| 平行四边形 | 48 | `字数 × 7 + 32`（斜边各留 8px） | 用 `<path>` |
| 圆形（连接符） | 直径 28 | — | 固定尺寸 |

**菱形最易翻车**：文字太长会溢出菱形对角线。判断文字尽量精简到 4-6 字；超长则拆成两行或改用"判断+子流程"结构。

## 5. 箭头与连线

### 5.1 箭头样式

- **流向箭头**：单向实线，灰 600 `#5F5E5A`，`stroke-width="1.5"`，`marker-end="url(#arrow)"`。
- **回环箭头**：单向实线（不用虚线），从回环起点绕到回环终点，可走直角折线。
- **不要用双向箭头**——流程图箭头永远单向，表达"执行到下一步"。

### 5.2 分支标注（关键）

- 判断节点的**每个出口必须标注条件**："是/否"、"Y/N"、"成功/失败"、"≥100/<100"。
- 标注文字放在分支线**上方**，距线垂直 8px，字号 12，颜色 `#5F5E5A`。
- **文字必须自带白描边**——分支标签常压在斜线/折线之上，会被线条压糊看不清。所有连线相关的标注文字（"是/否"、"成功/失败"等）必须加 `paint-order="stroke fill" stroke="#ffffff" stroke-width="3" stroke-linejoin="round"`，让文字自带白底，线穿过去也不会糊。
- 缺少分支标注 = 读者不知道什么条件走哪条路。

### 5.3 合流

- 多条分支汇合处用一个**实心圆点**（`<circle r="4">`，灰 600 填充）标记合流点。
- 合流后用单条箭头继续向下。
- 不要让多条线直接交汇在一个节点上不画合流点——视觉上会混乱。

### 5.4 连线规则

- 纵向流程：连线垂直，`x1=x2=cx`。
- 横向流程：连线水平，`y1=y2=cy`。
- 分支连线：可用斜线（从菱形角到步骤顶边），但同图斜线角度尽量一致。
- **禁止曲线**——流程图用直线和直角折线，不用贝塞尔曲线（那是思维导图）。

## 6. 配色策略

流程图**靠形状表意，颜色只作配角，保持极度克制**。

| 用法 | 色数 | 说明 |
|------|------|------|
| 纯单色 | 1 | 全图灰系或蓝系，最经典 |
| 起止 + 处理双色 | 2 | 起止用一色（如 green 50），处理用另一色（如 blue 50） |
| 高亮关键路径 | 1+1 | 全图单色，关键路径节点用强调色（如 amber 50） |
| 异常分支高亮 | 1+1 | 正常路径单色，异常/错误分支用 red 50 |

### 配色铁律

1. **色数 ≤ 2**（除非有明确的多类别语义）。
2. **禁止彩虹化**——每个步骤一个色是错的，形状已经表意了。
3. **判断节点不要用特殊色**——菱形形状本身已区分，加色反而干扰。
4. **异常分支可用 red**——这是流程图少数合理用色的场景。

## 7. 常见反例

1. **形状用错**——用矩形当判断、用椭圆当处理。最严重错误，必须杜绝。
2. **判断分支没标"是/否"**——读者无法追踪条件。每个出口必标。
3. **菱形太小文字溢出**——判断文字超出菱形对角线。加大菱形或精简文字。
4. **箭头方向混乱**——回环和前进分不清。回环用直角折线绕回，方向要明确。
5. **多色滥用**——每步一色。形状已表意，颜色退居配角，≤2 色。
6. **用曲线连接**——流程图用直线/直角折线，不用贝塞尔曲线。
7. **合流点缺失**——多分支直接交汇不画圆点。加合流圆点。
8. **双向箭头**——流程图箭头永远单向。
9. **起止节点缺失**——没有明确的"开始"和"结束"椭圆。流程必须有头有尾。
10. **同图方向混用**——有的步骤向下、有的向右。统一一个主方向。
