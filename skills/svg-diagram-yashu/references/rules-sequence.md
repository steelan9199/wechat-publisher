# 时序图 · 专属视觉规则

> 本文件是时序图（sequence diagram）的专属视觉规则。绘制时序图时，除遵守 `design-system.md` 和 `svg-drawing-knowledge.md` 外，**必须**遵守本文件。
>
> 时序图表达「多个参与者之间随时间推移的消息交互」。它靠**生命线**（竖直虚线）和**消息箭头**（水平线）建立时空结构——时间自上而下隐式推进，参与者水平排列。

---

## 1. 视觉特征

时序图的核心视觉语法是三个字：**线、息、序**。

- **线**——每个参与者有一条竖直生命线（虚线），从顶部标题栏贯穿到底部。生命线必须**笔直**，不能弯折。
- **息**——消息用水平箭头在生命线之间传递，箭头从源生命线指向目标生命线。
- **序**——消息自上而下按时间顺序排列，**位置越靠上 = 发生越早**。时间顺序不可颠倒。

### 与其他图的区别

| 特征 | 时序图 | 流程图 | 架构图 |
|------|--------|--------|--------|
| 主轴 | 时间（竖直） | 流程（竖直/水平） | 层级（竖直/水平） |
| 参与者 | 顶部标题栏 + 生命线 | 节点框 | 节点框 |
| 连线 | 水平消息箭头 | 流向箭头 | 依赖箭头 |
| 时间语义 | 有（上→下=早→晚） | 有（执行顺序） | 无（静态结构） |

---

## 2. 形状语义

| 元素 | 形状 | 含义 |
|------|------|------|
| 参与者标题栏 | 矩形（顶部） | 参与者名称，位于生命线顶端 |
| 生命线 | 竖直虚线 | 参与者存在的时间跨度 |
| 激活条 | 窄矩形（叠在生命线上） | 参与者正在执行/活跃 |
| 消息箭头 | 水平线 + 箭头 | 参与者间的通信 |
| 自调用 | 小弧形（从生命线出发回到自身） | 参与者自我调用 |
| 删除标记 | 生命线末端的大× | 参与者被销毁 |
| 分组框 | 矩形虚线框（左侧标标签） | 消息分组（如 loop/alt/opt） |

### 参与者图标（可选）

- 人类用户：标题栏上方可加人形剪影（用简单路径画头+肩）
- 系统/服务：标题栏上方加矩形或齿轮图标
- 数据库：标题栏上方加圆柱图标
- 简化处理：所有参与者统一用矩形标题栏，不画图标，靠名称区分

## 3. 坐标模板

### 3.1 基本布局

```
画布:       viewBox="0 0 680 H"
            H = 顶部留白(60) + 消息数 × 45 + 底部留白(40)
标题:       x=340, y=34 (居中)

参与者数:   通常 3-5 个，最多 6 个
参与者间距:  ≥120px (给消息标签留空间)
参与者 cx:  等间距分布在安全区 [120, 560] 内
  3 个:     cx=160/340/520
  4 个:     cx=130/300/470/... (间距 ~140, 4个略挤)
  5 个:     cx=110/250/390/530/... (间距 ~120, 极限)

标题栏:     y=50, 高 36, 宽 = 字数 × 7 + 24
生命线:     x=cx, y1=86 (标题栏底) → y2=H-30 (近底部)
激活条:     x=cx-5, width=10, 居中在生命线上
```

### 3.2 消息排列

```
消息 y 坐标: 从 y=120 开始, 每条消息间隔 45px
  消息1:     y=120
  消息2:     y=165
  消息3:     y=210
  ...
消息箭头:    水平线, y1=y2=消息y, x1=源cx, x2=目标cx
消息标签:    放在箭头上方, y=消息y-8, 居中于 (x1+x2)/2
```

### 3.3 激活条

激活条表示参与者在某段时间内活跃：

```
激活条 x:    参与者 cx - 5 (宽 10, 居中生命线)
激活条 y:    从该参与者收到消息的 y → 到它发出返回消息的 y
激活条 fill: 该参与者的色系 100 级
激活条 stroke: 该参与者的色系 600 级, 0.5px
```

不是每条生命线都要画激活条——只有明确需要表达"活跃时段"时才画。

## 4. 节点尺寸

| 元素 | 尺寸 |
|------|------|
| 参与者标题栏 | 高 36px，宽 `字数 × 7 + 24`，`rx="6"` |
| 生命线 | `stroke-dasharray="4 4"`，`stroke-width="1"` |
| 激活条 | 宽 10px，高 = 活跃时长（按消息间距算） |
| 消息箭头 | `stroke-width="1.5"` |
| 消息间距 | ≥45px（给标签留空间） |
| 参与者间距 | ≥120px |

**消息间距统一铁律**：所有消息间距必须相等（如统一 45px）。间距忽大忽小会让读者误以为时间间隔不同。

## 5. 箭头与连线

### 5.1 消息类型（UML 标准）

| 类型 | 线型 | 箭头 | 含义 |
|------|------|------|------|
| 同步调用 | 实线 | 实心三角 `▶` | 调用方等待返回 |
| 异步消息 | 实线 | 开放箭头 `>` | 调用方不等待 |
| 返回消息 | 虚线 | 开放箭头 `>` | 返回结果 |
| 创建消息 | 虚线 | 开放箭头 | 目标参与者被创建 |
| 删除消息 | 实线 | 实心三角 + 末端 × | 目标参与者被销毁 |

> 本技能的 `<defs>` 箭头标记是开放箭头样式，足以表达大多数场景。同步/异步的区别主要通过**线型**（实线/虚线）体现。

### 5.2 消息标签

- 标签放在箭头**上方**，距箭头 8px。
- 居中于箭头中点：`x = (x1 + x2) / 2`，`text-anchor="middle"`。
- 字号 12px，颜色 `#5F5E5A`。
- 标签内容 = 消息名/方法名，如 `login()`、`getUserInfo()`、`200 OK`。

### 5.3 自调用

参与者调用自身方法时，画一个小弧形从生命线出发回到自身：

```
M cx,y L cx+25,y L cx+25,y+18 L cx,y+18
（向右出发 25px → 向下 18px → 回到生命线）
marker-end="url(#arrow)"
```

### 5.4 生命线规则

- **笔直**——生命线是纯竖直线，不能弯折、不能倾斜。
- **贯穿**——从标题栏底延伸到图底，不能中途断开（除非有删除标记 ×）。
- **虚线**——`stroke-dasharray="4 4"`，`stroke-width="1"`，灰 400 `#888780`。
- **不交叉**——生命线之间平行，绝不交叉。

## 6. 配色策略

时序图配色极其克制，参与者可各一色但经典做法偏单色。

| 用法 | 色数 | 说明 |
|------|------|------|
| 纯单色 | 1 | 全图蓝系或灰系，最经典 |
| 参与者区分色 | 3-5 | 每个参与者一色系（标题栏 + 激活条），消息线统一灰 |
| 高亮关键消息 | 1+1 | 全图单色，关键消息用强调色 |

### 配色铁律

1. **消息箭头统一灰色** `#5F5E5A`——不要每条消息不同色，那会变成彩虹。
2. **参与者色系用于标题栏和激活条**——让读者快速识别"这条生命线是谁"。
3. **同参与者的标题栏和激活条同色系**——标题栏 50 填充 + 600 描边，激活条 100 填充 + 600 描边。
4. **生命线统一灰色** `#888780`——不跟参与者色。

## 7. 常见反例

1. **生命线弯折**——生命线必须笔直。任何弯折都是错的。
2. **消息箭头不水平**——倾斜的箭头让时间轴混乱。必须 `y1=y2`。
3. **时间顺序颠倒**——后面的消息画在前面之上。严格自上而下。
4. **消息间距不均**——忽大忽小，读者误以为时间间隔不同。统一 45px。
5. **激活条不闭合**——开始画了激活条但忘记结束。激活条必须有起有止。
6. **参与者间距太挤**——消息标签放不下，文字重叠。间距 ≥120px。
7. **消息标签压在箭头上**——标签和箭头线重叠。标签上移 8px。
8. **生命线交叉**——参与者顺序排错导致消息线大幅倾斜。调整参与者排列顺序。
9. **没有返回消息**——同步调用必须有返回（虚线箭头）。缺少返回 = 调用未闭合。
10. **自调用画成直线**——自调用必须画弧形，不能画成水平线返回自身。

## 8. 视觉优化进阶规则（实战经验）

> 以下规则来自一次时序图优化的实战复盘。基础规则（第 1-7 章）保证「画对」，本章节保证「画好」。**当基础规则与本章节冲突时，以本章节为准。**

### 8.1 激活条必须分段，不允许「贯穿式」

**问题**：默认渲染常把激活条从首次激活延伸到流程末尾，中间空闲等待时段也被填满，读者误以为系统持续工作。

**规则**：激活条严格按「收到消息 → 发出返回消息」分段。两次操作之间的空闲时段**不画激活条**。

```svg
<!-- 错：贯穿式（中间空闲也被填满） -->
<rect x="335" y="120" width="10" height="225" />

<!-- 对：分段，中间空闲留白 -->
<rect x="335" y="125" width="10" height="162" />  <!-- 第一次激活：处理 createPost -->
<rect x="335" y="329" width="10" height="42" />   <!-- 第二次激活：处理请求推荐 -->
```

### 8.2 自调用必须放大 + 包裹框

**问题**：默认自调用弧线只有 18px 高，又细又短，业务关键节点（如「敏感词检测」）反而视觉权重最弱，读者一扫而过。

**规则**：
- 自调用路径高度 ≥ 30px（推荐 32px）
- 业务关键自调用外加浅色虚线包裹框，框内含路径 + 标签
- 标签用参与色 + 字重 600，与普通消息标签区分

```svg
<!-- 包裹框：浅色背景 + 虚线边 -->
<rect x="cx+5" y="path_y-8" width="105" height="50" rx="4"
      fill="参与色" fill-opacity="0.08"
      stroke="参与色" stroke-width="0.6"
      stroke-dasharray="2 3" opacity="0.7"/>

<!-- 自调用路径（高度 32px，远大于默认 18px） -->
<path d="M cx,y L cx+40,y L cx+40,y+32 L cx+7,y+32"
      marker-end="url(#arrow)"/>
```

> 此规则升级第 5.3 节的「自调用画小弧形」——业务关键节点不能小。

### 8.3 流程末端必须加 × 终止符

**问题**：生命线虚线直接断在画布底部，读者困惑「流程是否结束？后面还有没有？」。

**规则**：所有参与者的生命线末端画一个淡色 ×（opacity 0.5-0.6），用各角色色，明确结束边界。

```svg
<g stroke-width="1.5" fill="none" opacity="0.55">
  <line x1="cx-5" y1="end_y-6" x2="cx+5" y2="end_y+6" stroke="角色色"/>
  <line x1="cx+5" y1="end_y-6" x2="cx-5" y2="end_y+6" stroke="角色色"/>
</g>
```

> 注：UML 中 × 严格含义是「对象销毁」。但在视觉表达层面，淡色 × 兼作「流程终点」的视觉锚点，不严格表示销毁。

### 8.4 标题层级差距 ≥ 4px

**问题**：标题 14px / 角色名 13px，差 1px，标题像「大一号的角色名」，层级建立失败。

**规则**：标题字号 - 角色名字号 ≥ 4px，且标题字重比角色名重一档。

| 元素 | 字号 | 字重 |
|------|------|------|
| 标题 | 16px | 600 |
| 角色名 | 12px | 500 |
| 消息标签 | 12px | 400 |

> 此规则升级第 4 章的「参与者标题栏字号」——原规则未约束标题与角色名的层级差。

### 8.5 生命线染色与角色绑定（推荐）

**问题**：角色框是彩色，生命线是统一灰色，读者要把「彩色框」和「灰色线」在脑里连起来，做了不必要的认知劳动。

**规则**：生命线用各角色色 50% 透明度的虚线，与角色框视觉绑定。

```svg
<!-- 替代原统一灰色 #888780 -->
<g stroke-width="1" stroke-dasharray="4 4" fill="none" opacity="0.5">
  <line x1="160" y1="88" x2="160" y2="400" stroke="#BA7517"/>  <!-- 用户色 -->
  <line x1="340" y1="88" x2="340" y2="400" stroke="#185FA5"/>  <!-- 客户端色 -->
  <line x1="520" y1="88" x2="520" y2="400" stroke="#0F6E56"/>  <!-- 服务端色 -->
</g>
```

> 此规则与第 6 章「生命线统一灰色 #888780」冲突。染色为**推荐做法**，统一灰色为**最低标准**，两者择一。

### 8.6 阶段分组填充左侧空白

**问题**：用户作为远端调用方，左侧大块空白，画面左右失衡；同时多个消息缺乏业务阶段归属感。

**规则**：当存在明确的业务阶段（如「发布 → 推荐」、「登录 → 鉴权 → 业务」），用浅色背景条 + 阶段标签横跨整图。

```svg
<rect x="40" y="100" width="600" height="190" fill="#F9FAFB" opacity="0.6"/>
<text x="52" y="116" font-size="11" fill="#6B7280" font-style="italic">① 发布阶段</text>

<rect x="40" y="295" width="600" height="90" fill="#F3F4F6" opacity="0.6"/>
<text x="52" y="311" font-size="11" fill="#6B7280" font-style="italic">② 推荐阶段</text>
```

### 8.7 箭头线加粗 + 加深

**问题**：1.5px + #5F5E5A 在浅色背景下对比度不够，快速扫视时容易漏掉箭头方向。

**规则**：消息箭头 `stroke-width="2"`，颜色 `#374151`（深灰）。

```svg
<g stroke="#374151" stroke-width="2" fill="none" stroke-linecap="round">
  <line x1="160" y1="125" x2="333" y2="125" marker-end="url(#arrow)"/>
</g>
```

> 此规则升级第 5 章的「消息箭头 stroke-width=1.5」和第 6 章「消息箭头统一灰色 #5F5E5A」。
