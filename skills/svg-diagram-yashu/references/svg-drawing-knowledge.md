## 1. SVG 渲染机制（不懂就会糊 / 会错位）

SVG 是**矢量 + 坐标系**格式，浏览器 / Edge 按坐标逐元素绘制。

- **坐标系**：原点在左上角，x 向右增大，y 向下增大。屏幕"上"= y 小，"下"= y 大（与数学笛卡尔相反，初学时最易搞反）。
- **viewBox**：`viewBox="minX minY w h"` 定义"用户坐标"范围；根 `<svg>` 写 `width="100%"` 让图随容器宽度等比缩放。本技能固定 `w = 680`，`h = H`（见 §2）。比例锁死，不会变形。
- **文字定位**：
  - `text-anchor="start | middle | end"` 控制文字在 x 上的对齐（`middle` = 以 x 为水平中心）。
  - `dominant-baseline="central"` 让 y 表示文字的**垂直中心**（不是基线）。配合它，双行框内两行文字用 `y = box_y + 22` 与 `box_y + 42` 即可垂直居中，换行不会被切。
  - **框内每个 `<text>` 都必须带 `dominant-baseline="central"`**，否则文字会沉到框底、甚至溢出。
- **填充 vs 描边**：`fill` 是填充色，`stroke` 是边框色，`stroke-width` 是线宽。
  - **连接线（箭头）必须 `fill="none"`**，否则连线会被当成闭合图形用 fill 颜色灌满，变成一条色块。
- **箭头 marker**（本技能 `<defs>` 里那段）：
  - `orient="auto-start-reverse"` 让箭头**自动朝向路径方向**（不用手算角度）。
  - `refX / refY` 是"箭头尖端"在 marker 小坐标系里的锚点（`refX = 8` 让尖端对准线尾）。
  - `markerWidth / markerHeight` 控制箭头大小（本技能 6×6）。
  - `stroke="context-stroke"` 是**关键**：让箭头颜色跟随连线自身的 `stroke` 颜色。若漏写，箭头会固定成黑色，与彩色连线脱节。
  - 在连线元素上写 `marker-end="url(#arrow)"` 才会显示箭头。
- **`<g>` 分组**：仅用于逻辑分组，不影响渲染；组内每个元素仍需各自设置 `fill / stroke`（SVG 不靠 CSS 继承，本技能强制每个图形显式设 `fill`）。
- **为什么强制扁平（无渐变 / 阴影 / 模糊 / 发光）**：一是风格统一；二是导出 PNG 用的 Edge 无头截图对滤镜支持不一，纯色最稳、跨环境一致。
- **为什么禁注释 / 禁旋转文字**：注释在 SVG 里虽非语法错误，但本规范禁用以保持文件纯净、避免被某些解析器误读；旋转文字在窄框里会溢出、且难以阅读。
- **字体兜底**：本技能字体栈为 `font-family="-apple-system, BlinkMacSystemFont, 'PingFang SC', sans-serif"`，不引入外部字体文件（无 @font-face / woff / ttf）。`-apple-system` 与 `BlinkMacSystemFont` 是浏览器调用系统 UI 字体的关键字，`PingFang SC` 是 Apple 系统预装中文字体（仅按名引用、不嵌入文件），`sans-serif` 作最终兜底——导出 PNG 的 Edge 环境未必装了某指定字体，系统字体栈 + sans-serif 兜底保证跨机一致，也不构成字体侵权。

## 2. 坐标几何计算（套公式，不靠猜）

所有坐标都可从少量输入推导。约定：画布安全区 `x ∈ [40, 640]`（宽 600），`viewBox` 宽固定 680。

### 2.1 框的尺寸与定位

- 框宽：`W = max(标题字符数 × 7, 副标题字符数 × 6) + 24`（`design-system.md` 公式）。
- 框高：单行 44，双行 56（本技能节点一律双行）。
- 已知中心 `cx` → 左缘 `x = cx − W / 2`。
- 已知左缘 `x` → 中心 `cx = x + W / 2`。
- 圆角 `rx = 8`；框间距 ≥ 60，框内文字距边 ≥ 12。

### 2.2 水平等分布局（n 个等宽框）

```
gap  = (600 − n × W) / (n + 1)
x_i  = 40 + gap + (i − 1) × (W + gap)     // i = 1..n
cx_i = x_i + W / 2
```

例：n = 3，W = 150 → gap = (600 − 450) / 4 = 37.5 → x = 77.5 / 265 / 452.5（中心 152.5 / 340 / 527.5）。

本技能架构图常用**三列右移版**（给左侧 tier 标签留列）：`x = 120 / 300 / 480`（中心 195 / 375 / 555），即整体右移约 42px，左列 `x ∈ [40, 110]` 放层级名。

### 2.3 viewBox 高度 H

`H = 最底部元素底边 y + 20`。**绝不手填**，先排完所有元素再取最大值 + 20。

例：4 层架构底框底边 496，若加底部闭环基线 540 → 取 540 → `H = 560`。

### 2.4 箭头端点

- 源框底边中点：`(cx_src, y_src_bottom)`（`y_src_bottom = 源框 y + 56`）。
- 目标框顶边中点：`(cx_dst, y_dst_top)`（`y_dst_top = 目标框 y`）。
- **收敛（多 → 1）**：各源 `cx_src` → 目标顶边的分散点 `cx_dst ± offset`（offset ≈ 目标框半宽 × 0.4，避免箭头全挤在一点）。
- **发散（1 → 多）**：源底边 `cx_src` → 各目标 `cx_dst`。
- 连线一律 `<line x1 y1 x2 y2>`，`stroke` 用灰 600，`marker-end="url(#arrow)"`。

### 2.5 闭环路径（数据反哺 / 反馈环）

从末节点底边中点出发，绕到图外再回到首节点底边，用虚线：

```
M cx_last,by  L 660,by  L 660,loop_y  L 20,loop_y  L 20,ty  L cx_first,ty
fill="none" stroke="强调色600" stroke-dasharray="5 4" marker-end="url(#arrow)"
```

（`by` = 层底边，`ty` = 层顶边，`loop_y` = 底部基线如 540；竖直段在 x = 20 / 660，落在所有框之外，不会压到节点。）作用：表达"输出回流到上游"的循环依赖，是让架构图"不简单"的利器。

### 2.6 标准 4 层架构坐标模板（直接套用）

```
标题:        y=34 (居中 x=340)
层级标签列:  x=44, 各层中心 y (见下)
节点框宽 W=150, 三列 x=120/300/480, 中心 cx=195/375/555
层1 y=70   (70..126)    层2 y=200  (200..256)
层3 y=320  (320..376)   层4 y=440  (440..496)
若加闭环:   loop_y=540  →  H=560

箭头:
  层1→层2: (195,126)->(300,200) / (375,126)->(340,200) / (555,126)->(380,200)
  层2→层3: (340,256)->(195,320) / (340,256)->(375,320) / (340,256)->(555,320)
  层3→层4: (195,376)->(195,440) / (375,376)->(375,440) / (555,376)->(555,440)
闭环(虚线): M555,376 L660,376 L660,540 L20,540 L20,376 L195,376
```

（除 `example-architecture.svg` 外，可直接用此模板起手，只改文案与色系。）

## 3. 配色判断（专业规则）

调色板本身见 `design-system.md`（9 色系 × 7 级，色值已定；**所有颜色必须从表中取，禁止凭直觉写 `#3b82f6` 之类**）。这里规定"怎么用"。

### 3.1 配色原则

- **色系数 = 需要区分的、有真实含义的类别数。** 颜色是「分类编码」或「强调高亮」的工具，不是装饰。每多一个色系都要能回答「它区分了什么有意义的信息」；答不上来就不加。

### 3.2 怎么决定用几个色系（按图型）

- **通用起点**：能单色就单色。需要拉开「主体 vs 关键」时，加 1 个强调色（暖色高亮枢纽 / 异常 / 关键路径）。
- **靠颜色分类的图——色数 = 类别数，自然可多**：
  - 架构图：按层或子系统分组，一组一色（通常 3–6，看实际分组数）。
  - 思维导图：一主分支一色，子节点用该色系更浅级；色数 = 主分支数（常见 5–8，无硬上限）。
  - 循环图：每一阶段一色，色数 = 阶段节点数（通常 4–6）。
  - 鱼骨图：每一肋（原因类别）一色，色数 = 肋数（通常 4–6）。
  - 组织架构图：按部门着色或仅高亮某一支；色数 = 部门数。
  - 2×2 矩阵：四象限各一浅色，或仅高亮重点象限（2–4）。
- **靠形状 / 位置表意的图——颜色只作配角，保持克制**：
  - 流程图：形状已表意（矩形=步骤、菱形=判断），颜色只高亮关键路径，1–2 色。
  - 时序图：参与者可各着一色区分，经典做法单色；参与者多时可到 4–5。
  - 中心辐射图：中心强调色 + 外围同色即可，1–3 色。
  - 时间线：按阶段 / 类别着色，1–4 色。
- **同组内区分**：用「同一色系的 50 / 100 / 200 明度差」代层次，**不引入新色系**（比加新色更高级、更不易花）。

### 3.3 取色铁律（与色数无关，必须遵守）

1. 节点取色：50 级填充 + 600 级描边；**标题文字统一 `#1f2937`、副标题 `#5F5E5A`**（跨色系对比都最高、最稳）。
2. 连线 / 箭头：常规流向用灰 600 `#5F5E5A`；强调闭环用其强调色系 600 级（如 teal `#0F6E56`）。
3. 禁用设计系统 9 色系以外的任何颜色。

### 3.4 为什么这套规则专业

- **色数跟着含义走**，既不浪费也不贫乏，杜绝"彩虹图"噪音。
- **冷暖对比**让"主体 vs 高亮"一眼可分，无需读字。
- **单一深色标题**保证任何填充背景下都清晰可读，杜绝低对比事故。
- **明度差代层次**比"加新色"更高级、更不容易花。

> 结论：`example-architecture.svg` 按"子系统分组"用了 3 色，符合「一分组一色」原则，**无需修改**。色数由图要表达的类别决定。
