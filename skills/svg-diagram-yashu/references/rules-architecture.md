# 架构图 · 专属视觉规则

> 本文件是架构图（architecture diagram）的专属视觉规则。绘制架构图时，除遵守 `design-system.md`（硬约束）和 `svg-drawing-knowledge.md`（通用机制）外，**必须**遵守本文件。
>
> 架构图表达「系统由哪些组件组成、组件之间如何交互」。它不像流程图那样描述过程步骤，而是描述**静态结构**。

---

## 1. 视觉特征

架构图的核心视觉语法是三个字：**层、流、组**。

- **层**——分层架构用色带或左侧层级标签明确标出每一层（接入层 / 服务层 / 数据层…），让读者一眼看出职责分层。
- **流**——箭头表达依赖方向或数据流向，方向必须一致（通常自上而下或从左到右），禁止同图混用两种主方向。
- **组**——同层/同子系统的组件用同一色系，跨层/跨子系统换色系。颜色是分组编码，不是装饰。

### 两类布局

| 布局 | 适用场景 | 主方向 |
|------|----------|--------|
| 分层架构 | 系统有清晰的职责分层（接入/业务/数据/基础设施） | 自上而下 |
| 横向流水线 | 沿一条调用链串联少数组件（客户端→网关→服务） | 从左到右 |

不要把两类布局混用。分层架构就老老实实分 3-5 层；横向流水线就 3-5 个组件一字排开。

---

## 2. 形状语义

架构图**不靠形状区分语义**（那是流程图的职责），主要靠颜色和位置分组。但以下形状有约定俗成的含义，需要遵守：

| 形状 | 含义 | 备注 |
|------|------|------|
| 圆角矩形 | 组件 / 服务 / 模块 | **默认选择**，绝大多数节点用它 |
| 圆柱形 | 数据库 / 持久化存储 | 用 `<rect>` + 顶部 `<ellipse>` 拼合 |
| 虚线矩形 | 外部系统 / 可选组件 / 待建设 | `stroke-dasharray` |
| 双线矩形 | 系统边界 / 信任边界 | 外层加一圈描边 |
| 六边形 | 队列 / 缓存 / 异步中间件 | 可选，非强制 |

> 反例：不要用菱形（那是流程图的判断节点）、不要用椭圆（那是流程图的起止节点）。

## 3. 坐标模板

### 3.1 分层架构（4 层标准模板）

直接套用，只改文案与色系：

```
画布:       viewBox="0 0 680 560", H=560
标题:       x=340, y=34 (居中)
层级标签列: x=42, text-anchor="start", 字号 12
节点框宽:   W=150, 三列 x=130/310/490, cx=200/380/560
层1 y=70   (70..126)    接入层
层2 y=200  (200..256)    业务层
层3 y=320  (320..376)    服务层
层4 y=440  (440..496)    数据层
闭环基线:  loop_y=540 →  H=560

层间箭头(单向实线):
  层1→层2: (200,126)→(200,200) / (380,126)→(380,200) / (560,126)→(560,200)
  层2→层3: 同上 y 换成 256→320
  层3→层4: 同上 y 换成 376→440

反馈闭环(虚线, 强调色):
  M cx_last,496 L 655,496 L 655,540 L 30,540 L 30,320 L cx_first,320
  (从最底层最右节点底部 → 绕外圈 → 回到第3层最左节点顶部)
```

3 层时去掉一层、调整 y 即可；5 层时把 y 间距压缩到 110px。

### 3.2 横向流水线（3-5 组件）

```
画布:       viewBox="0 0 680 300", H = 最底元素 y + 60
标题:       x=340, y=40 (居中)
节点框宽:   W=150, 等间距排列
  3 组件:   x=55/265/475 (gap=60),  cx=130/340/550
  4 组件:   x=40/215/390/565 (gap=25), cx=115/290/465/640 — 紧凑
  5 组件:   建议改用分层架构，横向太挤

节点 y:     y=110, 高 80 (双行+留白), cy=150
连线(双向):
  上行请求: y=135, 从左框右边 → 右框左边
  下行返回: y=165, 从右框左边 → 左框右边
  两线间距: 固定 30px, 全图统一
```

> 横向流水线的双向通道必须用**两条分开的单向箭头**（上行一条、下行一条），不要用一根双向箭头——分开画才能各自标注。

---

## 4. 节点尺寸

| 节点类型 | 高度 | 宽度 |
|----------|------|------|
| 双行节点（标题+副标题） | 56px | `max(标题字数×7, 副标题字数×6) + 24`，标准 150 |
| 单行节点 | 44px | 同上 |
| 数据库（圆柱） | 56px | 同上，顶部椭圆高 12px |

**铁律：同一层的所有节点必须等高。** 不同层可以不同高（如接入层单行 44px，业务层双行 56px），但同层必须一致——这是架构图最容易被挑刺的视觉问题。

---

## 5. 箭头与连线

### 5.1 分层架构

- **层间调用**：单向实线箭头，灰 600 `#5F5E5A`，`stroke-width="1.5"`。
- **反馈闭环**：虚线，强调色 600（如 teal `#0F6E56`），`stroke-dasharray="5 4"`，绕外圈走。
- **同层内调用**：可用水平实线箭头，但要谨慎——同层连线多了会让图变乱。

### 5.2 横向流水线

- **双向通道**：上行（请求）+ 下行（返回）两条平行单向箭头，间距**固定 30px**，全图所有通道必须一致。
- **箭头方向**：上行从左到右，下行从右到左。

### 5.3 连线标签（关键，最易翻车）

- 标签**水平偏移 +6px** 到线条一侧（`x = cx + 6`, `text-anchor="start"`），**绝不**把文字压在线条正上方。
- 多字标签内部用空格分隔节奏：`录 入`、`生 成 提 纲`，提升可读性。
- 标签字号 12px（caption），颜色 hint `#888780`，不抢主文本的戏。
- 标签 y 坐标 = 连线中点 y，`dominant-baseline="central"`。

## 6. 配色策略

架构图按**子系统/层级**分组着色，一组一色系。

| 层级示例 | 推荐色系 | 50 填充 | 600 描边 |
|----------|----------|---------|----------|
| 接入层 / 前端 | blue | `#E6F1FB` | `#185FA5` |
| 业务层 / 应用 | amber | `#FAEEDA` | `#BA7517` |
| 服务层 / 智能 | purple | `#EEEDFE` | `#534AB7` |
| 数据层 / 基础设施 | teal | `#E1F5EE` | `#0F6E56` |
| 外部系统 / 第三方 | gray | `#F1EFE8` | `#5F5E5A` |
| 高危 / 告警 | red | `#FCEBEB` | `#A32D2D` |

- **色数 = 有意义的分组数**，通常 3-5 色。不要为了好看加色。
- **闭环虚线**用与其反哺目标层同色系的 600 级，或用 teal 强调。
- **标题文字统一 `#1f2937`、副标题 `#5F5E5A`**（跨色系对比都最高）。

## 7. 常见反例

以下视觉问题必须避免（按出现频率排序）：

1. **同层节点高度不一**——最常见。绘制前先定 `y` 和 `height`，全层复制。
2. **连线文字压线**——文字直接叠加在箭线上。必须水平偏移 +6px。
3. **双向平行线间距不一**——横向流水线各通道间距肉眼不等。统一 30px。
4. **没有层级标签**——分层架构必须在左侧标出层名，否则读者不知道每层代表什么。
5. **整体偏下、留白失衡**——`viewBox` 高度算错，底部大段空白。`H = 最底元素 y + 20`，有闭环时闭环填底。
6. **同层节点用不同色系**——破坏分组感。同层必须同色。
7. **箭头方向不一致**——有的层间箭头向下、有的向斜，混搭。统一垂直或统一水平。
8. **连线穿过节点框**——箭头端点必须落在框边缘，不能落在框内部或穿过框。
