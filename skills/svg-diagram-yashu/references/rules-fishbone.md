# 鱼骨图 · 专属视觉规则

> 本文件是鱼骨图 / 因果分析图（fishbone diagram / Ishikawa diagram）的专属视觉规则。绘制鱼骨图时，除遵守 `design-system.md` 和 `svg-drawing-knowledge.md` 外，**必须**遵守本文件。
>
> 鱼骨图表达「一个问题由多个原因类别导致，每个类别下有具体子原因」。它靠**中央主干线**指向右侧"鱼头"（问题），**斜肋**从主干分叉代表原因类别，**子原因**挂在斜肋上。经典应用包括 6M 分析（人/机/料/法/环/测）、5-Why 分析、生产质量问题归因。

---

## 1. 视觉特征

鱼骨图的核心视觉语法是三个字：**干、肋、因**。

- **干**——中央水平主干线从左贯穿到右，右端指向"鱼头"（问题方框）。主干是全图的视觉脊梁。
- **肋**——4-6 条斜肋从主干上下交替分叉出去，每条肋代表一个原因类别（如"人员/设备/材料/方法/环境/测量"）。斜肋的角度统一（通常 60°）。
- **因**——每条肋上挂 2-3 条虚线子原因，子原因用文字标注，代表具体的原因细节。

### 鱼骨图的视觉隐喻

整张图看起来像一条鱼：
- 鱼头 = 问题（右侧大方框）
- 鱼脊 = 主干线（水平）
- 鱼刺 = 斜肋 + 子原因（上下交替）
- 鱼尾 = 主干线左端（可加箭头表示"原因来源"）

---

## 2. 形状语义

| 元素 | 形状 | 含义 |
|------|------|------|
| 鱼头（问题） | 矩形（右侧） | 待分析的问题/结果，位于主干右端 |
| 主干线 | 水平实线 | 因果关系的脊梁，从左到右指向问题 |
| 斜肋 | 斜线（60°） | 原因类别（如"人员"、"设备"） |
| 肋标签 | 文字（斜肋末端） | 原因类别名称 |
| 子原因 | 虚线 + 文字 | 具体原因，挂在斜肋上 |
| 鱼尾箭头 | 主干左端箭头（可选） | 表示原因从左侧汇聚 |

鱼骨图**不用圆角矩形节点框**（除了鱼头）——原因类别和子原因都用**文字 + 线条**表达，这是鱼骨图区别于其他图的视觉特征。

## 3. 坐标模板

### 3.1 标准鱼骨布局（6 类别，上下各 3）

```
画布:       viewBox="0 0 680 480"
标题:       x=340, y=34 (居中)

鱼头:       x=560, y=220, 宽 100, 高 60, rx=8
            (右侧居中, 写问题名称)

主干线:     x1=80 → x2=560 (鱼头左边), y=250
            stroke-width="2", 灰 600

斜肋角度:   60° (统一)
斜肋长度:   120px

上侧斜肋 (3条, 从主干向上分叉):
  肋1: 起点 (180, 250) → 终点 (180-60, 250-104) = (120, 146)
       (60° 斜线: 水平分量 60, 垂直分量 104)
  肋2: 起点 (300, 250) → 终点 (240, 146)
  肋3: 起点 (420, 250) → 终点 (360, 146)

下侧斜肋 (3条, 从主干向下分叉):
  肋4: 起点 (180, 250) → 终点 (120, 354)
  肋5: 起点 (300, 250) → 终点 (240, 354)
  肋6: 起点 (420, 250) → 终点 (360, 354)
```

### 3.2 斜肋通用公式

设主干 y = Y_main，肋在主干上的分叉点 x = X_rib：

```
60° 斜肋:
  上侧: 终点 = (X_rib - 60, Y_main - 104)
  下侧: 终点 = (X_rib - 60, Y_main + 104)

(60° 角: cos60°=0.5, sin60°=0.866; 长 120 → 水平 60, 垂直 104)
```

### 3.3 子原因挂法

每条斜肋上挂 2-3 个子原因，子原因用**水平虚线**从斜肋延伸出去：

```
子原因线:   从斜肋中点附近, 水平延伸 40px
  上侧肋的子因: 水平线向右延伸 (朝鱼头方向)
  下侧肋的子因: 水平线向右延伸 (朝鱼头方向)

子原因位置 (沿斜肋均匀分布):
  肋长 120px, 挂 3 个子因, 间距 40px:
  子因1: 距肋起点 30px 处
  子因2: 距肋起点 70px 处
  子因3: 距肋起点 110px 处 (近肋末端)

子因文字:   放在水平虚线末端, 字号 11, 颜色 #5F5E5A
```

### 3.4 4 类别布局（上下各 2）

如果只用 4 个原因类别（如"人/机/料/法"），上下各 2 条：

```
上侧: 肋1 (x=220), 肋2 (x=400)
下侧: 肋3 (x=220), 肋4 (x=400)
斜肋长度可加大到 140px (类别少时肋可更长, 给子因更多空间)
```

## 4. 节点尺寸

| 元素 | 尺寸 |
|------|------|
| 鱼头方框 | 100 × 60px，`rx="8"`，问题文字 13px/500 |
| 主干线 | `stroke-width="2"`，灰 600 |
| 斜肋 | 长 120px，`stroke-width="1.5"`，该类别色系 600 |
| 子原因虚线 | 长 40px，`stroke-dasharray="3 3"`，灰 400 |
| 肋标签 | 字号 13px / 500，该色系 800 |
| 子原因文字 | 字号 11px / 400，灰 600 `#5F5E5A` |
| 标题 | 字号 14px / 500 |

**斜肋角度统一铁律**：所有斜肋角度必须一致（统一 60°）。角度不一 = 鱼骨变形。

## 5. 箭头与连线

### 5.1 主干线

- **水平实线**，从左到右，灰 600 `#5F5E5A`，`stroke-width="2"`。
- **两端都不画箭头**——主干线只保留纯水平实线，不依赖箭头表达流向。右端直接连到鱼头方框左边（方框本身就是"问题"），左端也不加箭头。原因汇聚关系通过"子原因→斜肋→主干"的层级结构表达，不需要箭头辅助。

### 5.2 斜肋

- **斜线实线**，60° 角，`stroke-width="1.5"`，该类别色系 600 级。
- **无箭头**——斜肋表达"这个类别是原因之一"，不表达流向。
- 斜肋从主干分叉点出发，向左上或左下延伸（朝鱼尾方向）。

### 5.3 子原因虚线

- **水平虚线**，从斜肋延伸出去，`stroke-dasharray="3 3"`，灰 400 `#888780`，`stroke-width="1"`。
- **无箭头**——子原因用文字标注，虚线只表"挂在某肋上"。
- 虚线水平延伸 40px，文字放在虚线末端。
- **全图统一 dasharray 铁律**——所有子原因虚线的 `stroke-dasharray` 必须完全一致（统一 `"3 3"`）。禁止出现部分 `"3 3"`、部分 `"4 2"`、部分 `"2 4"` 等不一致的虚线节奏，否则视觉上会显得参差不齐。

### 5.4 禁止样式

- **禁止斜肋用箭头**——斜肋无箭头。
- **禁止子原因用实线**——子原因必须虚线，与斜肋区分。
- **禁止斜肋角度不一**——全图统一 60°。
- **禁止子原因挂在主干上**——子因必须挂在斜肋上，不能直接挂主干。

## 6. 配色策略

鱼骨图配色遵循"**结构优先、色彩克制**"原则。**默认采用统一中性灰模式**（见 6.4），多色版仅作为可选变体——除非明确需要类别对照，否则一律用中性灰。

### 6.1 多色版配色（可选变体）

| 6M 类别 | 中文 | 推荐色系 | 600 描边 | 800 文字 |
|---------|------|----------|----------|----------|
| Man | 人 | blue | `#185FA5` | `#0C447C` |
| Machine | 机 | teal | `#0F6E56` | `#085041` |
| Material | 料 | amber | `#BA7517` | `#633806` |
| Method | 法 | purple | `#534AB7` | `#3C3489` |
| Environment | 环 | green | `#3B6D11` | `#27500A` |
| Measurement | 测 | coral | `#993C1D` | `#712B13` |

### 6.2 配色铁律

1. **默认中性灰、多色可选**——除非明确需要类别对照，否则一律用 6.4 的中性灰模式。仅在需要"快速对照类别"的汇报场景才用多色版。
2. **多色版色数 = 肋数**——4 肋 4 色，6 肋 6 色。
3. **多色版每肋独立色系**——斜肋 + 肋标签共用该色系。
4. **主干统一灰色**——主干不跟肋色，用灰 600。
5. **子原因统一灰色**——子因虚线和文字用灰，不跟肋色（即使多色版也如此，避免色彩过载）。
6. **鱼头用中性色或红色**——鱼头是"问题"，可用 gray 50 或 red 50（如问题是负面事件）。

### 6.3 鱼头配色

- 默认：gray 50 填充 `#F1EFE8` + gray 600 描边 `#5F5E5A` + gray 800 文字 `#444441`。
- 问题为负面事件（如"质量缺陷"）：red 50 填充 `#FCEBEB` + red 600 描边 `#A32D2D` + red 800 文字 `#791F1F`。

### 6.4 统一中性灰模式（默认推荐）

斜肋、肋标签、子原因虚线、子原因文字**全部使用中性灰**，不按类别分色：

| 元素 | 描边色 | 文字色 |
|------|--------|--------|
| 主干线 | 灰 600 `#5F5E5A` | — |
| 斜肋 | 灰 600 `#5F5E5A` | — |
| 肋标签 | — | 灰 800 `#444441` |
| 子原因虚线 | 灰 400 `#888780` | — |
| 子原因文字 | — | 灰 600 `#5F5E5A` |
| 鱼头 | 见 6.3 | 见 6.3 |

**为什么默认中性灰**：鱼骨图的核心信息是"层级结构"（主干→斜肋→子原因），不是"类别区分"。统一灰色让读者聚焦结构本身，避免 6 种颜色同时刺激视觉造成的信息过载。多色版只在需要"快速对照类别"的汇报场景使用。

## 7. 常见反例

1. **斜肋角度不一**——有的 45°、有的 60°、有的 30°。全图统一 60°。
2. **子原因挂错肋**——子因虚线起点没落在斜肋上。精确计算挂点。
3. **鱼头位置偏**——鱼头不在主干右端正对位置。鱼头左边 = 主干右端 x。
4. **斜肋用箭头**——斜肋无箭头，箭头会让"类别"变成"动作"。
5. **子原因用实线**——实线与斜肋混淆。子因必须虚线。
6. **主干不水平**——主干弯折或倾斜。必须纯水平。
7. **肋标签位置乱**——标签没在斜肋末端。标签紧贴肋末端外侧。
8. **子原因文字压在斜肋上**——文字和斜肋重叠。文字放在虚线水平末端。
9. **类别数过多**——超过 6 条肋画面太挤。控制在 4-6 条。
10. **上下肋不对称**——上侧 4 条、下侧 2 条。尽量上下均衡分布。
11. **子原因直接挂主干**——子因必须挂斜肋，不能跳过肋直接挂主干。
12. **主干线带箭头**——主干两端都不画箭头，只保留纯水平实线。箭头会让"结构关系"变成"流向动作"，破坏鱼骨图的层级语义。
13. **子原因虚线 dasharray 不一致**——全图所有子原因虚线的 `stroke-dasharray` 必须统一为 `"3 3"`，禁止出现 `"4 2"`、`"2 4"` 等不同节奏。
14. **未经声明使用多色版**——默认采用统一中性灰模式（见 6.4）。如需多色版，需明确理由（如汇报场景需要快速类别对照）。
