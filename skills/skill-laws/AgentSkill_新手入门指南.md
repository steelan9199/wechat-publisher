## 1. 什么是 Agent Skill？

Agent Skill（智能体技能）是一种轻量级、开放的格式，用于扩展 AI 智能体的能力，让它们具备专业的知识和工作流程。

简单来说，一个 **Agent Skill 就是一个文件夹**，里面包含一个名为 `SKILL.md` 的文件。这个文件包含了元数据（如名称、描述）和指令，告诉智能体如何执行特定的任务。技能文件夹里还可以包含脚本、参考资料、模板和其他资源。

**核心思想：** 你可以把 Agent Skill 看作是给 AI 智能体准备的“说明书”和“工具箱”。通过它，你可以让原本通用的 AI 变得擅长处理特定领域的任务，比如处理法律文档、分析财务数据、或者格式化 PPT。

**官方定义来源：** 这种格式最初由 Anthropic 开发，并作为开放标准发布，现已被许多 AI 产品采用。

---

## 2. 为什么需要 Agent Skill？

尽管现在的 AI 智能体已经非常强大，但它们通常缺乏完成特定领域实际工作所需的上下文和专业知识。Agent Skill 通过将以下内容打包成可移植的、受版本控制的文件夹来解决这个问题：

-   **领域专业知识 (Domain Expertise)**：将专业知识（例如，法律审查流程、数据分析管道、演示文稿格式化规则）捕获为可重用的说明和资源。
-   **可重复的工作流 (Repeatable Workflows)**：将多步骤任务转化为一致、可审计的流程。
-   **跨产品复用 (Cross-product Reuse)**：构建一次 Skill，即可在任何支持 Agent Skill 标准的智能体产品中使用。

**举例：** 如果你有一个专门帮你审阅合同的人工智能助手，你可以把合同审查的步骤、关键条款清单、以及常见的法律风险点做成一个 Agent Skill。这样，任何一个支持 Agent Skill 的 AI 工具都能瞬间学会审阅合同。

## 3. Agent Skill 是如何工作的？

智能体通过 **渐进式披露** 的方式加载 Skill，整个过程分为三个阶段：

1.  **发现 (Discovery)**：
    *   **发生了什么：** 在智能体启动时，它只会加载每个可用 Skill 的 **名称 (name)** 和 **描述 (description)**。
    *   **为什么这样做：** 这样做的目的是让智能体只需要极小的上下文就能知道某个 Skill 可能在什么时候有用。
    *   **类比：** 就像你在图书馆的目录卡片上扫一眼书名和简介。

2.  **激活 (Activation)**：
    *   **发生了什么：** 当一个任务匹配了某个 Skill 的 `description` 时，智能体会读取完整的 `SKILL.md` 指令。
    *   **这是关键点：** `description` 写得是否精准，直接决定了智能体是否会在正确的时机调用这个 Skill。
    *   **类比：** 就像你找到了那本书，翻开了目录页，看到了章节结构。

3.  **执行 (Execution)**：
    *   **发生了什么：** 智能体会按照 `SKILL.md` 中的指令一步步执行，并根据需要执行 `scripts/` 中的代码或读取 `references/` 中的参考资料。
    *   **类比：** 你开始仔细阅读具体章节，并按照书中的步骤进行操作。

**优势：** 由于完整的指令只在需要时才加载，所以智能体可以同时“携带”很多 Skill，而不会占用过多的上下文空间。

## 4.  Agent Skill 的核心结构

### 4.1 文件夹结构

一个典型的 Skill 目录结构如下：

```
my-skill/                   <!-- Skill 的根目录 -->
├── SKILL.md                <!-- 必需：元数据 + 核心指令 -->
├── scripts/                <!-- 可选：可执行脚本 (如 Python, Bash 等) -->
├── references/             <!-- 可选：详细参考资料 -->
│   ├── REFERENCE.md        <!-- 技术参考文档 -->
│   └── FORMS.md            <!-- 表单模板或数据结构 -->
├── assets/                 <!-- 可选：静态资源 -->
│   ├── template.docx       <!-- 文档模板 -->
│   └── schema.json         <!-- 数据模式 -->
├── LICENSE.txt             <!-- 可选：许可证文件 -->
└── README.md               <!-- 可选：人类阅读的说明 (不参与智能体加载) -->
```

### 4.2 核心文件 SKILL.md

`SKILL.md` 是每个 Agent Skill **必须** 包含的文件。它由两部分组成：**前置元数据 (Frontmatter)** 和 **主体内容 (Body)**。

#### 4.2.1 前置元数据 (Frontmatter)

元数据位于文件顶部，使用 YAML 格式（在两个 `---` 之间），定义了 Skill 的基本属性。

**必填字段：**
*   `name`：Skill 的名称。例如：`合同审查助手`、`PDF 提取工具`。必须独特且易读。

**推荐字段：**
*   `description`：这是最重要的字段。智能体在发现阶段只看到这个名字和这段描述。
    *   **写法要点：** 具体说明这个 Skill 能做什么，以及 **何时** 应该使用它。
    *   **反面教材：** `description: 帮助处理 PDF。` （太笼统，智能体不知道啥时候该用它）
    *   **正面教材：** `description: 从 PDF 文件中提取文本和表格，填写表单，合并多个 PDF。当用户提到“PDF”、“文档提取”或“表单填写”时使用。`
*   `version`：版本号，建议遵循语义化版本（如 `1.0.0`）。

**可选字段：**
*   `compatibility`：兼容性说明。例如：`compatibility: 需要 Python 3.8+`。
*   `allowed-tools`：预先批准的可以运行的工具列表。例如：`allowed-tools: Bash(git:*) Read`。这是一个实验性功能，支持度取决于具体的 Agent 实现。

**示例 Frontmatter：**

```yaml
---
name: 法律合同审查助手
description: 审查法律合同，找出常见风险点，并提供修改建议。当用户提到“审阅合同”、“检查条款”或“法律建议”时使用。
version: "1.2.0"
compatibility: 需要 Python 3.8+，支持 pypdf2
---
```

#### 4.2.2 主体内容 (Body)

前置元数据之后的部分是 Markdown 格式的指令。这里没有严格的格式限制，写什么由你决定，只要能有效帮助智能体完成任务即可。

**推荐的内容结构：**

1.  **概述 (Overview)**：简要说明 Skill 的用途。
2.  **步骤 (Steps)**：详细的、分步的操作指南。
    *   示例：
        ```markdown
        1. 首先，检查文件类型。
        2. 然后，使用 OCR 识别文字。
        3. 最后，提取条款并归类。
        ```
3.  **输入/输出示例 (Examples)**：展示典型的输入和期望的输出。
4.  **边界情况 (Edge Cases)**：列出常见的异常情况及处理方法。

## 5. 编写 SKILL.md 的最佳实践

编写一个好的 Agent Skill 需要遵循一些核心原则，以确保智能体能真正理解并高效使用它。

### 5.1 名称 (name)

*   **简短直接**：使用清晰的名称，如 `Excel 数据清洗助手`。
*   **避免歧义**：不要使用模糊或重复的名称。
*   **中文友好**：如果你的 Skill 主要面向中文用户，建议使用中文命名。

### 5.2 描述 (description)

这是智能体**唯一**在启动时看到的关于 Skill 的信息。你的所有“引流”努力都必须体现在这里。

*   **三个要素：** `能力` + `触发条件` + `具体动作`。
    *   **能力**：这个 Skill 能做什么？（例如：分析文本、提取数据、生成代码）
    *   **触发条件**：什么情况下应该调用它？（例如：当用户提到“数据统计”时；当用户上传了 CSV 文件时）
    *   **具体动作**：它会生成什么结果？（例如：生成统计图表、给出改进建议）

**模板：**
`用于 [做什么]。当用户 [提到/需要/遇到] [什么场景] 时使用。使用后 [产出什么结果]。`

**对比：**

*   ❌ **差：** `处理 PDF 文件。`
*   ✅ **好：** `提取 PDF 中的文字和表格。当用户需要将 PDF 内容转换为可编辑文本，或者需要从扫描件中提取数据时使用。最终输出纯文本或 JSON 格式的数据。`

### 5.3 指令 (Body)

*   **清晰、逻辑性强**：使用编号列表或分步说明，避免歧义。
*   **假设明确**：假设智能体知道什么是 Python，什么是 JSON，但不要假设它知道你的公司内部流程或特定的 API 调用细节。
*   **包含示例**：在指令中加入 Input/Output 的示例。智能体很擅长“模仿”。
*   **处理错误**：如果某个步骤容易出错，请明确说明如何处理。例如：“如果网络超时，等待 5 秒后重试。”

### 5.4 文件引用

当你的指令很长时，不要全部塞在 `SKILL.md` 里。把详细的参考文档移到 `references/` 目录下，然后在 `SKILL.md` 中引用它们。

**语法：**
```markdown
详细的技术规范请参考 [参考手册](references/SPEC.md)。

数据格式定义请参考 [数据字典](references/DATA_DICT.md)。
```

**注意：** 保持引用路径简短，尽量从 `SKILL.md` 直接指向一层目录下的文件，不要嵌套太深。

## 6. 高级特性与规范

### 6.1 渐进式披露 (Progressive Disclosure)

这是 Agent Skill 的核心理念：**不要把所有东西都放在一个文件里**。

*   **Metadata**：智能体在启动时只加载 (~100 tokens)
*   **Instructions**：完整加载 (~5000 tokens 推荐上限)
*   **Resources**：按需加载 (例如，`scripts/`, `references/`, `assets/`)
    *   每次加载都会消耗上下文，所以保持这些文件“小而美”。

**最佳实践：** 将超过 500 行的详细技术文档拆分为独立的 Markdown 文件，放在 `references/` 中。

### 6.2 兼容性 (Compatibility)

如果你的 Skill 对运行环境有特殊要求（如必须安装特定版本的 Python、需要访问互联网、需要 Docker 环境），请务必在 `compatibility` 字段中明确说明。这有助于智能体提前判断是否能运行该 Skill。

**示例：**
```yaml
compatibility: 需要 Node.js 18+ 和 npm
```

### 6.3 允许的工具 (allowed-tools)

这是一个 **实验性** 功能，允许你预先定义哪些工具（Tool）是这个 Skill 专用的。这对于安全隔离或权限控制非常重要。

**示例：**
```yaml
allowed-tools: Bash(jq:*) Read
```

## 7. 验证你的 Skill

在发布之前，使用官方的验证工具来确保你的 Skill 结构正确，符合规范。

你可以使用 `skills-ref` 工具来验证：

```bash
skills-ref validate ./my-skill
```

**验证内容：**
1.  `SKILL.md` 的 Frontmatter 是否有效？
2.  字段名是否符合规范？
3.  文件是否存在且格式正确？

---

## 8. 总结

Agent Skill 是一种强大而灵活的机制，它让 AI 具备了“可插拔”的专业能力。通过遵循以下原则，你可以编写出高质量、易于维护的 Skill：

1.  **精准的描述**：让智能体知道何时该调用。
2.  **清晰的指令**：让智能体知道如何去执行。
3.  **合理的拆分**：利用文件引用和目录结构，降低复杂度。
4.  **渐进式披露**：始终保持主文件简洁，只在必要时加载细节。

现在，你已经掌握了 Agent Skill 的核心概念和编写规范，可以开始创建你的第一个 Skill 了！
