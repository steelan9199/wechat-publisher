# 结果评判指南 - 契约提取与通用维度评分

本指南说明如何从目标 skill 提取可验证契约，以及如何用通用维度对测试结果评分。

## 一、契约提取

契约是目标 skill 自身声明的、可验证的行为承诺。从 SKILL.md 中提取后，逐条核对测试场景的实际输出是否兑现。

### 契约来源段落

| SKILL.md 段落           | 可提取的契约类型                                |
| ----------------------- | ----------------------------------------------- |
| 输出格式 / 功能概述     | 输出格式契约（JSON/Markdown/特定模板/特定字段） |
| 工作流程 / 执行步骤     | 必经步骤契约（必须执行的步骤序列）              |
| 环境说明 / 脚本说明     | 必调资源契约（必须调用的脚本/工具/文件）        |
| 错误处理                | 异常处理契约（遇到特定错误时的处理方式）        |
| 激活条件（description） | 触发准确性契约（何时应触发、何时不应触发）      |

### 契约提取方法

1. **定位功能段落**：在 SKILL.md 正文中找到当前测试功能对应的描述、步骤、输出格式
2. **逐句识别可验证声明**：寻找以下模式：
   - "输出/生成/返回 {格式}" -> 输出格式契约
   - "运行/执行/调用 {脚本/工具}" -> 必调资源契约
   - "先 X，再 Y，最后 Z" -> 必经步骤契约
   - "若 X 失败，则 Y" -> 异常处理契约
   - "当用户说 X 时" -> 触发契约
3. **转换为可验证断言**：每条契约记录为：

```
契约ID: C1
描述: 输出必须包含 record_id 字段
来源: SKILL.md 步骤5"返回新建记录的 record_id"
验证方法: 检查最终输出中是否包含 record_id
```

### 契约判定标准

对每个场景的每条契约，判定为：

| 判定     | 条件                                                         |
| -------- | ------------------------------------------------------------ |
| 满足     | 实际输出完全兑现契约声明                                     |
| 部分满足 | 实际输出部分兑现（如格式对但字段缺失、步骤执行了但有偏差）   |
| 未满足   | 实际输出未兑现契约（如未调用应调用的脚本、输出格式完全不符） |
| 不适用   | 该契约与当前场景类型无关（如异常处理契约对正常场景不适用）   |

## 二、通用维度评分

对所有 skill 统一适用的 6 个质量维度。每个维度独立评判，基于场景的执行证据。

### 维度1：指令遵循度

子 agent 是否按 skill 声明的工作流程执行。

| 判定     | 条件                                       |
| -------- | ------------------------------------------ |
| 通过     | 完全按声明的工作流程执行，无偏离           |
| 部分通过 | 大体遵循但有少量偏离（如跳过了非关键步骤） |
| 未通过   | 严重偏离声明的工作流程，或完全未按流程执行 |

评判依据：子 agent 返回的"实际执行步骤"与 SKILL.md 声明的工作流程对比。

### 维度2：步骤完整度

声明的步骤是否全部执行，有无断链。

| 判定     | 条件                                         |
| -------- | -------------------------------------------- |
| 通过     | 声明的所有步骤均执行，从触发到产出结果无断链 |
| 部分通过 | 个别步骤未执行但不影响最终产出               |
| 未通过   | 关键步骤缺失，导致流程断链或无法产出结果     |

评判依据：子 agent 返回的"实际执行步骤"是否覆盖声明步骤的全部。

### 维度3：资源有效性

引用的脚本/文件/模板是否存在且可用。

| 判定     | 条件                                     |
| -------- | ---------------------------------------- |
| 通过     | 所有引用资源存在且可正常调用             |
| 部分通过 | 部分资源缺失或不可用，但有替代路径       |
| 未通过   | 关键资源不存在或不可用，导致功能无法执行 |

评判依据：子 agent 返回的"工具调用记录"中，调用的脚本/文件是否成功执行。

### 维度4：输出合规性

实际输出是否符合 skill 声明的格式。

| 判定     | 条件                                                         |
| -------- | ------------------------------------------------------------ |
| 通过     | 输出完全符合声明格式（JSON 结构/Markdown 结构/必需字段齐全） |
| 部分通过 | 格式大体符合但有小偏差（如多余字段、格式不统一）             |
| 未通过   | 输出格式与声明严重不符                                       |

评判依据：子 agent 返回的"最终输出"与 SKILL.md 声明的输出格式对比。

### 维度5：异常处理

遇到错误时是否按 skill 的错误处理规则处理。

| 判定     | 条件                                      |
| -------- | ----------------------------------------- |
| 通过     | 遇到异常时按 skill 声明的错误处理规则处理 |
| 部分通过 | 进行了异常处理但方式与声明略有偏差        |
| 未通过   | 遇到异常未处理或处理方式与声明完全不符    |
| 不适用   | 场景未遇到异常                            |

评判依据：子 agent 返回的"遇到的异常"和"实际执行步骤"，对比 SKILL.md 的错误处理表。

### 维度6：触发准确性

skill 是否在正确的场景被触发、在不应触发时未触发。

| 判定     | 条件                                                               |
| -------- | ------------------------------------------------------------------ |
| 通过     | 场景输入正确触发/未触发该 skill，符合 description 的"激活条件"声明 |
| 部分通过 | 触发边界模糊但大体正确                                             |
| 未通过   | 应触发未触发，或不应触发却触发                                     |

评判依据：场景的"模拟用户输入"是否匹配 description 声明的激活条件与关键词清单。description 质量评估规则参考 [skill-description-optimizer-yashu](../../skill-description-optimizer-yashu/SKILL.md)。

## 三、场景综合判定

结合契约验证和通用维度评分，给出场景综合结果：

| 综合结果         | 条件                                             |
| ---------------- | ------------------------------------------------ |
| 通过             | 契约全部满足（或不适用）+ 通用维度无"未通过"     |
| 部分通过         | 存在契约"部分满足"或维度"部分通过"，但无致命问题 |
| 失败             | 存在契约"未满足"或通用维度"未通过"               |
| 跳过（缺凭证）   | 用户未提供该场景所需的凭证，场景未执行           |
| 跳过（凭证失效） | 凭证预检失效或执行中熔断，场景未执行             |

### 凭证失效场景的评判规则

凭证失效导致的跳过与 skill 质量无关，评判时需区别对待：

| 情况                                   | 评判处理                                                                           |
| -------------------------------------- | ---------------------------------------------------------------------------------- |
| 预检阶段凭证失效，场景未执行           | 标记"跳过（凭证失效）"，不进行契约验证和维度评分，不计入通过率分母                 |
| 执行中熔断，场景未执行                 | 标记"跳过（凭证失效）"，不进行契约验证和维度评分，不计入通过率分母                 |
| 正常场景（NORMAL）中因凭证失效导致失败 | 若预检已通过但执行中凭证失效，该场景标记"失败（凭证失效）"并触发熔断，后续场景跳过 |

> **关键**：正常场景（NORMAL）中出现非预期的凭证失效属于环境问题而非 skill 问题，应触发熔断而非标记 skill 失败。

### 功能级汇总

每个功能汇总其所有场景的结果：

| 功能结果 | 条件                                               |
| -------- | -------------------------------------------------- |
| 通过     | 全部场景通过                                       |
| 部分通过 | 存在部分通过场景，但无失败                         |
| 失败     | 存在失败场景                                       |
| 跳过     | 全部场景跳过（缺凭证或凭证失效）                   |
| 部分跳过 | 部分场景跳过（缺凭证或凭证失效），已执行场景无失败 |

## 四、产出物匹配判定

仅适用于阶段1（正常场景）。对每个功能的"预期输出"与"实际输出"进行对比，给出匹配判定。

### 预期输出的确定

| 优先级 | 来源                   | 标注             | 说明                                                        |
| ------ | ---------------------- | ---------------- | ----------------------------------------------------------- |
| 1      | 目标 SKILL.md 明确声明 | `(SKILL.md声明)` | 从输出格式、功能概述、工作流程等段落中提取 skill 声明的产出 |
| 2      | AI 推断                | `(AI推断)`       | SKILL.md 未明确声明时，AI 基于功能描述推断该功能应有的产出  |

### 实际输出的记录方式

| 产出类型   | 记录方式             | 示例                                |
| ---------- | -------------------- | ----------------------------------- |
| 文本类     | 直接记录文本内容     | `2026-07-10 14:30:00 CST`           |
| 链接类     | 记录完整 URL         | `https://example.com/image/123.png` |
| 文件类     | 记录本地绝对路径     | `D:\output\report.docx`             |
| 结构化数据 | 记录 JSON 或关键字段 | `{"record_id": "rec123", ...}`      |

> 不下载、不复制产出文件，仅记录引用信息。

### 匹配判定标准

| 判定     | 条件                                                                     |
| -------- | ------------------------------------------------------------------------ |
| 一致     | 实际输出的类型、核心内容与预期输出吻合                                   |
| 部分一致 | 实际输出与预期方向一致但存在偏差（如格式略有不同、部分字段缺失）         |
| 不一致   | 实际输出与预期明显不符（如预期返回数据但返回错误、预期生成文件但未生成） |

> **从宽判定原则**：只有明显不符才标"不一致"，模糊地带标"部分一致"。判定须附简要说明，引用具体证据。

### 来源标注的显示规则

- 预期输出旁**始终标注来源**：`(SKILL.md声明)` 或 `(AI推断)`
- 当判定为"不一致"或"部分一致"时，来源标注尤其重要：帮助用户判断是 skill 未兑现承诺，还是 AI 推断预期有偏差

## 五、评判原则

- **基于证据**：所有评判必须引用具体执行证据（子 agent 返回的步骤/输出/异常），不得凭空判定
- **契约优先**：契约验证是主评判依据，通用维度是补充视角
- **不替 skill 发挥**：只评判 skill 声明的行为是否兑现，不因 skill 未声明的潜在能力缺失而扣分
- **子 agent 自核对仅作参考**：子 agent 返回的契约自核对是辅助信息，最终评判由主 agent 独立完成
- **凭证失效不扣分**：因凭证失效（预检或熔断）而跳过的场景，不得作为 skill 质量问题计入失败，应与 skill 逻辑缺陷导致的失败严格区分
- **终止不等于失败**：因基础凭证失效而终止测试时，报告中应明确标注"测试因凭证问题终止"，不得将未执行的场景计为失败
