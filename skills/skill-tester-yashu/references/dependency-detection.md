# 测试前置门禁 — 外部依赖检测指南

本指南说明如何在真实测试前检测目标 skill 对外部输入的依赖，并指导向用户索要缺失的凭证。

## 检测目标

真实测试要求 skill 能真正运行。部分 skill 依赖外部输入（API 凭证、资源链接、文件路径等），若不提前收集，测试会中途失败。本步骤在测试前一次性识别所有外部依赖，缺失的向用户索要。

## 检测范围

扫描目标 skill 的以下内容：

| 扫描对象         | 扫描内容                                                     |
| ---------------- | ------------------------------------------------------------ |
| SKILL.md 正文    | 触发条件、执行步骤、环境说明、错误处理中提及的外部资源       |
| scripts/ 目录    | 所有脚本文件中的环境变量引用、硬编码 URL、API 端点、文件路径 |
| references/ 目录 | 参考文档中提及的必需外部资源                                 |

## 依赖分类

将检测到的依赖分为四类：

### 1. 必需凭证类

skill 运行所必需的认证信息，缺失则无法执行。

识别信号（在 SKILL.md 或脚本中出现）：

- 关键词：`token`、`access_token`、`app_id`、`app_secret`、`api_key`、`secret`、`密钥`、`凭证`、`认证`、`授权`、`Bearer`
- 代码模式：`process.env.XXX_TOKEN`、`process.env.API_KEY`、`Authorization:`、`Bearer `
- 典型示例：飞书 app token、GitHub token、OpenAI API key

### 2. 资源标识类

skill 操作的具体外部资源标识，缺失则测试无目标对象。

识别信号：

- 关键词：`链接`、`URL`、`地址`、`ID`、`文档ID`、`表格ID`、`sheet`、`bitable`、`多维表格`、`仓库`、`repo`、`project`
- 代码模式：硬编码的 `https://` URL（非公共文档地址）、`{table_id}`、`{doc_id}` 等占位符
- 典型示例：多维表格链接、飞书文档 ID、GitHub 仓库地址

### 3. 环境变量类

skill 通过环境变量读取的配置，缺失可能导致脚本执行失败。

识别信号：

- 代码模式：`process.env.XXX`、`os.environ`、`dotenv`、`loadEnv`
- 配置文件：`.env`、`.env.example` 中声明的变量

### 4. 文件类

skill 运行时需要读取或写入的特定外部文件。

识别信号：

- 关键词：`文件路径`、`输入文件`、`配置文件`、`模板文件`
- 代码模式：硬编码的绝对路径（非 skill 自身目录内的相对路径）、命令行参数要求文件路径

## 依赖就绪判断

对每个检测到的依赖，判断当前是否已具备：

| 来源               | 判断方式                                                             |
| ------------------ | -------------------------------------------------------------------- |
| 用户本次会话已提供 | 检查用户在本次对话中是否已给出该凭证/链接                            |
| 环境变量已设置     | 运行 `echo $env:XXX`（PowerShell）或 `echo $XXX`（bash）检查是否非空 |
| 文件已存在         | 检查依赖的文件路径是否存在                                           |

## 索要规则

### 一次性清单索要

将所有缺失的必需依赖汇总成一份清单，**一次性**向用户索要，不要逐条打断。

### 索要话术模板

```
测试 {skill-name} 需要以下外部输入，请提供：

1. {依赖名称}（{类型}）— {用途说明}
   {若为凭证类：请确保该凭证有测试权限，测试过程中会真实调用对应 API}

2. {依赖名称}（{类型}）— {用途说明}
   ...

若某项无法提供，请说明，相关测试场景将标记为"跳过（缺凭证）"。
```

### 示例

```
测试 feishu-bitable 需要以下外部输入，请提供：

1. 飞书 app_token（必需凭证）— 用于调用飞书开放 API
   请确保该 token 有多维表格的读写权限，测试过程中会真实调用飞书 API

2. 多维表格链接（资源标识）— 作为测试操作的目标表格
   请提供一个可用于测试的表格链接（测试会产生真实数据写入）

若某项无法提供，请说明，相关测试场景将标记为"跳过（缺凭证）"。
```

## 缺失依赖的处理

| 情况                   | 处理                                                                                   |
| ---------------------- | -------------------------------------------------------------------------------------- |
| 用户提供了全部缺失依赖 | 进入凭证有效性预检（见下文）                                                           |
| 用户提供了部分依赖     | 已提供的进入凭证预检；未提供的，依赖该输入的场景标记"跳过（缺凭证）"，其余场景正常测试 |
| 用户全部无法提供       | 仅依赖该输入的功能全部标记"跳过"；不依赖外部输入的功能正常测试                         |
| 目标 skill 无外部依赖  | 跳过索要环节和凭证预检，直接进入测试场景生成                                           |

## 凭证有效性预检

用户提供凭证不代表凭证有效——token 可能已过期、app_secret 可能填错、资源链接可能已失效。若不做预检直接进入真实测试，所有依赖该凭证的场景都会因认证失败而失败，而这些失败与 skill 本身的质量无关。**基础凭证是所有真实测试的前提，凭证失效时继续测试毫无意义，必须终止。**

### 预检时机

在测试前置门禁收集到用户提供的凭证后、生成测试场景之前进行。即用户提供了凭证 → 预检 → （有效才）生成场景并执行。

### 预检原则

1. **最小化调用**：每类凭证只发起一次最轻量的真实调用，足以判定有效性即可，不做多余操作
2. **真实调用**：预检必须真实发起请求，不得模拟或假设。预检调用的请求与响应作为执行证据记录到报告
3. **只验证不破坏**：预检调用应选择只读/无副作用接口，避免产生测试数据
4. **逐凭证独立判定**：每个凭证独立预检，一个失效不影响其他凭证的预检

### 各类凭证的预检方法

| 凭证类型                           | 预检方法（优先使用目标 skill 脚本）                                                                                      | 失效信号                                                      |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------- |
| app_id + app_secret                | 调用目标 skill 的 token 获取/刷新脚本（如 `get-tenant-access-token.js`）。脚本不存在时，可调用该平台的 token 获取接口    | 脚本返回认证失败错误码、接口返回 secret 错误、app_id 不存在等 |
| access_token / tenant_access_token | 调用目标 skill 的 token 刷新脚本，或调用一个目标 skill 内置的只读接口脚本                                                | 401 Unauthorized、token expired、invalid token                |
| API key                            | 调用目标 skill 提供的校验脚本；若无脚本，调用最轻量的 list/ping 类接口                                                   | 403 Forbidden、invalid api key、unauthorized                  |
| Bearer token                       | 同 access_token，调用目标 skill 的校验脚本或基础校验接口                                                                 | 401、invalid token、expired                                   |
| 资源标识类（文档ID/表格链接等）    | 优先调用目标 skill 的链接解析/资源访问脚本（如 `url-to-document-id.js`）；无相关脚本时，用已验证有效的凭证尝试访问该资源 | 脚本返回解析失败、404 not found、资源不存在、无权限访问       |
| 文件路径类                         | 检查文件是否存在且可读                                                                                                   | 文件不存在、无读取权限                                        |

> 若某资源标识类依赖的凭证本身尚未通过预检，则该资源标识的预检跳过，直接标记为"无法预检（依赖的凭证失效）"。

### 预检结果判定

| 凭证状态 | 判定依据                                                                                            |
| -------- | --------------------------------------------------------------------------------------------------- |
| 有效     | 预检调用成功返回（HTTP 2xx，或业务语义成功）                                                        |
| 失效     | 预检调用返回明确的认证失败信号（401/403、invalid token、auth failed、expired、secret incorrect 等） |
| 无法判定 | 预检调用失败但非认证原因（网络超时、DNS 解析失败、服务端 500 等）。此时无法确认凭证是否有效         |

### 预检结果处理

| 预检结果                   | 后续动作                                                                                                                                           |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 全部必需凭证有效           | 进入测试场景生成阶段                                                                                                                               |
| 部分凭证失效               | 失效凭证相关的功能/场景标记"跳过（凭证失效）"，仅对有效凭证覆盖的功能继续测试；若所有必需凭证均失效，按"全部失效"处理                              |
| 所有必需凭证均失效         | **直接终止测试**，不生成测试场景，不执行任何场景，直接生成报告，标注"因基础凭证失效，测试终止"。告知用户哪些凭证失效及失效原因，建议用户检查后重试 |
| 凭证无法判定（非认证原因） | 向用户说明预检失败原因（如网络不通、服务不可用），询问是否：1) 重新提供凭证；2) 稍后重试；3) 终止测试                                              |

### 预检执行方式

预检调用由主 agent 直接执行，**优先调用目标 skill 自身提供的凭证脚本/工具**，不需要启动子 agent。因为预检的目的是验证凭证能否被目标 skill 正确处理，使用目标 skill 自己的代码完成预检，才能真实反映目标 skill 的凭证处理能力。

执行优先级：

1. **第一优先级**：调用目标 skill 内置的凭证脚本。例如测试 `feishu-docx` 时，预检 `appId`/`appSecret` 应直接调用其 `get-tenant-access-token.js` 脚本。
2. **第二优先级**：若目标 skill 未提供对应凭证脚本，但提供了资源访问/链接解析脚本（如 `url-to-document-id.js`），则调用该脚本验证资源标识类依赖。
3. **第三优先级**：若目标 skill 完全没有相关脚本，主 agent 可发起一次最小化的 HTTP 调用作为兜底，但必须在报告中注明"该凭证由主 agent 直接调用外部接口验证，未经过目标 skill 脚本"。

主 agent 在预检阶段禁止做业务逻辑处理，只能做参数文件组装、读取配置文件、调用目标 skill 脚本等轻量辅助工作。

### 预检证据保留

每个凭证的预检结果需记录以下信息，供报告使用：

- 凭证名称
- 预检调用方式（调用的接口/命令）
- 预检返回结果（状态码、错误信息，敏感值脱敏）
- 判定结果（有效/失效/无法判定）
- 若失效，失效原因摘要

## 重要规则

- 凭证仅在本次测试会话内有效，测试结束后不持久化、不写入任何文件
- 向用户索要时必须说明"测试会真实调用 API/脚本"，让用户知悉副作用
- 不要在缺凭证的情况下强行执行依赖该凭证的场景
- 检测依赖时基于 skill 的实际声明，不臆测未提及的外部依赖
- 若 skill 声明了 `.env` 文件但未提供，先询问用户是否愿意提供 `.env` 内容或对应值
- **凭证预检是硬性门禁**：预检未通过的凭证，其相关场景一律不得执行，不得跳过预检直接测试
- **凭证失效即终止**：所有必需凭证均失效时必须终止，不得带着失效凭证继续测试产生误导性结果
