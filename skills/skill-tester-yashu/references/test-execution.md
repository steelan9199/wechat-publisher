# 真实测试执行指南

本文件定义 skill-tester 的场景生成规则、分阶段执行协议、子 agent prompt 构造方法及证据采集规范。

## 一、测试场景生成

### 场景类型

| 类型     | 缩写   | 说明                                               |
| -------- | ------ | -------------------------------------------------- |
| 正常场景 | NORMAL | skill 的主路径，模拟典型用户输入，验证功能核心行为 |

### 场景 ID 规则

`{功能序号}-{类型缩写}`，例如 `1-NORMAL`。

### 场景结构

每个场景包含：

- **场景 ID**：`{功能序号}-{类型缩写}`
- **模拟用户输入**：构造一段模拟用户消息
- **预期行为契约**：从目标 skill 声明中推断的可验证断言
- **预期输出**：该功能预期产出的内容（优先从目标 SKILL.md 提取，无明确声明时由 AI 推断），标注来源
- **依赖凭证**：该场景需要的用户输入（已通过预检）

### 分阶段生成规则

| 阶段  | 生成场景类型 | 数量规则           |
| ----- | ------------ | ------------------ |
| 阶段1 | NORMAL       | 每个功能至少 1 个  |

## 二、分阶段执行协议

### 执行顺序

```
阶段0：预检
阶段1：1-NORMAL -> 2-NORMAL -> 3-NORMAL -> ...（全部 NORMAL 执行完毕）
-> 输出阶段1报告 -> 结束
```

### 严格串行

**禁止并发**。同一阶段内必须等当前子 agent 完全返回后，才能启动下一个场景的子 agent。

## 三、子 agent prompt 构造

每个场景的子 agent prompt 包含以下部分：

### 1. 角色与指令

```
你现在是严格执行目标 skill 的 agent。下方是目标 skill 的完整指令，你必须严格按照其工作流程执行本次测试场景。

执行要求：
- 完全遵循目标 skill 的所有步骤、规则、错误处理逻辑
- 真实调用所需的工具（RunCommand、WebSearch 等），不要模拟或跳过
- 若 skill 要求调用脚本，真实执行该脚本
- 若 skill 要求调用 API，使用提供的凭证真实调用
```

### 2. 目标 skill 指令注入

```
===== 目标 Skill 指令开始 =====
{目标 skill 的 SKILL.md 全文}
===== 目标 Skill 指令结束 =====
```

若场景涉及 references/ 下的参考文件，将其内容一并注入。

### 3. 测试场景

```
===== 测试场景 =====
场景ID: {场景ID}
功能: {功能名}
类型: {场景类型}
模拟用户输入: {模拟用户消息}
===== 测试场景结束 =====
```

### 4. 凭证

```
===== 可用凭证（仅供本次测试使用）=====
{凭证名称}: {凭证值}
===== 凭证结束 =====
```

### 5. 输出要求

```
执行完成后，请按以下结构返回结果：

【执行步骤】
按顺序列出实际执行的每一步

【调用的工具/脚本】
列出调用的所有工具和脚本，含参数和返回结果摘要

【最终输出】
按 skill 要求产出的最终结果。
注意：需明确记录产出物的具体内容，便于报告中做预期与实际对比：
- 文本类输出：直接记录完整文本
- 链接类输出（如图片URL、文档链接）：记录完整 URL
- 文件类输出（如生成的本地文件）：记录文件的本地绝对路径
- 结构化输出（如 JSON）：记录完整 JSON 或关键字段

【遇到的异常】
执行中遇到的任何异常（若无填"无"）

【契约核对】
针对以下预期行为契约，逐条说明是否做到：
- 契约1: {描述} -> {做到/部分做到/未做到，附说明}
```

## 四、证据采集

### 采集内容

| 证据项       | 说明                                                                    |
| ------------ | ----------------------------------------------------------------------- |
| 实际执行步骤 | 子 agent 实际执行的步骤序列                                             |
| 工具调用记录 | 调用的工具/脚本、参数、返回摘要                                         |
| 最终输出     | 子 agent 按 skill 产出的完整输出                                        |
| 产出物记录   | 实际产出物的具体内容（文本/链接/路径），仅阶段1采集，用于与预期输出对比 |
| 异常记录     | 执行中遇到的异常                                                        |
| 契约自核对   | 子 agent 对预期契约的自评                                               |

### 证据保留

- 每个场景的证据独立保留，与场景 ID 对应
- 工具调用返回结果过长时保留前后各 500 字符，中间用 `...（省略 N 字符）...` 标注
- 敏感凭证在证据中脱敏，仅保留前后各 4 个字符

## 五、凭证失效熔断机制

每个场景执行返回后必须进行熔断检查。

### 识别凭证失效信号

| 信号类型     | 示例                                                                 |
| ------------ | -------------------------------------------------------------------- |
| HTTP 状态码  | 401 Unauthorized、403 Forbidden                                      |
| 业务错误码   | 飞书 99991663、99991661 等                                           |
| 错误信息文本 | invalid token、token expired、authentication failed、unauthorized 等 |
| API 业务语义 | 明确的"凭证错误/失效/过期/无权限"语义                                |

### 区分失效原因

| 失败原因           | 判定依据                        | 处理                     |
| ------------------ | ------------------------------- | ------------------------ |
| 凭证失效           | 认证/鉴权层失败                 | 触发熔断                 |
| skill 自身逻辑问题 | 凭证有效但请求参数/流程错误     | 不触发熔断，正常标记失败 |

### 熔断动作

1. 当前场景标记为"失败（凭证失效）"或"跳过（凭证失效）"
2. 后续依赖同一凭证的场景立即标记"跳过（凭证失效）"
3. 已执行场景证据保留
4. 生成当前阶段报告，报告中注明熔断触发点、原因、被跳过场景清单

## 六、重要规则

- **分阶段交付**：每阶段结束后必须立即输出报告，禁止跨阶段连续执行
- **串行不可违反**：任何情况下都不允许并发执行多个场景
- **真实执行不可模拟**：子 agent 必须真实调用工具/API/脚本
- **指令注入完整**：SKILL.md 全文必须完整注入，不得截断
- **凭证隔离**：每个子 agent 只获得其场景需要的凭证
- **不修改目标 skill**：测试过程中不修改目标 skill 的任何文件
- **凭证失效即熔断**：执行中一旦确认凭证失效，立即终止后续依赖场景

## 七、授权保护处理规则（重要）

### 识别授权保护信号

当执行脚本时输出以下特征文本，判定为"授权保护"：

| 特征文本             | 说明               |
| -------------------- | ------------------ |
| `免费试用次数已用完` | 试用期已用完       |
| `请购买授权码`       | 需要购买授权       |
| `license-key.txt`    | 提示写入授权码文件 |
| `授权码`             | 明确要求授权码     |
| `未授权`             | 未经授权           |
| `请先激活`           | 需要激活           |

### 正确处理流程

1. **检测到授权保护信号 -> 立即终止测试**
2. **真实记录**：将授权保护作为测试结果的一部分，记录触发时的完整输出
3. **生成报告**：在报告中标注"因授权保护，测试终止"
4. **禁止绕过**：绝对不能尝试用 curl、Invoke-RestMethod 或其他方式绕过授权保护来测试

### 错误做法（禁止）

- ❌ 用 curl/Invoke-RestMethod 直接调用飞书 API 验证 token
- ❌ 用其他脚本绕过授权检查
- ❌ 修改目标 skill 的授权相关文件
- ❌ 尝试暴力破解或绕过授权机制

### 正确做法

- ✅ 如实记录授权保护提示内容
- ✅ 报告授权保护触发的完整输出
- ✅ 询问用户是否提供授权码继续测试

### 报告模板变更

在预检或测试报告的"测试终止原因"中添加：

```markdown
## 测试终止原因

因授权保护终止。

**触发输出**：
```

免费试用次数已用完
请购买授权码后继续使用: https://shop.xxx.com/xxx

