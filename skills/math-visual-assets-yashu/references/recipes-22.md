## Ⅰ 极小曲面与周期结构

### 3. Gyroid（Schwarz P） · A · 0.09s ★★★★★
```
cos x·cos y + cos y·cos z + cos z·cos x = 0
```
- **参数**：`L = 1.05π`，`azim=30, elev=18, k=0.62, maxsteps=300, thin=0.7`
- **看点**：无参数、无图纸，却能沿三方向无限 tiling 而无缝。唯一被工程实际使用的三周期极小曲面
- **极小曲面** = 平均曲率为零 = 肥皂泡的最小自然形态
- ⚠️ 解析场要 `k` 小（0.62）且 `maxsteps` 够大，否则步进穿透薄面

### 4. Schwarz D · A · 0.11s ★★★★
```
2cos x·cos y·cos z − cos²x − cos²y − cos²z + 1 = 0
```
- **参数**：`L = 1.15π`，`azim=32, elev=20, k=0.55, maxsteps=320, thin=0.7`
- 同家族另一张，长相完全不同：像不断自我穿插的编织骨架

```
Rr = a + cos(u/2)·sin v − sin(u/2)·sin 2v        (a = 2.0)
x = Rr·cos u    y = Rr·sin u    z = sin(u/2)·sin v + cos(u/2)·sin 2v
```

### 22. 瓶形克莱因瓶 Klein bottle (bottle form) · B · 约 36s ★★★★★
```
x = −(2/15)·cos u·( 3cos v − 30 sin u + 90 cos⁴u sin u − 60 cos⁶u sin u
                    + 5 cos u cos v sin u )
y = −(1/15)·sin u·( 3cos v − 3 cos²u cos v − 48 cos⁴u cos v + 48 cos⁶u cos v
                    − 60 sin u + 5 cos u cos v sin u − 5 cos³u cos v sin u
```

### 9. 罗马曲面 Roman / Steiner · B · 20.5s ★★★
```

z = cos t + ½(cos 2t − 1) + ½(cos 2t − 2cos²u)
```
- **参数**：`param_cloud(fn, 1700, 1700, **0, 2π**, **0, 2π**)`，**无裁剪**，`res=420`

### 7. 数学玫瑰 Rose bloom · B · 2.7s ★★★★★ ← 2026-10-06 重写
```
56 片花瓣，第 i 片：方位 φ = 2π·frac(i·0.618 + 25°/360·t)      (t = i/55)
  底部半径 r₀ = 0.04 + 0.30·t^1.40      底部高度 z₀ = 0.46 − 0.34·t^0.75
  瓣长     L  = 0.56 − 0.06·t           半宽     W  = 0.085 + 0.130·t
  起始倾角 β₀ = 3 + 76·t^1.45           沿途转角 Δβ = 5 + 26·t
  截面凹度 R(s) = Rc₂·(1 − curl·s^1.5),  Rc₂ = 0.11 + 0.45·t
点云 → sdf_from_points(pad=0.06, thick=2, res=352)
```
- **参数**：`azim=30, elev=26, k=0.95, glow=0.12, thin=0.75, light=0.85, zoom=0.85`
- 片瓣是**参数曲面各自的点云**（每片自带局部标架），不是任何旋转体

> 🔁 **为什么从"解析场"改成"点云"**（根因见下）
>
> 原场景把平面玫瑰线 `r = cos(kφ)` **绕 z 轴旋转**，再用方位调制 `|cos(kφ)|` 长出花瓣。
> 这是数学上就产不出玫瑰的构造：
> 1. **旋转体不可能有方位花瓣**。平面玫瑰线躺在 xy 平面里，绕 z 转一圈只能得到
>    一圈圈鼓包（陀螺/风车），旋转对称性把瓣数抹平了。
> 2. 代码自己加的 `|cos(kφ)|` 给的是 **2k 个瓣，不是 k 个** —— 与注释
>    "gives k petals in azimuth" 直接矛盾（探针实测赤道花瓣数 = 10，k=5）。
> 3. 片瓣是**沿整根 z 轴的径向厚壁**（切片实测 φ=0° 处 ρ∈[0.140, 1.000] 全实心，
>    φ=18° 全空），所以每条"瓣"从底一直通到顶；肉眼看就是风车/螺旋桨。
> 4. 中心是**贯穿孔**（轴线采样 0/2701 命中），与 docstring 写的
>    "closed at both poles" 相反；另有一个文档里从未提到的纬度调制 `0.80+0.20cos2θ`。
>
> **正确做法**：玫瑰之所以是玫瑰，靠的是**层层错位叠放的凹瓣**——
> 外瓣宽而低、平铺外翻，中瓣立起，内瓣卷成紧实的"花心"，
> 相邻花瓣按**黄金角**错开，任何两条边都不对齐。
> 所以改成点云：每片花瓣是一张独立的凹面（基部分段积分出的中轴线 + 截面弯曲），
> 再靠 `sdf_from_points` 求并集；花心另加一个小纺锤 + 底座圆顶**把中心封死**
> （中空的花心会渲成一个穿过花朵的洞）。
>
> 💡 复用价值：**"几何名字"要真的长成那个东西，先问"这个构造允许出现这个特征吗"。**
> 旋转体里找花瓣、棱柱里找分形，都属于先验不成立。
>
> 复现证据：`scripts/probes/_rose_bloom_audit.py`（花瓣计数、轴线命中、径向切片、
> 旧场 vs 新场对照）。
>
> ℹ️ 旧解析场 `F_ROSE3D`（旋转体，k 参数）**仍保留在引擎里**，可作"陀螺/风车"另用，
> 只是画廊不再使用它。

### 15. 曼德球 Mandelbulb（8 次方） · A · 2.2s ★★★★★　（2026-10-06 修复）
```
r = |z|;  θ = acos(z.z/r);  φ = atan2(z.y, z.x)
dr = r^(p−1)·p·dr + 1
z ← r^p·( sin pθ cos pφ,  sin pθ sin pφ,  cos pθ ) + c
de = ½·ln(r)·r / dr          （r 取**逃逸那一瞬**的 |z|）
```
- **场**：解析距离估计场 `F_MANDELBULB = 5`（`render3d_gpu._f_mandelbulb`），**不建网格、不跑 EDT**
- **参数**：`power=8, iters=16`，场盒与世界盒同为 `[−1.45, 1.45]³`，
  `azim=35, elev=30, k=0.95, maxsteps=420, glow=0.12, light=0.62, thin=0.45,
  zoom=0.68, contrast=1.00`
- 签名：`|∇de| ≈ 0.63 < 1`（保守），`min = −0.183`、`frac<0 = 0.253`，切片呈 7 重对称
- 两条引擎输出一致：240×240 同图对照 **IoU = 0.991**，maxdiff 0.079
  （残差全部落在混沌边界，源于 CPU float64 / GPU float32 迭代被 `8ⁿ` 放大）
- 把曼德布罗集合升到三维、指数改 8。表面褶皱在任何缩放下都重复出现
- 参考：`assets/figs/15_mandelbulb.png`

#### 🐛 曾经的"渲成一根管子"——根因是**坐标被压成二维**（已修）

旧实现（`gallery.py` 与 `gallery_gpu.py` 都有同一句）：

```python
z = (X + 1j * Y).ravel() + 1j * Z.ravel()      # == X + i·(Y+Z)
```

复数只有一个实部一个虚部，这句把三维坐标塞进了一个复数 ——
**整个场只依赖 `x` 与 `y+z`**。实测证据：

```python
# y=0 切片 与 y=0.4 且 z 平移 −0.4 的切片（保持 y+z 不变）
np.array_equal(field(X, 0, Z), field(X, 0.4, Z - 0.4))   # -> True，逐位相同
```

一个沿 `(0,1,−1)` 方向恒定不变的场，就是**二维集合沿该方向拉伸出的棱柱**，
渲染出来必然是那根"光滑管子"。所以两种引擎给出同样的错误结果。

> ⚠️ 旧文档把责任归给"场没有负内部 / 表面渲染器"，**那是误诊**。
> 场本身才是 bug：`c` 的构造错了，后面再怎么调相机、调 `k`、换 EDT 都不会好。

#### 另外两个真实存在、但都只在 DE 实现里才需要注意的细节

1. **`r` 必须取逃逸那一刻的 `|z|`，不是循环结束后的值。**
   逃逸后把轨道冻结成 0 再用 `r` 算 `de`，距离估计会塌掉
   （实测 max 从 0.798 掉到 6e-4，整场只剩噪声）。
2. **符号必须由"是否逃逸"给出。** `de` 只在逃逸点为正（那里 `r > 2` ⇒ `ln r > 0`）；
   被捕获的轨道返回 `−|de|`，这样穿面时有符号翻转，八分细化才咬得住表面。
   不能靠 `log(max(r,1.001))` 之类的"防溢出"写法 —— 它会把内部 `r<1` 的负号也翻正，
   内部就此消失。

> 📄 **完整复盘见 `references/mandelbulb-postmortem.md`**：正确实现逐字代码、
> 8 个坑（含"两引擎都错≠渲染器错"的误诊教训、`ss=1` 未测分支、迭代次数敏感度实测）、
> 以及"结果不对时"的六步定位流程。重渲或改参数前先读它。

### 16. 门格海绵 Menger Sponge · C · 3.0s ★★★★（2026-10-06 修复）
```
立方体均分 27 块 → 挖掉中心 + 6 个面中央 → 对剩余每块重复（3 层）
```
- **参数**：`res=190, [−1,1]³`，**3 层**，逐层用三进制判据（见坑 1）
  `azim=32, elev=20, k=0.92, glow=0.20`
- **体积趋于 0，表面积趋于无穷** —— "无限大却没重量"

#### 🐛 本图专属的三个坑（已修，原实现只做出 1 级海绵）

**坑 1：`face` 写成贯穿整条轴的长条板，第 2 层起全部嵌套在第 1 层里**

原实现逐层用"坐标对"判据：

```python
step = 1.0 / (3 ** (it + 1))
face = (((np.abs(X) < step) & (np.abs(Y) < step))   # 第三个轴完全不加约束
        | ((np.abs(Y) < step) & (np.abs(Z) < step))
        | ((np.abs(Z) < step) & (np.abs(X) < step)))
keep &= ~(mid | face)
```

`|X| < step & |Y| < step` 而**第三个轴不加任何约束**，挖掉的是沿整条轴贯穿的板。
第 1 层碰巧等价（3×3×3 下 `|X| < 1/3 & |Y| < 1/3` 正好只覆盖 3 个格子，
三块板的并集 = 中心 + 6 个面中央，即标准的 7 块），
但第 2 层的 `|X| < 1/9 & |Y| < 1/9` **严格包含**在第 1 层的板里，
于是 `keep &=` 什么都没删掉 —— **写了 4 次迭代，实际只等于 1 级**。

实测填充率 **0.7431 ≈ 20/27 = 0.7407**（1 级应得的值），
而 2/3/4 级分别是 0.5487 / 0.4064 / 0.3011。

**正确写法：每层一个全局的三进制判据。**
点在第 k 层的三个三进制数字里，**至多一个等于 1** 才保留。
这一条同时覆盖"中心格 + 6 个面中央格"，而且天然可叠加
（每层都在上一层存活的所有格子内生效）：

```python
for k in range(1, levels + 1):
    q = 3 ** k
    dig = sum((np.floor((axis + 1) * 0.5 * q).astype(np.int64) % 3 == 1)
              for axis in (nx, ny, nz))
    keep &= (dig <= 1)
```

**坑 2：层数取 3，不取 4**

860 px 下 4 级单元只有约 10 px 宽，最细一级的孔洞糊成纹理，
整体读起来像"布满小方块的板"，反而认不出是门格海绵。
3 级的单元约 32 px，大孔—中孔—小孔三层递归一眼可见。
且 `res−1 = 189 = 3³ × 7` 恰好整除 → 每个 3 级单元占 7 个体素，无混叠。
（真要渲 4 级就取 `res=244`，`243 = 3⁴ × 3`，实测填充率 0.3050、误差 +1.3%，
渲染 5.7 s。）

**坑 3：EDT 的 `sampling` 必须等于掩膜自己的体素尺寸**

原实现的掩膜是 190³，采样间距却按一个无关的 `nn = 300` 算：

```python
nn = int(max(64, min(384, round(300 * ext / ext))))   # = 300，与掩膜无关
vox = ext / (nn - 1)                                  # 2/299，实际应为 2/189
```

所有距离因此被整体压缩 **1.58×**，sphere tracing 每步变小、步数变多
（视觉上几乎看不出来，但白烧步数）。正确写法就是 `vox = ext / (res - 1)`。

> 📄 复现证据：`scripts/probes/_menger_base3_audit.py` ——
> 填充率对照、掩膜切片 dump、以及"原样 / 修 sampling / 真 4 级 / 场取负"
> 四版渲染与成品图的 IoU 矩阵（原样 IoU=1.00000，取负 IoU=0.99945，
> 证明 sphere tracing 与场的内外符号无关，形体才是唯一变量）。

### 14. 阿波罗尼斯球夹 · C · 61.0s ★★★（2026-10-05 重写）
```
4 个正四面体相切的单位球 + 中心隙球，反复做"球在球内反演"
```
- **参数**：`rounds=5, res=520, box=2.3, rmax=0.42, thick=0.007`
  种子球半径 1.0，球心距原点 `R=√(3/2)`（使棱长=2 即相切），中心隙球半径 `R−1`
  `azim=35, elev=18, k=0.9, glow=0.24, zoom=0.92`
- 球数增长：4 → 20 → 144 → 396 → 636 → **6081**（5 轮）
- 渲染成**壳层**（`|d| − thick`），因为球夹是球面而不是球体
- 🔑 多个球取 `np.minimum` 合并 —— 比反复采样快得多

#### 🐛 本图专属的两个坑（已修，原实现渲出全黑图）

**坑 1：反演是对合（involution），重复反演只会振荡**

原实现：
```python
denom = float(ci @ ci - ri * ri)      # ri = r*m  →  误用了 (m·r)²
centre = (m * ci + ci) / denom
```
反演映射满足 `I(I(x)) = x`。原代码的公式不是标准反演，
重复作用只会把球在原球与像球之间来回推。实测 8 轮后仍然只有 4~5 个球，
且几乎全被 `radius > 3.0` 的守卫滤掉 —— **分形根本没生成**。

正确做法是**对当前集合里的每个球，在其余每个球里各反演一次**，
新球并入工作集再继续下一轮：
```python
for a, ra in cur:
    for b, rb in cur:
        dv = a - b
        den = float(dv @ dv) - rb*rb
        cen = b + (rb*rb/den) * dv
        rad = abs(rb*rb*ra/den)
```
> 去重必须用**坐标哈希**（`round(x*1000)`）。用 O(n²) 的 `any(np.linalg.norm(...) < eps)`
> 去重在第 4 轮就会超时（实测 5 轮生成 6081 球，`np.where` 一次性建 SDF 会申请 75 GiB 内存）。

**坑 2：`np.minimum` 累积实心球会把包围盒填满**

原实现对 55 个**实心**球取 `min`，结果包围盒内 SDF 全为负：
```
sdf min = -2.4849   frac<0 = 1.00000   ← 整个盒子都是"内部"
```
场里没有外部，渲染器无从判断表面在哪 → 渲出一块实心方块 → **纯黑图**。
球夹是球面集合，必须取壳层或改用占据场 + EDT。

### 15. 曼德球 · C · ⚠ 输出错误（2026-10-05）

> **状态：已删除 `assets/figs/mandelbulb.png`，因为渲出来是一根管子。**

```

```

#### 🐛 坑 1：`np.maximum(r, 1.001)` 截掉了 `log` 的符号（已修）

```python
de[ok] = r[ok] * np.log(np.maximum(r[ok], 1.001)) / np.abs(dz[ok])
#                                    ^^^^^^^^^^^^^^ 防溢出，却把内部 r<1 的负 log 也变成正
```
实测 `de` 全场 `min = +0.000`、`frac<0 = 0.00000`。
**没有负内部的场无法 sphere tracing**，光线只蹭最外壳 → 渲成管子。

#### 🐛 坑 2：float64 溢出 → NaN 静默打洞（已修）

`z**8` 会越过 float64 上限变成 `inf`，`inf` 参与下一步运算即产生 `NaN`。
**`NaN` 与任何阈值比较都是 False**，所以 `occ = |z| < 2.0` 会把这些体素
静默排除，在物体上打出隧道。实测 `res=80` 时 **19% 的格子是 NaN**。

修法是"逃逸即冻结"：
```python
esc |= (~np.isfinite(r)) | (r > BAIL)
z = np.where(esc, 0.0, z)
```

- 8 重旋转对称性实测 100%

两条独立路径给同样错误结果，说明问题在**表面渲染器**而非本场景。

#### 🐛 本图专属的坑（已修，原实现亮度上限仅 0.15，近乎全黑）

**坑 1：跳跃映射的间距是 133 个体素，`close` 桥接不了**

`de Jong` 的相邻轨道点间距中位数 **0.707**，而定义域宽度只有约 2.0。
在 `res=380` 下这相当于 **133 个体素**的跳跃 —— 远大于 `close=2`

> ⚠️ 这条修正了本文档原先"跳跃映射必须 `close`"的说法：
> **`close` 只对几十个体素级的间距有效**（Clifford 的 238 体素是特例，
> 因为它的轨迹有额外的形态学支撑）。**先量间距中位数，再决定用
> `close` 还是改用 EDT 小球并集。**

正确做法是不做形态学桥接，直接用**精确 EDT** 表达"每个采样点周围半径 r 的小球并集"：
```python
occ[idx[:,0], idx[:,1], idx[:,2]] = True          # 采样点体素化
din = distance_transform_edt(~occ, sampling=vox)  # 到最近采样点的距离
f = grid_from_array((din - 0.0135).astype(np.float32), lo, hi)  # 减去半径 = 球并集
```
这是精确解，**与采样间距无关**。

0.15 提到 0.59，形态（双瓣 + 钩形缺口）清晰可辨。
