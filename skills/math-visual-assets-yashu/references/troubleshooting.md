# 定位问题的正确方法（方法论 > 坑本身）

本项目的 4 次重大 bug **全部靠逐级数值对比定位，没有一个靠读代码猜出来**。

---

## 一、三步定位法

### 步骤 1：先二分 —— 形体对不对？

渲一张图，和参考图做差，看**diff 图**。

```python
d = np.abs(gpu - cpu)
# diff = 0 的区域 => 那段代码是对的
# diff ≠ 0 的区域 => 问题在这里
```

**形态类错误（缺瓣、只出一小片、整体偏移）在 diff 图上一眼可见。**

### 步骤 2：再逐级拆解 —— 一次只动一个变量

把后处理拆成五级，每级单独 CPU vs GPU 比 maxdiff：

```
downsample → clamp → blur → bloom_acc → tonemap
```

典型成果：定位到 `gaussian_filter` 标量 sigma 连颜色轴一起模糊，
GPU 版补 3×3 颜色混合矩阵后 maxdiff 从 0.30 降到 0.005。

### 步骤 3：用针对性合成数据 —— 构造只激活单一路径的输入

| 要验证什么 | 构造什么输入 | **不要**用什么 |
|---|---|---|
| 边界约定（reflect/symmetric） | **delta 图 + 非对称随机 + 大图内区对比** | 线性 ramp、小图 |
| 某一级后处理 | 常数图（只触发这一级） | 真实渲染图 |
| 权重公式 | 手动算的已知答案 | 真实数据 |

> ⚠️ **本项目最大的弯路**：用真实渲染图做测试输入
> → **多个缺陷互相掩盖**，定位不了。
> ⚠️ **第二个弯路**：用**线性数据**验证边界约定
> → 线性 ramp 下所有反射约定结果**完全相同**，
> 会得出「我的实现是对的」这个**错误结论**。
> 浪费两轮：先 9×11 小图测（r=5 时每个像素都在反射区，**无解**），
> 后线性 ramp 测 1D 映射（**假通过**）。

## 二、症状 → 病因速查

### 症状 1：只渲出一小片碎片

**先测点云的真实取值范围**，别先调阈值。

```powershell
& $py "$SK\scripts\probes\_diag_roman.py"
```

**真实案例（roman）**：原以为是裁剪阈值 `< 2.2` 失效，
实测只杀掉 11% 的点 —— **不是主因**。真因是**参数域只覆盖半个曲面**：
`t∈[0,π]` ⇒ `sin(t)≥0` ⇒ `x = sin(t)·cos²u ≥ 0` 恒成立，
实测 x∈[0, 0.977] 而非 [−1, 1]。

**检查清单**
- [ ] 参数域是否覆盖完整曲面？（对 `sin/cos` 参数化，范围少一半是常见错）
- [ ] 裁剪阈值相对场上界设得合理吗？
- [ ] 打印 `P.min(0)` / `P.max(0)`，看包围盒是否被不对称地切掉

### 症状 2：同心环 / 条纹摩尔纹

**先查采样间距，再查分辨率。** 绝大多数"摩尔纹"其实是欠采样。

```powershell
& $py "$SK\scripts\probes\_diag_quality.py"
```

关键量：**采样间距 / 体素尺寸**。两个方向都要≤ 1。

**真实案例（helicoid）**：原以为是"分辨率不足"，建议 `res=330→420`。
实测 v 方向只有 46 个采样点，`dv=0.0556` 是体素 `0.0151` 的 **3.7 倍**
→ 是**欠采样条纹**，不是分辨率。把 nv 提到 230 后摩尔纹消失（res 只作辅助）。

**检查清单**
- [ ] 两个参数方向的采样间距各是多少？除以体素尺寸，>1 就是欠采样
- [ ] 点云密度够吗？（`occupied_voxels / points` 看是否<1，即多点挤一格）
- [ ] 若已是密集网格，才考虑提 `res`

### 症状 3：物体偏小 / 画面偏暗

**网格盒远大于物体** → 相机按盒子取景，物体自然显小。

```powershell
& $py "$SK\scripts\probes\_diag_quality.py"   # 看 pt extent vs grid box
```

**真实案例（orbital）**：盒是 ±1.15，物体只到 ±0.90
→ 浪费约 20% 画面。把 `half` 收到 0.94 + `zoom=0.88` 后正常。

**检查清单**
- [ ] 打印点云包围盒，和网格盒对比
- [ ] 用 `zoom` 参数拉近（比改盒子更安全）
- [ ] 偏暗看 `gain`（发光类）或 `glow`/`light`（表面类）

### 症状 4：满屏碎点噪点

**点云断裂**，需要形态学桥接。

```powershell
& $py "$SK\scripts\probes\_diag_spacing.py"    # 看相邻采样点相距多少体素
```

**真实案例（clifford）**：跳跃型映射的相邻点可相距**238 个体素**，
占据率仅 0.108%。`_tube_from_points` 原本不做膨胀，
EDT 于是把每个采样点解析成一个独立小blob → 碎点。
`close=2`（两次 6 邻域膨胀）桥接成连续管。

**判据（实测）**
| 吸引子 | 类型 | 采样间距 | 需要 close？ |
|---|---|---|---|
| lorenz | ODE 积分 | 2.9 体素 | 否，`close=0` |
| dejong | 跳跃映射 | 170 体素 | 是 |
| clifford | 跳跃映射 | 238 体素 | 是，`close=2` |

**检查清单**
- [ ] 算 `np.linalg.norm(np.diff(P, axis=0), axis=1).mean() / vox`
- [ ] > 3 体素就加 `close`
- [ ] ⚠️ 先分清"渲染噪点"和"结构本身"：跑 `_diag_clifford_grain.py`，
      若 highfreq_rms 与已验收场景同量级，**那是真实结构，不要修**

### 症状 5：网格盒切出平边

```powershell
& $py "$SK\scripts\probes\_diag_helicoid_edge.py"
```

**先确认是不是真截断**：算点到每个盒面的余量（体素数）。
`< 2 体素` 才是截断。

**真实案例（helicoid）**：交接文档判断是"被网格盒截断"，
实测 z 方向有 **11.86 体素余量** —— **不是截断**，
而是曲面自身 `u=+2.55` 的**开口边界**（曲面本来就是开面的）。

### 症状 6：图只剩一半 / 缺瓣 / 塌成碎块

**阈值相对场上界设得太高。**

**真实案例（orbital_f）**：`c=0.95` 是对 `｜Y₃₀｜ = ｜cos3θ｜` 设的，
但该场**上界只有 1.0**，`|cos3θ| > 0.95` 只剩极值附近
→ 填充率 2.07%，塌成两片碎块。`c=0.5` 后填充率 5.23%，恢复 5 瓣。

**检查清单**
- [ ] 求该场函数在定义域上的**实际数值范围**（`|Ylm|` 上界随 l 变化）
- [ ] 阈值 `c` 相对上界的比例是多少？
- [ ] 打印 `keep.mean()` 填充率 —— 1~10% 正常，<3% 很可能阈值过高

### 症状 7：CPU/GPU 结果不一致

按产物类型分诊（对任何 CPU↔GPU 对照都成立）：

**IoU 掉了但 maxdiff 还小** → 形体变了（查场函数/几何）
**IoU=1.0 但 maxdiff 大** → 形体对，颜色错（查后处理）

> 迭代型场（Mandelbulb）永远拿不到 1.00000：CPU 走 float64、GPU 走 float32，
> 误差被 `8ⁿ` 放大，混沌边界上逃逸次数会差 1，边界像素错开约 1 px。
> **形体一致（肉眼无差）就算过**，不要为了刷到 1.0 去改精度。

### 症状 8：渲成一根光滑管子 / 棱柱 / 空壳

**先怀疑"场沿某个方向恒定不变"，而不是渲染器。**
最常见的成因是**把三维坐标塞进了一个复数**：

```python
z = (X + 1j * Y) + 1j * Z          # == X + i·(Y+Z)，y 和 z 被挤进同一个虚部
```

场于是只依赖 `x` 与 `y+z`，是一个**二维集合沿 `(0,1,−1)` 拉伸出的棱柱**，
渲染出来必然是那根管子。

**探针：取两个"应当等价"的切片比 `array_equal`。**

```python
a = field(X, np.zeros_like(X), Z)              # y = 0
b = field(X, 0.4*np.ones_like(X), Z - 0.4)     # y + z 相同
np.array_equal(a, b)     # -> True 就是中招了
```

**真实案例（mandelbulb，2026-10-06）**：就是这个 bug，`array_equal` 实测为 `True`。
⚠️ 旧文档当年把它误诊成"场没有负内部 / 表面渲染器有缺陷"，
白白绕了一大圈 —— 记住这条判据：

> **两条独立引擎给出相同的错误结果时，先假设"它们读的是同一份错场"。**
> 两个渲染器同时错在同一个地方，概率极低。

**检查清单**
- [ ] 场里有没有 `1j` / `complex` 把多维坐标压扁？
- [ ] 两个应当等价的切片，`np.array_equal` 是否为 True？
- [ ] 场沿某个方向的变化量是否为 0（`np.abs(np.diff(f, axis=k)).max()`）？
- [ ] 只有以上都排除后，再去看「五·补二」的"无负内部"

## 三、验证标准为什么这样定

| 指标 | 含义 | 为什么用它 |
|---|---|---|
| **silhouette IoU** | 形体是否完全一致 | 单看 hash 会被浮点噪声干扰；IoU=1.0 说明形体完全一致 |
| **max abs diff** | 色彩偏差 | 分辨"形体对但颜色偏"和"形体就错了" |
| `px>1/255` 占比 | 偏差分布 | 看是少数像素偏还是全局偏 |
| `np.array_equal` | 完全确定 | GPU 跑两次必须逐位相同（排除随机性） |

**最强证据**：klein_bottle 的 GPU 图与 **CPU 引擎独立渲染**的结果
肉眼完全一致（含既有摩尔纹）→ 说明迁移未引入任何回归。

## 四、残留的 8-bit 量化条带（不是缺陷，别去"修"）

平滑梯度区域会出现同心环，**但这不是体素阶梯，是 8-bit 量化条带**。

实测判据（orbital_d 平滑区）：
- 相邻像素差 `< 0.5` 的比例 = **58~69%**
- 120×120 色块内**唯一 R 值只有 51/256** 个

体素阶梯的特征是差值大且呈网格状；量化条带的特征是**大量平台 + 少量跳变**。

如需消除可加**三角分布抖动（dither）**后再量化，
但会改变交付风格，且**本项目未采用** —— 保持与既有交付一致优先。
